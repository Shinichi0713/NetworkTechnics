拠点同士の通信はOSPFで、拠点間の通信はBGP-4でというような住み分けがされていますが、単一のルーティングプロトコルで実施しようという考えが出てきています。
今日はそんな考えにより生じたプロトコル BGP Anywhereについて説明します。

## BGP Anywhereとは？

BGP Anywhere（「BGPをどこでも」「BGPエニウェア」）とは、インターネットの基幹ルーティングプロトコルである**BGP（Border Gateway Protocol）を、従来のISP間の接続だけでなく、企業ネットワークの内側や、クラウド、データセンター内など、ありとあらゆる場所で全面的に採用しようというネットワーク設計思想または構築手法**のことです。

通常、BGPは異なる組織（Autonomous System: AS）同士を接続するために使われますが、これを組織内部の細かい接続まで拡張して適用するのが最大の特徴です。

### BGP Anywhere の背景：なぜ「どこでもBGP」なのか？

従来の企業ネットワークやデータセンターでは、以下のようなルーティングプロトコルが使い分けられてきました。

* **組織内（内部ルーティング）:** OSPF、EIGRP（シスコ独自）など、設定が比較的簡単で、経路の切り替わり（収束）が速いプロトコル。
* **組織外（外部ルーティング）:** BGP。大規模で複雑な制御ができるが、設定が複雑で収束が遅いプロトコル。

しかし、以下のような変化により、内部ルーティングにもBGPのような「細かく、柔軟で、大規模に対応できるプロトコル」が必要になってきました。

1. **データセンターの大規模化:** クラウドサービスの普及により、データセンター内のサーバー数が爆発的に増加し、従来のプロトコル（OSPFなど）の処理能力の限界が見えてきた。
2. **マルチクラウド・ハイブリッドクラウド:** 自社データセンターとAWS、Azure、Google Cloudなどを複雑に接続する必要があり、組織外で標準のBGPを組織内までシームレスに延長した方が管理しやすい。
3. **SD-WANの普及:** 拠点をインターネット経由で柔軟につなぐSD-WANでは、アンダーレイ（物理回線）とオーバーレイ（仮想ネットワーク）の両方でBGPを使うことで、高度なトラフィック制御が可能になる。

### BGP Anywhere の具体的な方式・特徴

BGP Anywhereでは、これまで組織外に使っていたBGPを、組織内の以下のような場所で全面的に利用します。

__1. データセンター内（Closトポロジー）への適用__

最新の大規模データセンターでは、Closトポロジー（Spine-Leaf構成）という格子状の物理配線が一般的です。この構成では、多数の LeafスイッチとSpineスイッチを接続しますが、このすべてのスイッチ間でBGP（特にeBGP：external BGPを応用した構成）を走らせます。

* **メリット:** 各スイッチが独自の経路判断を行うため、特定のプロトコルに依存しない**オープンな標準技術**で、数千〜数万台規模のスイッチを安定してルーティングできます。

__2. マルチクラウド・オーバーレイネットワークへの適用__

自社ネットワークと、複数のクラウドプロバイダ（AWS、Azure、GCPなど）の拠点をBGPで直接接続します。さらに、その上の仮想ネットワーク（VXLAN、SD-WANなど）の経路情報の交換にもBGPを使います。

* **メリット:** 自社ネットワークからクラウド内部のネットワークまで、**単一のプロトコル（BGP）で一元管理**でき、一貫したルーティングポリシー（経路の優先度設定など）を適用できます。

__3. サーバーそのものへの適用（Routing on the Host）__

サーバー（物理、仮想、またはコンテナ）自体にBGPスピーカー（routing daemon）をインストールし、サーバーが所属するネットワークスイッチとBGPで経路情報を交換します。

* **メリット:** サーバー上のアプリケーション（例：コンテナのIPアドレス）を、ネットワーク全体へ瞬時に、かつ柔軟に広報できます。

### BGP Anywhere のメリット・デメリット

| メリット | デメリット |
| --- | --- |
| **単一プロトコルによる一元管理:** 内部OSPF＋外部BGPのような使い分けがなくなり、運用・管理がシンプルになる。 | **設定の複雑さ:** BGPはOSPFなどに比べて設定項目が多く、ポリシー制御を理解していないと誤設定を招きやすい。 |
| **高度なトラフィック制御:** 経路の優先順位（LOCAL_PREF, MED）や経路の属性（AS_PATH）を使って、非常に細かい通信経路の制御が可能。 | **収束速度:** 経路が切り替わる速度（収束時間）は、一般的にOSPFなどの内部ルーティングプロトコルの方が速い。（ただし、最新のBGP実装やBFD技術で大幅に改善されている） |
| **大規模・標準化:** 数万台規模のネットワークに対応でき、ベンダーに依存しない標準技術である。 | **CPU負荷:** 経路情報が多い場合、ルーターやスイッチのCPU負荷が高くなる可能性がある。 |

## 仕組み

BGP Anywhereの仕組みを理解するためには、まずBGPそのものの基本的な動作と、それを「組織内のあらゆる場所」へ適用するための設計思想を理解する必要があります。

### BGPの基本的な動作

BGP（Border Gateway Protocol）は、異なる組織（Autonomous System: AS）同士を接続するために使われるルーティングプロトコルです。その仕組みは、以下の要素で構成されています。

1. **AS番号の割り当て:** 各組織には、ユニークなAS番号が割り当てられます。
2. **ピア（ネイバー）の確立:** BGPルーター同士は、TCP（ポート179）を利用して接続を確立し、ピアとなります。
3. **経路情報の交換:** ピアとなったルーター同士は、自身の持つ経路情報を「BGPメッセージ」として交換します。
4. **ASパスによるループ防止:** 経路情報には、その経路が通過したASのリスト（ASパス）が含まれます。ルーターは、ASパスに自身のAS番号が含まれている経路情報を受け取らないことで、ルーティングのループを防ぎます。
5. **最適な経路の選択:** ルーターは、受け取った経路情報から、ASパスの長さ、LOCAL_PREF（組織内優先度）、MED（組織間優先度）などの属性に基づいて、最適な経路を選択します。

### BGP Anywhere の設計思想

BGP Anywhereは、従来の組織外（AS間）だけでなく、組織内（AS内）やデータセンター内、クラウド、サーバーなど、あらゆる場所でBGPを採用する設計思想です。その仕組みは、以下の要素で構成されています。

#### 1. データセンター内への適用

最新の大規模データセンターでは、Closトポロジーという格子状の物理配線が一般的です。この構成では、多数の LeafスイッチとSpineスイッチを接続しますが、このすべてのスイッチ間でBGPを走らせます。これにより、特定のプロトコルに依存しない、数千〜数万台規模のスイッチを安定してルーティングできます。

#### 2. マルチクラウド・ハイブリッドクラウドへの適用

自社データセンターと、複数のクラウドプロバイダ（AWS、Azure、GCPなど）の拠点をBGPで直接接続します。さらに、その上の仮想ネットワーク（VXLAN、SD-WANなど）の経路情報の交換にもBGPを使います。これにより、自社ネットワークからクラウド内部のネットワークまで、一貫したルーティングポリシーを適用できます。

#### 3. サーバーへの適用（Routing on the Host）

サーバー自体にBGPスピーカーをインストールし、サーバーが所属するネットワークスイッチとBGPで経路情報を交換します。これにより、サーバー上のアプリケーションを、ネットワーク全体へ瞬時に、かつ柔軟に広報できます。

#### 4. EVPN-VXLAN との強力な結合

データセンター内のL2/L3仮想化には、EVPN-VXLANという技術セットが標準です。この「EVPN」の制御パネルとして、BGPのエクステンション（MP-BGP）が使われます。これにより、物理ネットワークはシンプルなIP転送に特化し、複雑なテナント管理やMACアドレス情報の交換はBGPが効率的に行います。

### BGP Anywhere の仕組みのまとめ

BGP Anywhereは、従来のAS間ルーティングだけでなく、組織内、データセンター内、クラウド内まで全面的にBGPを使うことで、マルチクラウド時代の複雑、かつ大規模なネットワークを、一貫して柔軟に管理・制御しようとする仕組みです。

## 動向

BGP Anywhere（組織内のあらゆる場所でBGPを採用する設計思想）の利用動向は、現在、成熟した標準技術としての定着とクラウドネイティブ環境へのさらなる拡張という2つの大きな流れの中にあります。

かつては一部の大規模ハイパースケーラー（Google, Facebook/Metaなど）独自の最先端手法でしたが、現在は一般企業の大規模データセンターやマルチクラウド環境でも一般的な選択肢となっています。

現在の具体的な動向を、いくつかの領域に分けて解説します。

### 1. データセンター内：標準技術としての「完全定着」

データセンター内の物理ネットワーク（アンダーレイ）構築において、BGP Anywhere（特にeBGPを用いたClosトポロジー）は、事実上の業界標準（De Facto Standard）となりました。

* **動向:**
* OSPFなどの従来のIGPプロトコルは、大規模環境での収束速度や管理の複雑さから、主要な部分からは押し出されつつあります。
* 特定のベンダーに依存しない「オープンネットワーキング（White BoxスイッチとSonicなどのOSの組み合わせ）」の普及が、標準プロトコルであるBGPの採用を後押ししています。


* **現状の見立て:** 新規で数〜数百ラック規模のデータセンターを構築する場合、BGPを採用しない設計は少数派になりつつあります。

### 2. 仮想ネットワーク（Overlay）：EVPN-VXLAN との強力な結合

物理ネットワークの上で動く仮想ネットワーク（オーバーレイ）の制御において、BGPは不可欠な存在となっています。

* **動向:**
* **EVPN-VXLAN** という技術セットが、データセンター内のL2/L3仮想化の標準となりました。この「EVPN（Ethernet VPN）」の制御パネル（Control Plane）として、BGPのエクステンション（MP-BGP）が使われます。
* これにより、物理ネットワークはシンプルなIP転送に特化し、複雑なテナント管理やMACアドレス情報の交換はBGPが効率的に行います。


* **現状の見立て:** 「BGP Anywhere」を実装するということは、実質的に「EVPN-VXLANの制御にBGPを使う」ことと同義になりつつあります。

### 3. クラウドとの接続：マルチクラウドの「共通言語」化

企業ネットワークと複数のパブリッククラウド（AWS, Azure, GCPなど）、またはオンプレミスとクラウドを接続する境界において、BGPの役割はさらに重要になっています。

* **動向:**
* **スタティックルーティングの限界:** クラウド側のVPCやサブネットが動的に増減する環境では、静的な経路設定（スタティックルート）の運用は不可能です。
* **共通言語:** OSPFなどはクラウド事業者の境界ではサポートされないことが多く、すべてのクラウド事業者、キャリア、SD-WANベンダーが解釈できる**唯一の共通ルーティングプロトコル**としてBGPが選ばれています。
* **SD-WAN/SDCIとの連携:** MegaportやEquinix FabricなどのSDCI（Software-Defined Cloud Interconnect）サービスを利用して、クラウド間BGPルーティングを動的に一元管理する手法が増えています。



### 4. サーバー/ホスト領域：「Routing on the Host」の普及（コンテナ対応）

「BGP Anywhere」の最前線は、ネットワークスイッチからサーバー（ホスト）そのものへ、さらにその上で動くコンテナ（Kubernetesなど）へと広がっています。

* **動向:**
* **Routing on the Host:** サーバー自体にBGPスピーキング能力（FRR, Birdなどのルーティングソフト）を持たせ、ToR（Top-of-Rack）スイッチとBGPセッションを張ります。
* **Kubernetes (CNI):** **Calico** や **Cilium** といったKubernetesのネットワークプラグイン（CNI）は、コンテナのIPアドレスを外部ネットワークに広報するためにBGPを利用します。これにより、コンテナへの通信が物理ネットワーク側で最適にルーティングされます。


* **現状の見立て:** ハイパースケーラーやクラウドプロバイダでは一般的ですが、一般企業でもKubernetesの大規模運用に伴い、ホストBGPの採用事例が増え始めています。

### 5. 新たな動向と課題：運用の複雑さと、それを解決するオートメーション

BGPを「どこでも」使うことはメリットばかりではありません。数千、数万のBGPセッションを管理するのは人間の手には負えなくなります。

* **動向と課題:**
* **AS番号管理の複雑化:** すべてのスイッチやホストにAS番号を割り当てる必要があり、採番計画や設計が複雑になります。
* **誤設定のリスク:** BGPの設定ミスは、OSPFよりも広範囲に深刻な影響（経路ハイジャックやループ）を及ぼす可能性があります。
* **自動化の必須化:** この課題を解決するため、Ansible, Terraform, またはベンダー独自のネットワークオーケストレーター（Cisco NDO, Juniper Apstraなど）を用いた、BGP設定の完全自動化（Intent-Based Networking）が、「BGP Anywhere」とセットで導入される動向にあります。

## 総括

BGP Anywhereを一言で表すと、**「インターネットの共通言語であるBGPを、企業内・データセンター内・クラウド内・サーバー上まで、ネットワークの隅々まで広げて使おうという設計思想」** です。

以下、簡潔に総括します。

### 1. なぜBGP Anywhereが生まれたか

従来は「社内はOSPF、社外（ISP間）はBGP」という住み分けでしたが、以下の変化により境界が曖昧になりました。

- **データセンターの大規模化**: OSPFでは数千〜数万台の機器を管理しきれなくなった
- **マルチクラウド化**: AWS/Azure/GCPと自社ネットワークを、共通プロトコルでつなぎたい
- **SD-WAN/コンテナ化**: 拠点間、サーバー上のコンテナまで、柔軟に経路を広報したい

→ 結果、**「内部も外部も、全部BGPで統一しよう」** という流れが生まれた。

### 2. どこで使われるか

| 適用場所 | 具体例 |
|---------|--------|
| **データセンター内** | Spine-Leaf構成（Closトポロジー）の全スイッチ間でeBGPを運用 |
| **クラウド接続** | 自社DCとAWS/Azure/GCPをBGPで直接接続。VXLAN/SD-WANの制御にもBGPを使用 |
| **サーバー上** | Routing on the Host。サーバーにBGPデーモンを入れ、ToRスイッチと経路交換 |
| **コンテナ** | KubernetesのCalico/Ciliumが、PodのIPを外部にBGP広報 |

### 3. メリットとデメリット

| メリット | デメリット |
|---------|-----------|
| 単一プロトコルで一元管理でき、運用がシンプル | 設定が複雑で、誤設定の影響が大きい |
| 経路の優先度等、細かいポリシー制御が可能 | 収束速度はOSPF等に比べ遅い（最新実装で改善中） |
| ベンダー非依存の標準技術で、数万規模までスケール | 大量のBGPセッション管理は自動化が必須 |

### 4. 仕組みの核心

BGPの本質は **「TCP/179でピアを張り、経路情報を属性付きで交換する」** ことです。

BGP Anywhereではこれを**組織内（AS内）まで拡張**し、さらに：

- **EVPN-VXLAN**: BGPでMACアドレスやテナント情報を交換し、データセンターの仮想ネットワークを制御
- **Closトポロジー**: 各スイッチに独立したAS番号を振り、eBGPで接続することで、シンプルかつ大規模なルーティングを実現

### 5. 現在の動向

- **データセンター**: BGP Anywhereは事実上の標準（De Facto Standard）に
- **クラウド接続**: 全クラウド事業者がBGPを理解できるため、マルチクラウドの「共通言語」として定着
- **Kubernetes**: Calico等により、コンテナネットワークの経路広報にもBGPが標準化
- **自動化**: 数千セッションの管理は人手では不可能なため、Ansible/Terraform/Intent-Based Networkingによる自動化が必須の潮流に
