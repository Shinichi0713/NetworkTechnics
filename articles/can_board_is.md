マイコンなどのコントロールデバイスでCANのバスを用いた通信を行う場合、通常のメッセージを送信するのみでは通信を行うことが出来ません。
電気信号をCANのルールに整形を行うCANボードが必須となります。

本日はそんなCANボードの話を行っていきます。

## 概要
CANボードとは、**マイコンやPCがCANバス（車の通信網）と「話せる」ようにするための変換基板**です。
CANコントローラがプロトコルを処理し、CANトランシーバーが電気信号を変換することで、ArduinoやPCから車のCANバスにフレームを送受信できます。

### CANボードの構成

CANボードは基本的に以下の2つの部品で構成されています。

| 部品 | 役割 |
|------|------|
| **CANコントローラ** | CANプロトコルの処理（フレーム生成・受信・エラー検出など）を行うIC。例：MCP2515、SJA1000 |
| **CANトランシーバー** | デジタル信号とCANバスの差動信号（CAN_H / CAN_L）を相互変換するIC。例：TJA1050、SN65HVD230 |

```
[マイコン/PC] ←──SPI/USB/UART──→ [CANコントローラ] ←──→ [CANトランシーバー] ←──CAN_H/L──→ [車両のCANバス]
```

### 主な種類

__1. マイコン用CANボード（シールド/モジュール）__

ArduinoやRaspberry Piに載せて使う小型基板です。

| 製品例 | 接続方式 | 用途 |
|--------|----------|------|
| MCP2515 CANボード | SPI通信 | Arduino、Raspberry Pi、ESP32など |
| PiCAN2 | Raspberry Pi専用HAT | Raspberry Piに直接装着 |
| CANBed | Arduino互換+CAN一体 | 車載診断ツールのプロトタイプ |

__2. PC接続用CANインターフェース__

PCのUSBポートからCANバスに接続するデバイスです。

| 製品例 | 接続方式 | 用途 |
|--------|----------|------|
| CANtact | USB | セキュリティ診断、オープンソース |
| PCAN-USB | USB | プロ仕様、Windows/Linux対応 |
| USB2CAN | USB | 低価格、SocketCAN対応 |

__3. 車載OBD-II接続型__

車のOBD-IIコネクター（診断端子）に直接差し込むタイプです。

| 製品例 | 特徴 |
|--------|------|
| OBD-II CANボード | 車のOBD-IIポートに挿してCANバスにアクセス |
| Macchina M2 | Arduino互換で車載ハッキング向け |

### CANボードの用途

- **車載診断**：OBD-II経由でエンジン回転数、車速、故障コードを読み取る
- **車載システム開発**：ECUのプロトタイプ開発やテスト
- **セキュリティ診断**：CANフレームの注入・リプレイ攻撃の検証
- **産業用制御**：工場のロボットやセンサーネットワークの構築

## CANボードが行っていること

CANボードは、**マイコンが「CANプロトコルの複雑な処理」と「車両特有の電気信号変換」を肩代わりする専用回路**です。

以下、Arduino + MCP2515（CANコントローラ）+ TJA1050（トランシーバー）という典型的な構成で、**送信・受信の具体的な処理**を追って説明します。

### CANボード内の2つの主要チップ

CANボードには、役割の異なる2つのICが載っています。

```
┌──────────────────────────────────────────┐
│              CANボード                    │
│  ┌──────────────┐    ┌──────────────┐   │
│  │ MCP2515      │SPI │ TJA1050      │   │
│  │ CAN          │←→ │ CAN          │CAN_H│
│  │ コントローラ  │    │ トランシーバー │←→車両バス
│  └──────┬───────┘    └──────┬───────┘   │
└─────────┼──────────────────┼────────────┘
          │SPI               │差動信号
    ┌─────┴─────┐      ┌────┴────┐
    │  Arduino  │      │CAN_H/L │
    └───────────┘      └─────────┘
```

| チップ | 役割 | 具体的な処理 |
|--------|------|-------------|
| **MCP2515**（CANコントローラ） | プロトコル処理担当 | フレーム生成、CRC計算、ACK確認、ビットタイミング管理、受信フィルタ |
| **TJA1050**（CANトランシーバー） | 電気信号変換担当 | デジタル0/1をCAN_H/Lの差動電圧に変換（送信時）、その逆変換（受信時） |

### 具体例1：マイコンから車両へ「速度フレーム」を送信する

ArduinoがICSimと同じように、ID `0x244` に速度データを送る場合を想定します。

__ステップ1：ArduinoがSPIで「送りたいデータ」を伝える__

ArduinoはCANプロトコルの細かい処理をしません。単に **「このIDに、このデータを送ってください」** と、SPI通信でMCP2515に命令します。

```cpp
#include <mcp_can.h>
MCP_CAN CAN(10);  // CSピンは10番

void setup() {
    CAN.begin(MCP_ANY, CAN_500KBPS, MCP_16MHZ);
    
    // 送信するデータ（ID 0x244, 5バイト）
    byte data[5] = {0x00, 0x00, 0x00, 0x01, 0x6E};
    
    // 「ID 0x244 に data を送せ」とMCP2515に命令
    CAN.sendMsgBuf(0x244, 0, 5, data);
}
```

**ここでArduinoがやっていることは「メモリ書き込み命令」を送るだけ**です。実際のCANフレーム作成はこれからCANボード側で行います。

__ステップ2：MCP2515がCANフレームを「組み立てる」__

MCP2515は受け取った命令から、以下を自動で生成します。

- **SOF**（Start of Frame）：通信開始ビット
- **Arbitration Field**：ID `0x244` をビット列に変換
- **Control Field**：データ長（5バイト）を設定
- **Data Field**：`00 00 00 01 6E`
- **CRC Field**：データが壊れていないか確認するための検査符号を自動計算
- **ACK Slot**：相手が受信したか確認するための隙間を作る

```
Arduinoから受け取った中身：
「ID=244, データ=5バイト」

MCP2515が生成する実際のCANフレーム（ビット列）：
[SOF][ID:244][長さ:5][Data:00 00 00 01 6E][CRC:xxxx][ACK][EOF]
```

__ステップ3：MCP2515がビットタイミングを管理して送信する__

CANは**同期したビットレート**（例：500Kbps）で通信する必要があります。MCP2515は内部のバウレートジェネレータを使い、正確なタイミングで1ビットずつTJA1050に送ります。

さらに、バスが混雑していても**仲裁（Arbitration）** を自動処理します。他のECUも同時に送り始めた場合、優先度の高い（IDが小さい）フレームが勝つ仕組みを、MCP2515がハードウェアレベルで監視・判断します。

__ステップ4：TJA1050が電気信号に変換する__

MCP2515から出てきたのは**5Vのデジタル信号（0と1）** です。TJA1050はこれを、車両のCANバスで使われる**差動信号**に変換します。

| デジタル値 | CAN_H | CAN_L | 状態 |
|-----------|-------|-------|------|
| 0（支配ビット） | 3.5V | 1.5V | 差動2.0V |
| 1（従属ビット） | 2.5V | 2.5V | 差動0V |

この差動電圧がツイストペアケーブルを通じて、車両内の他のECUに届きます。

### 具体例2：車両から「ドアロックフレーム」を受信する

次に、車両側のECUがドアロック状態をID `0x188` で送っている場合、Arduinoがそれを受信する流れです。

__ステップ1：TJA1050が差動信号をデジタル信号に戻す__

CAN_H/Lの微弱な差動電圧（ノイズに強い）を、TJA1050が再び**0/1のデジタルパルス**に変換し、MCP2515に渡します。

__ステップ2：MCP2515がビットストリームをデコードする__

TJA1050から連続して入ってくるビット列を、MCP2515が以下のように解釈します。

1. SOFを検出して「フレームの始まり」を認識
2. IDフィールドを読み取って「これは0x188のフレームだ」と判断
3. データ長を確認して、続くバイト数を把握
4. データを取り出す
5. CRCを計算して、壊れていないか検証
6. ACKビットを返して「受信完了」を送信側に通知

__ステップ3：受信フィルタで不要なフレームを除外__

CANバスには毎秒数千のフレームが流れます。MCP2515は**受信フィルタ（RX Filter）** を持ち、Arduinoが必要としないIDのフレームは**ソフトウェアに渡さずに破棄**します。

例えば「ID 0x188だけ受信する」ように設定しておけば、スピードメーター（0x244）などのフレームはMCP2515内部で無視され、Arduinoの負荷が減ります。

__ステップ4：ArduinoがSPIで読み出す__

MCP2515は「新着メッセージあり」をINTピンでArduinoに通知します。ArduinoはSPIでMCP2515の受信バッファを読み出します。

```cpp
void loop() {
    if (CAN_MSGAVAIL == CAN.checkReceive()) {  // 受信データあり？
        unsigned long id;
        byte len;
        byte buf[8];
        
        CAN.readMsgBuf(&id, &len, buf);  // SPIでMCP2515から読み出し
        
        if (id == 0x188) {
            // ドアロック状態の処理
        }
    }
}
```

### まとめ：CANボードが行っている具体的な処理

| 処理 | 担当 | マイコン（Arduino）がやること |
|------|------|------------------------------|
| フレームのビット組み立て | **MCP2515** | SPIで「IDとデータ」を渡すだけ |
| CRC計算・エラーチェック | **MCP2515** | 何もしない（自動） |
| ビットタイミング・同期 | **MCP2515** | 何もしない（水晶振動子で自動） |
| バス仲裁（優先順位競合） | **MCP2515** | 何もしない（ハードウェア処理） |
| 差動信号への変換 | **TJA1050** | 何もしない |
| 受信フィルタリング | **MCP2515** | フィルタ設定だけ行う |
| ACKの送受信 | **MCP2515** | 何もしない（自動） |

> **つまり、CANボードは「CANプロトコルの重労働（ビット単位のタイミング管理・CRC・仲裁・電気変換）をすべて引き受け、マイコンには『IDとデータの読み書き』だけをさせる」ための専門家チップセットです。**

マイコンにCANボードがないと、ArduinoのCPUがすべてのビットタイミングをソフトウェアで処理しなければならず、ほかの処理が全くできなくなります。CANボードはその負担を完全に肩代わりします。

## 総括

マイコンでCANを使った制御とは、**「CANプロトコルの重労働は専用チップ（CANボード）に任せ、マイコンはIDとデータの読み書きだけを行う」** 開発スタイルです。

マイコンはSPIやUSBでCANボードに「ID 0x244にこのデータを送れ」と命令するだけで、フレーム組み立て・CRC計算・ビットタイミング管理・仲裁・電気信号変換などの複雑な処理はすべてCANボードが自動で行います。

受信時も同様で、CANボードが不要なフレームをフィルタリングし、必要なデータだけをマイコンに届けます。

**一言でいえば、マイコンは「CAN通信の内容（アプリケーション）」だけを考え、「CAN通信の仕組み（プロトコル・物理層）」は専用ハードウェアに任せることで、効率的な車載・組込み制御を実現する手法です。**
