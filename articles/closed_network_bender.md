通信業者から提供される一般公開されていないネットワークのことを閉域ネットワーク(以下閉域NW)と呼びます。
この閉域NWの特性について説明していきます。

## 閉域NWとは？

ベンダー（通信事業者やシステムインテグレーターなど）から「閉域NW（閉域ネットワーク）」が提供されているという文脈では、**「インターネットとは隔離された、特定の顧客企業や組織専用の通信網を、サービスとして利用できる」** という意味になります。

### 具体的にどのようなものか

企業が本社、支社、工場、データセンター、クラウド環境などをつなぐ際に、「インターネットVPN」ではなく、**ベンダーが保有する専用の通信網**を使って拠点同士を接続するサービスです。

代表的なサービス例は以下の通りです。

- **IP-VPN**：IPによる閉域網。複数拠点を同一のプライベートネットワークとして接続できる
- **広域イーサネット（EWANなど）**：レイヤ2レベルで拠点を接続する閉域網サービス
- **専用線（回線）**：2点間を物理的に専有するような回線で接続する形
- **閉域接続型のクラウドゲートウェイ**：AWSやAzureなどのパブリッククラウドに、インターネットを経由せずに接続するためのベンダー提供回線

### ベンダー提供の閉域NWの主な特徴

| 特徴                               | 説明                                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------------------- |
| **インターネット非経由**     | 通信がインターネット上を流れないため、外部からの不正アクセスや傍受のリスクが低い       |
| **品質の安定性**             | 帯域や遅延が比較的安定しており、業務系システムや音声・映像通信にも向く                 |
| **複数拠点の一元接続**       | 本社・支社・DCなどを、まるで同一LANにいるように接続できる                              |
| **運用の委託**               | 網の管理・運用・監視をベンダーが行うため、顧客のIT部門の負荷が減る                     |
| **セキュリティ要件への対応** | 個人情報や機密データを扱う業務で、「インターネット経由を避ける」要件を満たすことが多い |

## どの様に構築されている?

閉域NWは、一言で言えば **「物理的・論理的にインターネットと分離された通信空間」** ですが、その実現方法にはいくつかの技術的なアプローチがあります。

大きく分けて、**「専用回線で物理的に分離する方法」** と、**「ベンダーの通信網の中で論理的に分離する方法」** の2つがあります。

### 1. 物理的な専用回線で構築する方法

最もシンプルで徹底した閉域網です。

- **専用線（リース回線）**
  - 拠点Aと拠点Bの間に、通信事業者が光ファイバーや銅線などの**専用の物理回線**を引きます。
  - その回線はその企業だけが使用するため、完全に他社と分離されています。
  - コストは高いですが、帯域や品質は最も安定します。

### 2. 通信事業者の網の中で「論理的に分離」する方法（一般的）

現実には、全拠点同士を物理的な専用線だけで繋ぐとコストがかさむため、**通信事業者（キャリア）の大規模な通信網の中で、論理的に区切った仮想的な専用網**を作る方法が主流です。

代表的な技術は以下の通りです。

#### MPLS / IP-VPN

- キャリアのバックボーンネットワーク上で、**MPLS（Multi-Protocol Label Switching）** という技術を使い、各企業の通信に「ラベル（タグ）」を付与して区別します。
- 企業Aのパケットと企業Bのパケットは、同じ物理的な回線やルーターを流れることがありますが、ラベルによって**論理的に完全に分離**されています。
- 各企業の拠点は、まるで同じプライベートネットワークにいるように通信できます。

#### 広域イーサネット（レイヤ2 VPN）

- MPLSと似た考え方ですが、OSI参照モデルの**レイヤ2（データリンク層）** で分離します。
- 拠点Aから拠点Bまで、まるで1本の長いLANケーブルで繋がっているように振る舞います。
- 企業側のルーターが特別な設定をあまり必要としない場合もあり、比較的導入しやすいです。

#### VRF（Virtual Routing and Forwarding）

- キャリア側のルーター内部で、**仮想的な複数のルーティングテーブル**を作り、企業ごとに別々のテーブルを使わせる技術です。
- これにより、異なる企業の通信経路が混ざらないように制御します。

### 3. 顧客の拠点とキャリア網はどう繋がるか？

閉域NWを使う際、顧客の拠点では通常、以下のような機器や回線でキャリアの閉域網に接続します。

- **最終回路（アクセス回線）**
  - 顧客のビルや事務所から、通信事業者の最寄りの局舎まで、光回線やメタル回線などで接続します。
  - この区間も原則として他社と混在しない専用的な接続になります（あるいは論理的に厳密に分離されます）。
- **CE（Customer Edge）ルーター / 通信装置**
  - 顧客側に設置されるルーターで、ここからキャリア側のPE（Provider Edge）ルーターへ接続されます。
  - この機器が、閉域NWの入り口・出口となります。

### 4. クラウドとの接続（閉域NWの延長）

近年では、AWSやAzureなどのパブリッククラウドにも、インターネットを経由せずに閉域NWから直接接続する仕組みが整っています。

- **Direct Connect（AWS）や ExpressRoute（Azure）** などのサービスに対し、通信事業者の閉域NWを介して接続します。
- これにより、「本社・支社・クラウド」がすべて同一の閉域ネットワーク空間に入り、インターネットに一度も出ずに通信が完結します。

### 5. 最近のトレンド：SD-WANとの組み合わせ

閉域NWは品質が安定する一方、コストが高く柔軟性に欠けることがあります。そのため、最近では以下のようなハイブリッド構成も増えています。

- **重要な業務システムの通信**：閉域NW（IP-VPNなど）を使用
- **一般インターネットアクセスやクラウドSaaS**：通常のインターネット回線を使用
- **SD-WAN機器**が両方の回線を管理し、通信の種類に応じて自動的に経路を振り分けます。

ただし、ここでいう「閉域NW」の部分は、前述のMPLSや広域イーサネットで構築された論理的な専用網であることに変わりはありません。

## どんな用途？

閉域NW（閉域ネットワーク）は、**「インターネットを経由したくない」「通信の品質やセキュリティを高いレベルで担保したい」** という状況で用いられます。

具体的には、以下のようなケースが代表的です。

### 1. 機密データや個人情報を扱う業務

個人情報、医療記録、金融情報など、漏洩や改ざんのリスクが許容できないデータをやり取りする場合です。

- **例**：銀行の本店と支店の接続、病院と検査センターの連携、自治体の基幹系システム
- **理由**：インターネット上を流すと、暗号化していても攻撃対象になり得ますが、閉域NWはそもそも外部に通信が露出しないため、リスクを大幅に減らせます。

### 2. 基幹業務システムの拠点間接続

企業の生産活動や経営に直結する重要なシステムを、本社・支社・工場・データセンター間で連携させる場合です。

- **例**：ERP（基幹業務システム）、在庫管理システム、生産管理システム
- **理由**：システムが止まると業務が麻痺するため、インターネットの輻較（ふくそう）や障害の影響を受けにくい閉域NWが選ばれます。

### 3. 通信品質・安定性が求められるケース

遅延（ラグ）や途切れが許容できない通信を行う場合です。

- **例**：工場の機械制御、IP電話やテレビ会議システム、POS（売上管理）システム、放送局の映像伝送
- **理由**：閉域NWは帯域を保証しやすく、品質が安定しているため、リアルタイム性が求められる通信に適しています。

### 4. パブリッククラウドへの安全な接続

AWSやAzureなどのクラウド上に置いた業務システムに、社内からインターネットを経由せずにアクセスしたい場合です。

- **例**：本社・支社から、クラウド上の基幹システムやファイルサーバーにアクセスする
- **理由**：インターネットVPNでも暗号化はできますが、閉域NW接続（Direct ConnectやExpressRouteなど）にすることで、より高いセキュリティと安定した通信速度を得られます。

### 5. 法令・規制・契約上の要件を満たす必要がある場合

業界のガイドラインや取引先との契約で、「インターネット経由を避ける」あるいは「閉域網を使用する」ことが求められることがあります。

- **例**：金融分野（金融庁のガイドライン）、行政機関（政府共通NW）、重要インフラ（電力・ガス・鉄道）
- **理由**：コンプライアンス上、インターネット接続だけでは要件を満たせないため、閉域NWが事実上の必須となります。

### 6. インターネット接続を持たない・持たせたくない拠点の接続

セキュリティ上の理由で、一部の拠点にインターネット回線を引きたくない場合でも、閉域NWだけを通して他拠点やデータセンターに接続できます。

- **例**：高セキュリティゾーンの工場、研究所、サーバールーム
- **理由**：その拠点からインターネットに出られないようにしつつ、必要な業務システムだけにはアクセスできるようにする、という設計が可能です。

## 総括

閉域NWとは、**通信事業者などのベンダーが提供する、インターネットと隔離された顧客専用の通信網**です。本社・支社・データセンター・クラウドなどを、まるで同一の社内LANのように安全に接続できます。

### 主な技術的実現方法

- **物理的専用回線**：光ファイバーなどの回線を企業専有で引く方法。最も徹底していますがコストが高いです。
- **論理的分離（主流）**：キャリアの共有網の中で、MPLS・VRF・広域イーサネットなどの技術を使い、企業ごとに仮想的な専用空間を切り分ける方法です。物理は共有しつつ、通信は完全に分離されます。

### 主な用途

- **機密データの保護**：金融・医療・行政など、個人情報や機密情報を扱う業務でインターネット経由を避けたい場合。
- **基幹システムの接続**：ERPや生産管理など、止まると業務に支障が出る重要なシステムを拠点間で安定して連携させたい場合。
- **品質保証**：IP電話・映像伝送・工場制御など、遅延や途切れが許容できない通信。
- **コンプライアンス対応**：業界ガイドラインや契約で「閉域網の使用」が求められる場合。
- **クラウドへの安全接続**：AWS/Azureなどにインターネットを経由せず接続する（Direct Connect/ExpressRouteなど）。

### まとめ

閉域NWは、**「インターネットに出さずに、品質とセキュリティを高く保ちながら拠点をつなぐための専用通信空間」** です。コストはインターネットVPNより高いものの、重要な業務や機密データのやり取り、法的要件を満たす場面では欠かせないインフラとなっています。
