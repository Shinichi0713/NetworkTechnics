スマホを使った、電話番号を使わないインターネットのような通信ネットワークを用いる通話をIP通話と呼びます。
IP通話はシグナリング（呼び）と通話から構成されます。

本日はそんなIP通話について説明します。

## IPシグナリング

**シグナリング（signaling）** とは、**「通話の音声そのものではなく、通話を『成立させるための制御情報』を交換すること」** です。

IP電話では、音声データの送受信とは別に、**「呼び出す」「出る」「切る」「どのコーデックを使うか」** といったやり取りを行う必要があります。これがシグナリングです。

### 1. シグナリングが担う主な役割

| 役割 | 具体例 |
|------|--------|
| **ユーザーの場所を探す** | 「1001番は今、どのIPアドレスにいるか」（REGISTERの情報を参照） |
| **通話の確立（呼び出し）** | 「電話をかけます」「出ます」 |
| **能力交換（ネゴシエーション）** | 「G.711とOpusに対応しています」「ではOpusで」 |
| **通話の終了** | 「切断します」「了解しました」 |
| **通話中の制御** | 保留、転送、3者通話など |

### 2. 音声（メディア）との違い

IP電話では、通信が**2つの流れ**に分かれています。

- **シグナリング**：通話の「制御指令」。SIPなどで送信。TCP/UDPポート（通常5060等）を使用。
- **メディア（RTP）**：実際の音声パケット。UDPの別ポートで直接端末間（またはサーバー経由）で流れる。

**例えると**
- シグナリング = **電話のボタン操作と着信音の制御**
- メディア（RTP） = **受話器から実際に流れる声**

### 3. 主なシグナリングプロトコル

| プロトコル | 特徴 |
|-----------|------|
| **SIP**（Session Initiation Protocol） | 現在の主流。HTTPに似たテキストベース。シンプルで拡張性が高い。 |
| **H.323** | 比較的古い、バイナリベースのプロトコル。現在はSIPに移行が進んでいる。 |
| **IAX**（Inter-Asterisk eXchange） | Asteriskなどで使われる、トランク接続向けのプロトコル。 |

### 4. SIPにおけるシグナリングの流れ（発信〜通話〜切断）

```
発信者                サーバー/Proxy              着信者
  |                       |                        |
  |---- INVITE ---------->|----------------------->|
  |                       |---- 180 Ringing ------->|  （呼び出し中）
  |<--- 180 Ringing ------|<-----------------------|
  |                       |---- 200 OK ------------>|  （出た）
  |<--- 200 OK -----------|<-----------------------|
  |---- ACK ------------->|----------------------->|
  |                       |                        |
  |<================ RTP（音声） =================>|
  |                       |                        |
  |---- BYE ------------->|----------------------->|  （切る）
  |<--- 200 OK -----------|<-----------------------|
```

この**INVITE、180、200、ACK、BYE**などのやり取りがすべてシグナリングです。

### そもそも何な訳？

**呼び出し**とは、**「相手に『通話したい』と知らせて、応答を待つ一連の動作」** です。

IP電話では、以下の2つの側面があります。

- **シグナリングとしての呼び出し**：発信者がINVITEを送り、着信者側で**180 Ringing**（呼び出し中）を返す。これにより、相手の端末が「リンリン」と鳴ります。
- **メディアとしての呼び出し**：実際の音声（RTP）はまだ流れていません。呼び出し中は**制御信号だけ**がやり取りされています。

一言で言えば、**「通話の音声を送る前に、相手に『出てください』と合図する手続き」** です。

## 通話

呼び出し（Ringing）の後、通話は以下の流れで実現されます。


### 1. 着信応答（200 OK）

着信者が電話に出ると、端末は**200 OK**という応答を発信者に返します。これが「出た」という合図です。


### 2. ACK（応答の確認）

発信者側は**ACK**を送り、双方で通話確立が合意されます。これでSIPシグナリングによる「通話の準備」は完了です。


### 3. RTPセッションの開始（実際の通話）

合意が成立すると、**音声パケット（RTP）** が端末間で直接（またはサーバー経由で）流れ始めます。

- **SIP**：通話の制御（始める・終わる）
- **RTP**：実際の声のデータ

### 4. 通話終了（BYE）

どちらかが切ると**BYE**が送られ、相手が**200 OK**で応答して通話が終了します。RTPの音声流も停止します。


## Register

**REGISTER**は、**SIP（Session Initiation Protocol）** というIP電話（VoIP）のシグナリングプロトコルにおいて、**「自分（端末）が今、どのIPアドレスで、どのように届くか」をサーバーに教えるための手続き**です。

### なぜREGISTERが必要か

IP電話では、人は **「電話番号」や「SIP URI（例：sip:alice@example.com）」** で識別されますが、実際の通信は**IPアドレス**で行われます。

- 端末のIPアドレスは、DHCPや移動によって**変わることがあります**。
- 発信側が「今のaliceのIPアドレスは？」を逐一知ることはできません。

そこで、**Registrar（登録サーバー）** という存在に対して、端末が「私はこの番号で、このIPにいます」と**能動的に登録・報告**するのがREGISTERです。

### REGISTERで何が起きているか

1. **端末が電源ON／ネットワーク接続時**に、SIPサーバー（Registrar）へREGISTERを送信。
2. サーバーはこの情報を**Location DB（位置データベース）** に保存。
3. 誰かがその番号に発信すると、サーバーはLocation DBを参照し、**現在のIPアドレスに呼び出し（INVITE）を中継**します。

### まとめると

| 項目 | 内容 |
|------|------|
| **目的** | 「自分の現在のIPアドレスと連絡先URIの対応」をサーバーに登録する |
| **なぜ必要か** | IPアドレスは可変なため、番号→IPの解決をサーバーに委ねる |
| **いつ行うか** | 端末起動時、定期的な更新（通常は有効期限付き）、IP変更時 |
| **有効期限** | 登録は期限付き（例：3600秒）で、期限切れ前に再REGISTER（リフレッシュ）する |


## 総括

通話の本質は、**「制御（シグナリング）」と「実データ（メディア）」を分離し、まず制御で合意を作ってから、実際の音声を直接流す**ことにあります。

具体的には、**「どこにいるかを登録する（REGISTER）→ 呼び出して応答を待つ（INVITE/Ringing）→ 出たという合意を交わす（200 OK/ACK）→ 音声を直接送受信する（RTP）→ 切る合意を交わす（BYE）」** という一連の状態遷移です。

つまり、通話とは **「まず『通路とルール』をシグナリングで確保し、その通路を通じてリアルタイムの音声を直接やり取りする」** 通信です。
