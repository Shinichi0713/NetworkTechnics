## L2フォワーディングとは
「L2フォワーディング」には、文脈によって**2つの意味**があります。ここでは両方を整理して説明します。

### 1. L2F（Layer 2 Forwarding Protocol）としてのL2フォワーディング

もっとも一般的には、**L2F（Layer 2 Forwarding Protocol）** というVPNトンネリングプロトコルを指します。[L2F](https://ja.wikipedia.org/wiki/Layer_2_Forwarding) は、Cisco SystemsとMicrosoftが1990年代に共同開発したプロトコルで、[RFC 2341](https://datatracker.ietf.org/doc/html/rfc2341) として標準化されました。

__本質__

**[PPPフレーム](https://yoshishinnze.hatenablog.com/entry/2025/12/15/000000)などのレイヤー2フレームを、IPネットワーク上を通して別の拠点まで「トンネリング」する技術**です。

__背景と用途__

- ダイヤルアップ接続の時代に、リモートユーザーがISPに電話回線で接続し、そのPPPセッションを企業の本社ネットワークまでトンネリングで中継するために使われました。
- 後に、MicrosoftのPPTPと統合され、**[L2TP](https://ja.wikipedia.org/wiki/Layer_2_Tunneling_Protocol)（Layer 2 Tunneling Protocol / RFC 2661）** として発展しました。

```
[リモートユーザー]──(ダイヤルアップ/PPP)──→[ISPのNAS]
                                                  │
                                                  ▼ L2Fトンネル
                                           [企業本社のL2Fサーバー]
                                                  │
                                                  ▼
                                           [社内ネットワーク]
```

__L2F → L2TPへの流れ__

| プロトコル | 特徴 |
|------------|------|
| **L2F** | Cisco主導。PPPフレームのトンネリング。暗号化なし。 |
| **PPTP** | Microsoft主導。PPPフレームのトンネリング。暗号化なし。 |
| **L2TP** | L2FとPPTPを統合。現在も広く使われるレイヤー2トンネリングプロトコル。 |

### 2. L2スイッチにおける「レイヤー2フォワーディング」

もう一つの意味は、**L2スイッチ（レイヤー2スイッチ）がイーサネットフレームを転送する仕組み**そのものです。

__本質__

**MACアドレスを見て、同一ネットワーク（同一VLAN）内でフレームを適切なポートに転送する技術**です。

__動作の仕組み__

L2スイッチは、受信したイーサネットフレームの**宛先MACアドレス**を見て、どのポートに出せばよいかを判断します。

1. **MACアドレス学習**：どのMACアドレスがどのポートに接続されているかをMACアドレステーブルに記録
2. **フォワーディング**：宛先MACアドレスに対応するポートだけにフレームを送出
3. **フラッディング**：宛先MACアドレスが不明な場合、同一VLANの全ポート（受信ポート除く）に送出

```
[PC-A: MAC=aa:aa] ──→ [L2スイッチ] ──→ [PC-B: MAC=bb:bb]
                           │
                    MACテーブルで判断
                    aa:aa → Port1
                    bb:bb → Port2
```

__L2フォワーディング vs L3ルーティング__

| 項目 | L2フォワーディング（L2SW） | L3ルーティング（ルーター/L3SW） |
|------|---------------------------|--------------------------------|
| 判断基準 | MACアドレス | IPアドレス |
| 転送単位 | イーサネットフレーム | IPパケット |
| 動作層 | データリンク層（レイヤー2） | ネットワーク層（レイヤー3） |
| 同一VLAN内通信 | 可能 | 不要（L2で完結） |
| 異なるVLAN間通信 | 不可（L3機器が必要） | 可能 |

## そもそも同じもの？

**完全に別物です**。
L2FはVPNの一種で、L2スイッチのフォワーディングは社内LANのスイッチが行う普通の転送動作です。名前が似てるだけで中身は別物です。

名前に「L2（Layer 2）」と「フォワーディング」が含まれるため紛らわしいですが、両者は**技術的な目的・動作・文脈がまったく異なる**別々の技術です。

### 違いの整理

| 項目 | L2F（Layer 2 Forwarding Protocol） | L2スイッチのフォワーディング |
|------|-----------------------------------|---------------------------|
| **本質** | VPNトンネリングプロトコル | スイッチのフレーム転送機能 |
| **目的** | PPPフレームなどをIPネットワーク上で別拠点まで運ぶ | 同一VLAN内でイーサネットフレームを適切なポートに届ける |
| **動作の場所** | ルーター・VPNゲートウェイ・NAS（ダイヤルアップサーバー） | L2スイッチ（社内LAN機器） |
| **扱う情報** | PPPフレーム全体をカプセル化 | MACアドレスを見てポートを選択 |
| **ネットワークを越えるか** | はい（WAN・インターネットを越える） | いいえ（同一VLAN・同一セグメント内） |
| **標準化** | [RFC 2341](https://datatracker.ietf.org/doc/html/rfc2341)（後にL2TPへ統合） | IEEE 802.1D（スパニングツリー）などとともに基本的なL2仕様 |

### なぜ名前が似ているのか

「Layer 2（レイヤー2）」と「Forwarding（転送・フォワーディング）」は、どちらもネットワーク技術において**非常に汎用的な単語**です。

- **L2F**：「レイヤー2（PPPフレームなど）の情報を、別の場所まで転送（フォワード）するプロトコル」という意味で命名された
- **L2スイッチのフォワーディング**：「レイヤー2（イーサネットフレーム）を、適切なポートに転送（フォワード）する動作」という意味

つまり、**「レイヤー2の何かを、どこかに転送する」という大枠は共通**していますが、**「何を」「どこへ」「なぜ」転送するかが全く異なります**。

### 技術的な本質の違い

__L2F__
```
[リモートPC]──(PPP/電話回線)──→[ISP]──(IPネットワーク上をL2Fでトンネリング)──→[企業本社]
```
- **「遠く離れた場所にあるレイヤー2接続を、IPネットワークを通じて持ち運ぶ」** 技術

__L2スイッチのフォワーディング__
```
[PC-A]──→[L2スイッチ]──→[PC-B]  （同一LAN内）
```
- **「同じ部屋や同じ建物の中で、MACアドレスに基づいてフレームを届ける」** 動作



## なぜ重要か

「L2フォワーディング」の文脈によって、必要な理由が異なります。以下の2つの観点で整理します。

### 1. L2F（VPNトンネリング）としての必要性

L2Fが必要だったのは、**「リモートユーザーがダイヤルアップで接続したPPPセッションを、企業の本社ネットワークまでレイヤー2のまま届けたい」** という要請に応えるためです。

__なぜ必要だったか__

- **ダイヤルアップ時代の課題**：リモートユーザーはISPに電話回線で接続し、PPPで認証を行います。しかし、このPPPセッションを企業の本社まで届けるには、ISPのネットワークを「通過」する必要がありました。
- **IPレイヤーで中継すると認証情報が失われる**：PPPフレームの中にはパスワード認証（PAP/CHAP）などの情報が含まれています。これをIPパケットとして再構成して中継すると、企業側で「誰が接続してきたか」を正しく認識できなくなります。
- **レイヤー2のままトンネリングすることで解決**：PPPフレームをそのままカプセル化してIPネットワーク上を運び、本社のL2Fサーバーで再構築することで、**企業側は「まるでユーザーが直接ダイヤルインしてきたかのように」PPPセッションを扱えます**。

```
[リモートユーザー]──(電話回線+PPP)──→[ISP]──(L2Fトンネル)──→[企業本社]
                                         ↑
                              PPPフレームをそのままカプセル化して運ぶ
```

__現代での位置づけ__

L2F自体は現在ほぼ使われていませんが、その後継である **[L2TP](https://ja.wikipedia.org/wiki/Layer_2_Tunneling_Protocol)** は現在も広く使われています。L2TPが必要な場面は以下の通りです。

- **異なる拠点間で同一のブロードキャストドメイン（同一VLAN）を維持したい**：IPレイヤーでルーティングするとVLANが分断されるため、レイヤー2で繋ぐ必要がある
- **リモートアクセスVPNで、企業の内部認証（RADIUS等）をそのまま使いたい**：PPPセッションをトンネリングすることで、ISP側ではなく企業側で認証処理を完結させる

### 2. L2スイッチのフォワーディングとしての必要性

L2スイッチにおけるフォワーディングが必要なのは、**「同一ネットワーク（同一VLAN）内で、複数の端末が効率的に通信できるようにするため」** です。

__なぜ必要か__

- **ハブ（L1）との違い**：ハブは受信した信号を全ポートにそのまま流します（コリジョンが多発し、帯域が浪費される）。
- **L2スイッチの役割**：MACアドレスを学習し、宛先に該当するポートだけにフレームを送出することで、**不要な通信を他のポートに流さず、帯域を節約**できます。
- **VLAN内での通信をL3に頼らず完結させる**：同一VLAN内のPC間通信は、わざわざルーター（L3）を経由させる必要がありません。L2スイッチが直接転送することで、**レイテンシの低減**と**ルーターの負荷軽減**が実現します。

```
[PC-A] ──→ [L2スイッチ] ──→ [PC-B]
                │
         MACテーブルでPort2だけに送出
         （他のポートには流さない）
```

### まとめ

| 文脈 | なぜ必要か |
|------|-----------|
| **L2F/L2TP（VPN）** | PPPフレームなどのレイヤー2情報をそのまま別拠点まで届け、企業側で認証・接続処理を完結させるため |
| **L2スイッチのフォワーディング** | MACアドレスで宛先を絞り込み、同一VLAN内の通信を効率的・低レイテンシで行うため |

つまり、どちらの場合も共通する本質は、**「レイヤー2の情報（フレームやMACアドレス）を適切に扱い、必要な相手に届ける仕組みが必要だから」** です。

## 総括

L2フォワーディングの2つの側面の本質は、以下のように整理できます。

### 1. L2スイッチのフォワーディング（MACベース転送）

> **「同じネットワーク内で、MACアドレスという『住所』を見て、必要な相手にだけデータを届ける技術」**

__一言で表すと__

**「無駄な配達を防ぎ、正しい宛先にだけフレームを届ける制御技術」**

### 2. L2F（Layer 2 Forwarding Protocol）

> **「遠く離れた地点同士を、あたかも同じレイヤー2ネットワークにいるかのように接続するトンネリング技術」**

__一言で表すと__

**「地理的な距離をレイヤー2で越え、遠隔地を仮想的に同一LANにする技術」**

### 両者の共通する本質

| 側面 | 本質 |
|------|------|
| **L2スイッチのフォワーディング** | **同一LAN内での「正確な届け先への制御」** |
| **L2F** | **遠隔地を同一LANとして「見せる」仮想化** |

どちらも、**「レイヤー2のフレームを、意図した先に届ける」**という点では共通しています。違いは、L2スイッチの方が**「物理的に同じLAN内での制御」**であるのに対し、L2Fは**「地理的に離れたLANを仮想的に同一LANとして接続する」**という点です。

### まとめ

> **L2フォワーディングの本質は、「レイヤー2のフレームを、意図した正しい先に届ける技術」です。スイッチの場合は同一LAN内の制御として、L2Fの場合は遠隔地を同一LANとして見せる仮想化として実現されます。**
