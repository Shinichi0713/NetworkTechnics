インターネットから組織の内部にあるサーバーにアクセスする際に、何気に組織内部の事情に合わせた変換が必要となります。
そんな変換技術の一つとしてポートフォワード（port forwarding / ポート転送）があります。

## 概要
ポートフォワードは、**ネットワークの「入り口」であるルーターやファイアウォールが、特定のポート番号宛ての通信を、内部ネットワークの特定の端末に「転送」する仕組み**です。

以下に、技術者として理解しておくべきポイントをまとめます。

### 1. ポートフォワードの本質

インターネットから自社や自宅のネットワークに通信が届くとき、通常は「グローバルIPアドレス（例：`203.0.113.10`）」宛てに届きます。しかし、そのグローバルIPの背後には、プライベートIP（例：`192.168.1.0/24`）を使った多数の端末（PC、サーバー、プリンターなど）が接続されています。

ルーターは「この通信はどの端末宛てか」を自動では判断できないため、**「ポート番号 X 宛ての通信が来たら、内部の端末 A に渡せ」** という転送ルールを事前に設定しておくのがポートフォワードです。

> 例：インターネットから `203.0.113.10:8080` 宛てのアクセスを、社内の `192.168.1.50:80`（社内Webサーバー）に転送する。

### 2. なぜ必要なのか（NATとの関係）

現代のネットワークでは、[NAT](https://ja.wikipedia.org/wiki/Network_Address_Translation)（Network Address Translation）によって、複数の端末が1つのグローバルIPアドレスを共有しています。[ポートフォワード](https://ja.wikipedia.org/wiki/%E3%83%9D%E3%83%BC%E3%83%88%E3%83%95%E3%82%A9%E3%83%AF%E3%83%BC%E3%83%89) は、このNAT環境下で **「外部から内部の特定のサービスに意図的に到達させる」** ための例外ルールです。

通常のNAT（Outgoing）は、内部端末が外に通信を始めたとき、その帰りの通信を自動で振り分けます。しかし、**外部から内部へ通信を始める（Incoming）場合**には、この自動振り分けが働かないため、ポートフォワードが必要になります。

### 3. 動作の仕組み

```
[インターネット上のクライアント]
         │
         ▼
  203.0.113.10:8080  ← グローバルIP:ポート
         │
    [ルーター/FW]  ──「ポートフォワード設定」──┐
         │                                      │
         │（設定なしの場合）                    │（設定ありの場合）
         ▼                                      ▼
    通信を破棄                              192.168.1.50:80
                                         （社内Webサーバー）
```

ルーターは以下の情報で転送先を判断します。

- **プロトコル**（TCP / UDP）
- **宛先ポート番号**（外部から見たポート番号）
- **転送先プライベートIP**と**転送先ポート番号**

### 4. 主な用途

__(1) 社内サーバーの公開__

社内に設置したWebサーバーやメールサーバーを、インターネットからアクセス可能にする場合に使用します。

__(2) リモートアクセス__

[RDP](https://learn.microsoft.com/ja-jp/windows-server/remote/remote-desktop-services/clients/remote-desktop-clients)（Windowsのリモートデスクトップ）や[SSH](https://ja.wikipedia.org/wiki/Secure_Shell)のポートを転送し、外出先から社内の特定の端末に接続します。

__(3) ゲーム・P2P・IoT機器__

オンラインゲームや監視カメラ、NASなどが外部からの接続を必要とする場合に設定します。

### 5. ポートフォワードの種類

| 種類 | 概要 |
|------|------|
| **ローカルポートフォワード** | 外部（インターネット）→ 内部ネットワークの特定端末への転送。最も一般的な形態。 |
| **リモートポートフォワード** | 内部ネットワーク → 外部への逆方向転送。主に[SSHトンネリング](https://ja.wikipedia.org/wiki/SSH%E3%83%88%E3%83%B3%E3%83%8D%E3%83%AB)で使用。 |
| **ダイナミックポートフォワード** | 特定のポートをSOCKSプロキシとして動作させ、複数の転送先を動的に切り替える方式。 |

### 6. セキュリティ上の注意点

ポートフォワードは便利ですが、**「外部に穴を開ける」** 行為そのものなので、注意が必要です。

- **攻撃対象の拡大**：公開したポートがスキャンされ、脆弱性攻撃やブルートフォース攻撃を受けるリスクが増加します。
- **IP制限**：可能であれば、接続元IPアドレスを限定（例：社外局IPのみ許可）すべきです。
- **ポート番号の変更**：Well-knownポート（22番SSH、3389番RDPなど）をそのまま公開すると攻撃を受けやすいため、外部側のポート番号を変更（例：2222番、33890番）することが推奨されます。
- **VPNとの使い分け**：セキュリティ要件が高い場合は、ポートフォワードで個別に穴を開けるのではなく、[VPN](https://ja.wikipedia.org/wiki/%E3%83%90%E3%83%BC%E3%83%81%E3%83%A3%E3%83%AB%E7%A7%81%E6%9C%89%E7%B6%B2%E8%B7%AF)接続を介して内部ネットワークにアクセスする方が安全です。

### 7. よく混同される概念との違い

| 技術 | ポートフォワードとの違い |
|------|------------------------|
| **[DMZ](https://ja.wikipedia.org/wiki/Demilitarized_Zone)** | DMZは「特定の内部端末への**全ポート**を転送（またはほぼ全て）」する極端な形態。ポートフォワードは「特定のポートのみ」を転送する。 |
| **[リバースプロキシ](https://ja.wikipedia.org/wiki/%E3%83%AA%E3%83%90%E3%83%BC%E3%82%B9%E3%83%97%E3%83%AD%E3%82%AD%E3%82%B7)** | ポートフォワードは「通信をそのまま転送」するのに対し、リバースプロキシは「中継して内容を解釈・加工」する（例：SSL終端、ロードバランシング）。 |
| **[UPnP](https://ja.wikipedia.org/wiki/Universal_Plug_and_Play)** | 自動でポートフォワード設定を行う仕組み。便利だがセキュリティリスクが高く、企業環境では無効化が推奨されます。 |

## ネットワーク内の特定端末に通信転送するとは

より正確に言うと、ポートフォワーディングでは　**「ポート番号そのものも変換される場合がある」**　という点を補足しておくとよいでしょう。

### 認識の確認

__正しい点__
> 「特定ポートの通信を特定の端末に転送する技術」

これはまさにポートフォワーディングの本質です。インターネット側から届いたパケットの**宛先を書き換えて**、内部の特定端末に届けるのが役割です。

__補足：ポート番号も変換されることがある__

ポートフォワーディングでは、**IPアドレスだけでなく、ポート番号も書き換わることがあります**。

```
外部からのアクセス: 203.0.113.10:8080
                        ↓ ポートフォワーディング
内部の転送先:      192.168.1.50:80
```

この例では、**ポート番号 8080 が 80 に変換**されています。これは「ポートを書き換えている」ように見えますが、目的は「ポート番号を変更すること」ではなく、「**正しいサービス（Webサーバーの80番）に届けること**」です。

### つまり

| 観点 | ポートフォワーディング |
|------|----------------------|
| 目的 | 外部から内部の特定端末・サービスに通信を届ける |
| IPアドレス | グローバルIP → プライベートIP に書き換える |
| ポート番号 | 場合によっては書き換える（例: 8080→80） |
| 本質 | 「通信の宛先（IP+ポート）を変更して転送する技術」 |

つまり、**「ポート番号そのものを変更することが目的の技術」ではなく、「特定の通信を特定の端末に届けるために、必要に応じて宛先（IPやポート）を書き換えて転送する技術」** という理解が最も正確です。

## デバイス

ポートフォワーディングが実施されるのは、**NAT機能（特にDestination NAT）を持つ機器**です。

例えばネットワークの通信を転送するデバイスとしてL3SWが存在します。
L3SWの中にも対応しているものはありますが、**「L3SWだから必ずポートフォワーディングができる」というわけではありません**。NAT機能を搭載したL3SWや、いわゆる「FW（ファイアウォール）付きL3SW」であれば可能ですが、単なるルーティング機能のみのL3SWでは実施できません。

### ポートフォワーディングが実施される主な機器・場所

| 機器 | 実施可否 | 備考 |
|------|----------|------|
| **家庭用・SOHO用ルーター** | ◎ | 最も一般的。設定画面で「ポート転送」「ポート開放」として存在。 |
| **企業用ファイアウォール（FW）** | ◎ | 境界でDNAT（Destination NAT）として実装されるのが標準。 |
| **NAT対応L3SW** | ◎ | 高機能なL3SW（ヤマハルーター、Cisco ISR、企業向けL3SWなど）。 |
| **NAT非対応L3SW** | ✕ | ルーティングはできるが、IPアドレス/ポートの書き換え（NAT）ができない。 |
| **L2SW** | ✕ | レイヤー2で動作するため、IPやポートの概念で振り分けられない。 |
| **サーバーOS（ソフトウェア）** | ◎ | Linuxの[iptables](https://ja.wikipedia.org/wiki/Iptables)/[nftables](https://ja.wikipedia.org/wiki/Nftables)、Windowsのポートプロキシ機能など。 |

### 技術的な実装の実体

ポートフォワーディングは、厳密には **「Destination NAT（DNAT / 宛先NAT）」** という技術で実装されることがほとんどです。[NAT](https://ja.wikipedia.org/wiki/Network_Address_Translation) には「Source NAT（SNAT、内部→外部の送信元変換）」と「Destination NAT（DNAT、外部→内部の宛先変換）」があり、ポートフォワーディングは後者に該当します。

```
[外部クライアント] ──→ [NAT対応ゲートウェイ（ルーター/FW/L3SW）]
                              │
                              ▼ DNAT変換
                        宛先IP: グローバルIP → プライベートIP
                        宛先Port: 8080 → 80
                              │
                              ▼
                        [内部サーバー]
```


ポートフォワーディングは、**「NAT機能を持つゲートウェイ機器」** で実施されます。具体的には以下が該当します。

- **一般的な実施場所**：境界ルーター、ファイアウォール、NAT対応のL3SW
- **実装の実態**：Destination NAT（宛先NAT）としてのIP/ポート書き換え
- **L3SWでできるか**：機種による。NAT（NAPT/DNAT）機能を持つL3SWなら可能

つまり、「L3SW」というカテゴリそのものではなく、**「NAT機能を持つネットワーク機器」** という理解が正確です。

## 総括

ポートフォワーディングの本質は、**「NATの境界で通信の宛先（IPアドレス・ポート番号）を書き換え、外部から内部の特定サービスに意図的に届ける技術」** です。

より一言で表すなら、**「境界を越えて通信を『届け先』に導く宛先書き換え」** です。

### なぜこれが本質か

通常、NAT環境では内部から外部への通信は自動で管理されますが、**外部から内部への通信は「どの端末に届けるか」が不明**なため破棄されます。

ポートフォワーディングは、この**「破棄の壁」に対して、意図的な例外ルールを作る**ことで、特定の通信だけを内部に通します。それがDestination NAT（宛先NAT）として実装される理由です。

### 一言で言うと

> 「ポートフォワーディングとは、インターネット側から届いたパケットの宛先を書き換えて、社内の特定のサーバーやPCに届ける技術です。NATで複数の端末が1つのグローバルIPを共有しているとき、『このポート番号宛ての通信はあの端末に渡せ』という転送ルールを作るのが役割です。」
