PCがネットワーク経由で通信するには、ネットワーク上のアドレスを示す[IPアドレス](https://yoshishinnze.hatenablog.com/entry/2026/08/14/043000)が必要です。
そしてIPアドレスを設定する部位をインターフェースと呼びます。

このインターフェースに、他の人との通信を用途としない変わり種があります。
ループバックインターフェースと呼ばれるアドレスに関しては、他の人との通信には使いません。

今日はそんなループバックインターフェースについて説明します。

## 概要
ループバックインターフェース（loopback interface）とは、コンピュータが自分自身と通信するために使用する、仮想的なネットワークインターフェースのことです。

### 主な特徴

- **物理的なハードウェアではありません**: 実際のNIC（ネットワークカード）のような物理デバイスではなく、OSの内部で仮想的に作られたインターフェースです。
- **自分自身への通信に使われます**: データを外部ネットワークに出さず、同じマシン内で送受信します。
- **常に有効です**: ネットワークケーブルの接続状況や物理的なネットワークの状態に関わらず、常に利用可能です。

### 代表的なIPアドレス

最もよく知られているループバックアドレスは、IPv4では以下の範囲です。

- `127.0.0.1`（最も一般的に使われます）
- `127.0.0.0/8`（`127.0.0.0` ～ `127.255.255.255` の全範囲がループバックに割り当てられています）

この `127.0.0.1` は「localhost」というホスト名で解決されることが一般的です。

### よく使われる場面

- **Webアプリケーションのローカル開発**: 開発中のサーバに `http://127.0.0.1:8080` などでアクセスする
- **データベースへのローカル接続**: `localhost` 経由で同じマシン上のMySQLやPostgreSQLに接続する
- **ネットワークサービスの動作確認**: ネットワーク機能が正しく動作しているかを、外部に依存せずにテストする
- **プロセス間通信**: 同一マシン上の異なるプロセス間でネットワークソケットを使って通信する

## なぜ必要なのか？
自分自身との通信のため、と言われても。
なぜ自分自身との通信が必要となるかピンときません。
ということで、ループバックインターフェースが必要な理由について説明します。

### 1. ネットワークの「自分宛て通信」を可能にする
アプリケーション開発していると、一つのコンピュータ上で複数のアプリケーションを連携して動作させたい用途があります。
こんな場面のため、というのは、コンピュータ上で動作するアプリケーション同士が、**ネットワークの仕組みをそのまま使って**通信できるようにするためです。

たとえば、WebブラウザとWebサーバが同じマシン上にある場合、ブラウザは「このマシン上のWebサーバにアクセスしたい」と思います。ループバックインターフェースがなければ、「自分自身にパケットを送る」という特殊な処理を、アプリケーションごとに別途実装する必要が出てきます。

ループバックがあることで、OSのネットワーク機能を一切変更せずに、「外部に出さずに自分に戻ってくる」という動作が自然に実現できます。

### 2. 物理ネットワークに依存しない「必ず使える通信路」を提供する

ループバックインターフェースは、以下の状況でも常に利用可能です。

- ネットワークケーブルが抜けている
- Wi-Fiに接続していない
- 物理的なNIC（ネットワークカード）が故障している

これは非常に重要です。たとえば、データベースやWebサーバなどの**常時起動しているサービス**は、起動時に自分の待ち受けアドレスを確保する必要があります。ループバックがあれば、外部ネットワークに繋がっていなくても「少なくとも自分自身からはアクセスできる」という保証が得られます。

### 3. 開発・テストを安全かつ簡単にする

開発者がWebアプリやAPIをローカルで動作確認するとき、`127.0.0.1` や `localhost` を使うのは日常的です。ループバックを使えば：

- **外部に影響を与えない**: 間違って本番サーバや外部ネットワークに触る心配がない
- **他の人からアクセスされない**: 原則として同じマシンからしか到達できないため、開発中の不完全な状態が外部に露出しない

### 4. OS内部のプロセス間通信を統一的に行う

現代のOSでは、多くのシステムサービス（ログ記録、設定管理、セキュリティ関連など）が独立したプロセスとして動作しています。これらが互いに通信する際、専用の複雑な仕組みではなく、**「TCP/IPでlocalhostに繋げばいい」** という統一された方法を使えます。

これにより、アプリケーション開発者は「相手が同じマシン内にあるのか、別のマシンにあるのか」を意識せずに、同じコードで通信処理を書くことができます。

## ルータに設定するのは何のため？

ルータに設定するループバックインターフェースは、PCの `127.0.0.1` のような「自分自身への通信」という意味合いとは少し異なります。ルータの場合は、**物理インターフェースに依存しない「常に有効なIPアドレス」** を持つための仮想インターフェースとして使われます。

主な目的は以下の通りです。

### 1. ルーティングプロトコルの安定した識別子（Router ID）を確保する

OSPFや[BGP](https://yoshishinnze.hatenablog.com/entry/2026/09/24/043000)などのルーティングプロトコルでは、ネットワーク内で各ルータを一意に識別する「Router ID」が必要です。

もし物理インターフェースのIPアドレスをRouter IDに使うと、その物理ポートがダウンしたり、IPアドレスが変更されたりした際に、Router IDも変わってしまい、ルーティングプロトコルが再計算・再収束を起こす可能性があります。

一方、ループバックインターフェースは**物理ポートの状態に関係なく常にUP**であるため、ルータの識別子として非常に安定します。

### 2. 管理アクセス用の「絶対に落ちないIPアドレス」を持つ

ルータには通常、複数の物理インターフェース（ギガビットEthernetなど）があります。管理のためにどれか一つの物理IPにアクセスすると、そのリンクが切断された瞬間にアクセス不能になります。

ループバックにIPアドレスを設定しておけば、**どの物理経路からでも到達可能な限り**、そのループバックアドレス宛にパケットが届きます。結果として、特定の物理リンクの障害に左右されない、信頼性の高い管理用アドレスとして機能します。


因みに。
この物理リンクの障害に左右されな理由は、**「ルーティングプロトコルがループバックアドレスを『そのルーター全体』への到達先として広告する」** からです。物理インターフェースのIPとは、ネットワーク上での扱いが根本的に異なります。

__物理インターフェースのIPとの違い__

__物理IPの場合__

物理インターフェースのIPは、**特定のリンク（ケーブル）に紐づいています**。

```
[管理PC] ----(Link A)---- [ルーター1: Gig0/0 = 10.0.1.1]
```

この状態で管理PCが `10.0.1.1` にアクセスすると、パケットは Link A を通るしかありません。Link A が切断されると、ネットワーク上から `10.0.1.0/24` というサブネットへの到達経路が消えるため、アクセス不能になります。

__ループバックIPの場合__

一方、ループバックアドレス（例：`10.0.0.1/32`）は、**どの物理ポートにも紐づいていません**。

```
[管理PC] --- [ルーター2] ---(Link A)--- [ルーター1: Gig0/0]
                         ---(Link B)--- [ルーター1: Gig0/1]
                                      [ルーター1: Loopback0 = 10.0.0.1/32]
```

ルーティングプロトコル（OSPF など）が動作していると、ルーター1は自分のループバックアドレス `10.0.0.1/32` を「自分に届く経路」として、隣接するルーター（ルーター2）に広告します。
ルーター2のルーティングテーブルには以下のように登録されます。

- `10.0.0.1/32` に行くには → **Link A 経由でルーター1へ**
- Link A がダウンすると、OSPFが再計算し → **Link B 経由でルーター1へ** に切り替わる

つまり、ルーター2から見れば **`10.0.0.1/32` は「ルーター1そのもの」への到達先**になっています。どの物理リンクを使うかは、到達性が保たれる限りルーティングプロトコルが自動で選んでくれます。

__ルーター内部での処理__

パケットがルーター1に到達した後の話も重要です。

ルーター1は、**どの物理インターフェース（Gig0/0 でも Gig0/1 でも）から入ってきたとしても**、パケットの宛先IPが「自分自身が持つアドレス」であれば、それをローカル処理の対象と判断します。
→ループバックインターフェースがあれば確実にデータを受け取ることが可能となるわけです。
ルーター1のルーティングテーブルには以下のように登録されています。

```
C    10.0.0.1/32 is directly connected, Loopback0
```

したがって、Link B から入ってきた `10.0.0.1` 宛のパケットも、OS（IOS など）が「これは自分の Loopback0 に届けるべきパケットだ」と認識し、適切に処理します。



### 3. BGPピアリングのエンドポイントとして使う

BGPでは、ピア（隣接ルータ）とのTCPセッションを確立しますが、この際にループバックアドレスを使うことが一般的です。

物理インターフェース間でピアリングすると、直結リンクの障害で即座にセッションが断たれます。しかし、ループバック同士でピアリングし、裏側でIGP（OSPFなど）で経路冗長性を確保しておけば、**複数の物理経路のうち一つが生きていればBGPセッションを維持**できます。

### 4. テストや診断のためのエンドポイント

VPNトンネルの終端点や、ポリシーのテスト、pingによる到達性確認など、**「このルータそのもの」を対象とする通信**の宛先としても活用されます。

### PCのループバックとの違い

| 項目 | PCのループバック | ルータのループバック |
|------|------------------|----------------------|
| 代表的なIP | `127.0.0.1` | `10.0.0.1` など任意のIP（通常 `/32`） |
| 到達範囲 | 自分自身のみ | ネットワーク経由で他のルータからも到達可能 |
| 主な目的 | 自分宛通信の汎用化 | 安定した識別子・管理アドレスの確保 |

つまり、ルータのループバックは「自分に手紙を出す私書箱」ではなく、**「住所が変わらず、かつどの道からでも届く本社の代表電話番号」** のような役割と考えるとイメージしやすいかもしれません。


## その他用途

先程説明した以外にも用途があります。

### ネットワーク機器（ルーター・L3スイッチ）におけるその他の用途

__1. トンネル（GRE / IPsec / MPLS）のエンドポイント__

GREトンネルやIPsecトンネルを張る際、物理インターフェースをエンドポイントにすると、そのリンクが落ちた瞬間にトンネルが切断されます。ループバックをトンネルのソース・デスティネーションに指定すれば、**裏側のIGP経路が生きている限りトンネルが維持**され、物理的な冗長構成と連動した安定したトンネルが実現できます。

また、MPLS環境ではルーターの **LSR ID（ラベルスイッチングルータの識別子）** としてループバックが必須です。

__2. 各種管理系プロトコルの「送信元アドレス」として__

SNMPトラップ、Syslog、NTP（時刻同期）、TACACS+/RADIUS（認証）など、ルーターが外部サーバーに向けて送信する管理トラフィックでは、**どのIPアドレスを送信元（source）にするか**を指定できます。

ループバックをソースに指定することで：
- ファイアウォールやACLで「この管理用サブネットからの通信のみ許可」といったポリシーを作りやすくなります
- 物理リンクの変更に伴って送信元IPが変わることを防げます
- サーバー側のログで「どのルーターからの通信か」を一貫して識別できます

__3. 管理系サービスの「待ち受けアドレス」として__

SSH、Telnet、HTTP（Web管理画面）などのサービスを、特定の物理インターフェースではなく**ループバックにだけバインド**する運用が行われます。これにより：
- 管理アクセスはループバック経由のみに限定される
- ユーザー側のセグメントに直接SSHで入るのではなく、必ず何らかの経路（管理用ネットワークなど）を通して到達する構造が強制される

__4. マルチキャストのRP（ランデブーポイント）アドレス__

PIM-SM（Sparse Mode）などのマルチキャスト環境では、RP（Rendezvous Point）としてループバックアドレスが使われることが多いです。RPはネットワーク内のマルチキャストグループの「集会所」のような存在ですが、物理インターフェースがダウンするとRPが機能不全になると困るため、安定したループバックがRPアドレスとして選ばれます。

### サーバー・ホスト側におけるその他の用途

__5. サービスのセキュアな「バインド」先__

Webサーバーやデータベース（MySQL、PostgreSQLなど）は、設定によって「どのIPアドレスで待ち受けるか」を指定できます。`127.0.0.1` のみにバインドすれば、**そのサービスは同じマシン内からしかアクセスできなくなります**。

これはセキュリティ上非常に重要です。たとえば：
- データベースを `127.0.0.1:3306` にだけバインドし、アプリケーションサーバーは同じマシン上で動かす
- 管理用のWebコンソールをlocalhostのみに公開し、外部からはVPNやSSHトンネル経由でアクセスさせる

__6. マイクロサービス・コンテナ環境での通信__

DockerやKubernetesなどのコンテナ環境では、各Pod/コンテナ内にも `lo`（ループバック）インターフェースが存在します。同じPod内の複数コンテナ間の通信や、サイドカーパターンでの連携にlocalhostが使われます。

## 総括

ループバックインターフェースとは、**物理的な接続に依存せず、常に存在する「自分自身」を指す仮想的な通信口**です。

PCでは、同じマシン内のアプリケーションがネットワークの仕組みをそのまま使って通信できるよう、`127.0.0.1` という「自分宛ての標準的な宛先」として機能します。

ルータなどのネットワーク機器では、特定のケーブルやポートに紐づかない「その機器そのもの」を表すIPアドレスとして機能します。物理リンクが変わっても消えないため、ルーティングプロトコルの識別子や、いつでも到達できる管理用アドレスとして使われます。

結局のところ、ループバックインターフェースは**ネットワークの変動に動じない「自分自身への確実な入口」** です。PCでも機器でも、物理的な接続状況に関わらず「自分」に届く通信路を確保するための仕組みです。
