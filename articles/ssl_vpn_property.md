在宅勤務をしているときに、インターネットから社内の特定リソースにアクセスしたい、手軽に。
そんな場面によく使われるVPN技術としてSSL-VPNと呼ばれる技術が使われます。

## 概要

**SSL-VPN**は、**SSL/TLSプロトコル**を利用して、インターネット経由で企業の内部ネットワークなどに安全にリモート接続するためのVPN技術です。

### 1. 基本的な仕組み

- **Webブラウザや専用アプリを使って接続**します。
- 通信内容をSSL/TLSで暗号化し、**HTTPSと同じ443番ポート**を主に使用します。
- 接続が確立すると、リモートユーザーの端末があたかも社内LANに直接つながっているかのように、内部システムにアクセスできます。

### 2. IPsec-VPNとの主な違い

| 項目                           | SSL-VPN                            | IPsec-VPN                              |
| ------------------------------ | ---------------------------------- | -------------------------------------- |
| **動作レイヤ**           | アプリケーション層（SSL/TLS）      | ネットワーク層（IPsec）                |
| **必要なもの**           | Webブラウザや軽量クライアント      | 専用クライアントソフト・設定           |
| **ファイアウォール穿越** | **容易**（HTTPSポート使用）  | **比較的困難**（専用プロトコル） |
| **主な用途**             | リモートアクセス（在宅勤務・出張） | 拠点間接続（本社―支社）               |
| **接続の容易さ**         | 手軽                               | 設定が複雑な場合が多い                 |

### 3. SSL-VPNの主な接続モード

- **Webモード（Webプロキシ）**Webブラウザから社内のWebメール、業務システムなどにアクセスする。専用アプリ不要で手軽。
- **トンネルモード（ネットワーク拡張）**
  専用クライアントを使い、リモート端末全体の通信を社内ネットワークにトンネリングする。社内サーバや共有フォルダなど、Web以外のサービスも利用可能。

### 4. メリット

- **接続が手軽**：Webブラウザがあれば基本的に接続可能。
- **ファイアウォールを通りやすい**：HTTPS（443番）を使うため、多くの環境で接続可能。
- **細かいアクセス制御**：ユーザーやグループごとに、どのアプリケーションやサーバにアクセスできるかを制限しやすい。

### 5. 注意点・デメリット

- **性能**：IPsecに比べて、大量データ転送ではやや遅くなる場合がある。
- **セキュリティ**：端末がウイルスに感染している場合、SSL-VPN経由で社内に持ち込まれるリスクがある（NACなどと併用が推奨）。
- **Webモードの制限**：Webアプリケーション以外（専用クライアントソフトが必要なシステムなど）は使えない場合がある。

## IPsecとの違い

[拠点間を接続する技術](https://yoshishinnze.hatenablog.com/entry/2026/01/30/000000)としてはSSL-VPN以外にIPsecという技術があります。
SSL-VPNとIPsecの違いは、**動作するレイヤ、接続の仕組み、向いている用途**にあります。以下に本質的な違いを整理します。

### 1. プロトコルとレイヤの違い

| 項目                   | SSL-VPN                                           | IPsec                        |
| ---------------------- | ------------------------------------------------- | ---------------------------- |
| **動作レイヤ**   | アプリケーション層（L7）                          | ネットワーク層（L3）         |
| **暗号化の単位** | SSL/TLSで「通信内容（アプリケーション）」を暗号化 | IPパケット全体を暗号化・認証 |
| **見え方**       | 特定のアプリ（Web、専用クライアント）を保護       | 端末全体のIP通信をトンネル化 |

### 2. 接続手順と使い勝手

| 項目                       | SSL-VPN                                         | IPsec                                                  |
| -------------------------- | ----------------------------------------------- | ------------------------------------------------------ |
| **クライアント要件** | Webブラウザや軽量アプリで接続可能               | 専用クライアントソフトと設定が必要                     |
| **設定の複雑さ**     | **簡単**（URLにアクセスして認証するだけ） | **複雑**（事前共有鍵、証明書、ポリシー設定など） |
| **ユーザーの負担**   | 小さい（ブラウザがあればOK）                    | 大きい（接続設定の管理が必要）                         |

### 3. ファイアウォール穿越（接続しやすさ）

| 項目                   | SSL-VPN                                         | IPsec                                                                                 |
| ---------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------- |
| **使用ポート**   | HTTPS（TCP 443）                                | ESP（IPプロトコル50）、AH（51）、UDP 500/4500                                         |
| **穿越の容易さ** | **非常に容易**（HTTPSはほぼ全環境で開放） | **困難な場合あり**（NAT越えに追加設定が必要、企業FWでブロックされることが多い） |

### 4. 向いている用途

| SSL-VPN                                                             | IPsec                                                |
| ------------------------------------------------------------------- | ---------------------------------------------------- |
| **リモートアクセス**（在宅勤務、出張者から社内へ）            | **拠点間接続**（本社―支社、データセンター間） |
| 社内Webシステム、メール、ファイルサーバへの**一時的アクセス** | 拠点全体のLAN同士を**常時接続**する            |
| 個人端末からの**手軽な接続**                                  | 大量の通信を**安定・高速**に送る               |

### 5. セキュリティ特性の違い

| 項目                       | SSL-VPN                                                | IPsec                                        |
| -------------------------- | ------------------------------------------------------ | -------------------------------------------- |
| **認証のタイミング** | ユーザー認証（ID/PWや証明書）が基本                    | 端末（ゲートウェイ）同士の認証＋ユーザー認証 |
| **保護範囲**         | アプリケーション単位で細かく制御可能                   | ネットワーク全体を一括で保護                 |
| **端末チェック**     | クライアントの健全性（アンチウイルス等）を確認しやすい | 比較的困難                                   |

### 6. 性能の違い

- **IPsec**：ネットワーク層で直接処理するため、**オーバーヘッドが小さく、スループットが高い**。拠点間の大量データ転送に向いています。
- **SSL-VPN**：アプリケーション層で処理するため、**ややオーバーヘッドが大きい**。ただし、リモートアクセスの帯域では実用上問題ないことが多いです。

## SSL-VPN種類

SSL-VPNを実現する手法には主に**3つのモード（方式）** があります。ベンダーによって呼び方が若干異なりますが、概念的には以下のように分類されます。

### 1. Webモード（Webプロキシモード）

**仕組み**

- WebブラウザからSSL-VPNゲートウェイにHTTPSで接続し、社内のWebアプリケーション（Webメール、業務システム、イントラネット等）に中継してもらう方式です。
- SSL-VPN装置が「プロキシ」として動作し、社内Webサーバとの通信を代理で行います。

**特徴**

- **クライアント不要**：Webブラウザがあれば接続可能。
- **接続が最も手軽**：URLにアクセスして認証するだけ。
- **制限**：Webアプリケーション（HTTP/HTTPS）のみ利用可能。専用クライアントが必要なアプリや、社内ファイルサーバ（SMB等）は基本的に使えません。

**向いている場面**
-インターネットカフェや顧客先PCなど、**一時的に借りた端末から社内Webシステムにだけ入りたい**場合。

### 2. トンネルモード（ネットワーク拡張モード / フルトンネルモード）

**仕組み**

- 専用のSSL-VPNクライアント（仮想NICドライバ等）を端末にインストールし、端末全体の通信をSSL-VPNゲートウェイ経由で社内ネットワークにトンネリングします。
- 接続中は、リモート端末が**社内LANの一部のように振る舞い**、社内IPアドレスを取得するか、社内ルーティングが可能になります。

**特徴**

- **利用範囲が広い**：Web以外のサービス（ファイルサーバ、データベース、RDP/SSH接続、社内専用アプリ等）も利用可能。
- **クライアント要**：専用アプリやドライバのインストールが必要。
- **セキュリティ制御**：社内ネットワークへの接続を一括管理しやすい。

**向いている場面**

- **在宅勤務や常時リモート勤務**：社内システム全般に自宅からアクセスしたい場合。

### 3. ポートフォワーディングモード（Thinクライアントモード）

**仕組み**

- WebブラウザでSSL-VPNゲートウェイに接続した上で、**JavaアプレットやActiveX、HTML5などの軽量プラグイン**を一時的に起動し、特定のアプリケーションだけを社内にトンネリングします。
- トンネルモードほど完全なネットワーク拡張ではなく、**指定されたアプリの通信だけ**を中継します。

**特徴**

- **インストールが軽い**：完全な専用クライアントではなく、ブラウザ上で軽量コンポーネントが動作。
- **権限が制限された環境でも動作しやすい**：管理者権限不要で動くことが多い。
- **対応アプリに制限あり**：対応していないアプリケーションでは使えない場合がある。

**向いている場面**

- **社内PCではない端末**から、特定の業務アプリ（メールクライアント、ターミナル接続等）だけ安全に使いたい場合。

### 補足：ベンダー独自の拡張

一部のSSL-VPN製品（Fortinet FortiGate、Palo Alto、Citrix、F5等）では、以下のような独自機能も提供しています。

- **ファイル共有/ポータルモード**：ブラウザ上で社内ファイルサーバ（Windowsファイル共有等）にアクセスし、ファイルのアップロード/ダウンロードを可能にする。
- **HTML5ベースのリモートデスクトップ**：ブラウザ上でRDP/SSHクライアントを動作させ、専用アプリなしでサーバに接続する。
- **Split Tunneling（分割トンネリング）**：社内リソースだけをVPN経由にし、インターネット接続は直接行うことで、VPN負荷と帯域を節約する。

## 総括

SSL-VPNの本質は、**「手軽さと細かい制御を両立させた、個人向けのリモートアクセス技術」** です。

IPsecが「拠点全体を常時つなぐ基幹回線」であるのに対し、SSL-VPNは **「人がインターネットから社内リソースに入る接続」** に特化しています。Webブラウザや軽量クライアントでHTTPS一本（443番）から接続できる手軽さ、および「誰が、どのアプリに、どこまで入れるか」をアプリケーション層で細かく制御できる点が、他のVPN技術と決定的に異なる本質です。

3つの接続モード（Web／ポートフォワーディング／トンネル）も、結局は **「利便性」と「アクセス範囲」のトレードオフ**を用途に応じて選べる仕組みに過ぎず、現代の在宅勤務やモバイル勤務を支える基盤として広く使われているのは、この「手軽で制御しやすい」特性によるものです。
