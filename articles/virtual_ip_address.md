複数サーバーを運用して可用性を向上させたり、処理負荷の低減するためにパケット転送する技術(機器)が存在します。
そんな時に出てくるIPアドレスに、**VIP(Virtual IP Address)** と呼ばれるものが用いられます。

## VIP（仮想IPアドレス）とは

複数の物理的なサーバーやネットワーク機器が、**一つの仮想的なIPアドレス**を共有して使用する仕組みです。クライアントから見ると「1台のサーバー（または1つの機器）」に見えますが、裏側では複数の実体が存在しています。

## VIPが必要となった背景

なぜそんな仮想的なIPアドレスが必要になったのでしょうか？
主な理由は、以下の3点です。

1. **単一障害点をなくすため**  
   1台のサーバーや機器が故障しても、別の機器が同じIP（VIP）を引き継ぎ、サービスを継続できます。

2. **負荷を分散するため**  
   多数のクライアントからのアクセスを、裏側の複数台のサーバーに振り分けて処理能力をスケールさせます。

3. **クライアント側に変更を意識させずに裏側を変更するため**  
   サーバーの増設・メンテナンス・移行時も、クライアントが見るIP（VIP）は変えずに済みます。実体を隠蔽（抽象化）できるため、運用の柔軟性が高まります。

## 主な用途
冒頭で説明した用途に加えて、仮想IPアドレスがあることでサーバーの入れ替え等、提供している機能(サービス)を停止せずにサーバーを変えたりということが出来るようになります。

### 1. ロードバランシング
複数のサーバー（リアルサーバー）の前にVIPを配置し、クライアントからの接続要求をVIP宛に送ってもらい、ロードバランサーがその負荷を各サーバーに振り分けます。
- 例: Webサイトへのアクセスを、裏側の10台のサーバーに分散させる

### 2. 高可用性（冗長化・フェイルオーバー）
2台の機器（例：ルーターやファイアウォール）を冗長構成にし、片方が故障してもVIPがもう片方の機器に自動的に移動（引き継ぎ）することで、サービスを継続させます。
- 例: プライマリのルーターがダウンしたら、セカンダリのルーターが同じVIPを持つことで通信が途切れないようにする

### 3. サービスの柔軟な移行
サーバーのメンテナンスや移行時に、実際の物理IPを変えずにVIPだけを別のサーバーに付け替えることで、クライアント側に設定変更を意識させずに移行できます。

## イメージ図
こんな運用の時に使われます。

```
[クライアント]
     │
     ▼
[VIP: 192.168.1.100]  ← 仮想IP（表向きの窓口）
     │
   [ロードバランサー または 冗長化機器]
     │
   ┌─┴─┐
   ▼   ▼
[サーバーA] [サーバーB]  ← 実際に処理する実体（リアルサーバー）
```

## 関連技術

VIPを用いる関連技術には以下のようなものがあります。

- **VRRP（Virtual Router Redundancy Protocol）**: ルーターの冗長化でVIPを使う際の代表的なプロトコル
- **ECMP（Equal-Cost Multi-Path）**: VIPを使った負荷分散の手法の一つ
- **DSR（Direct Server Return）**: VIPを使ったロードバランシングの方式の一つ

## VIPを実際に使うフロー

実際にVIPが振り分けられるイメージは以下のようなものです。

1. **クライアントがVIP宛にリクエストを送信**  
   クライアントは、ロードバランサーが持つ仮想IP（VIP）を目的アドレスとして通信を開始します。

2. **ロードバランサーがリクエストを受信**  
   ロードバランサー（またはL4/L7スイッチ）がVIP宛のパケットを受け取ります。

3. **振り分けアルゴリズムでサーバーを選択**  
   事前に設定されたルール（ラウンドロビン、最少接続数、重み付け、IPハッシュなど）に基づき、裏側のリアルサーバー（サーバーA/B/C…）の1台を選びます。

4. **パケットの宛先を書き換えて転送（DNAT）**  
   ロードバランサーは、パケットの宛先IP（VIP）を、選ばれたリアルサーバーの実際のIPに書き換え、サーバーへ転送します。

5. **リアルサーバーが処理を実行**  
   選ばれたサーバーがリクエストを受信し、アプリケーション処理を行います。

6. **レスポンスを返送（通常はVIP経由）**  
   リアルサーバーがレスポンスを返します。  
   - **NAT方式**の場合：ロードバランサーがレスポンスの送信元IPをVIPに書き換えてクライアントへ返します。  
   - **DSR方式**の場合：サーバーが直接クライアントへレスポンスを返します（送信元はVIP）。

7. **クライアントはVIPと通信していると認識**  
   クライアントから見ると、常に「VIPという1つのサーバー」とやり取りしているように見え、裏側で振り分けられていることを意識しません。

## 総括

VIPの本質は、**「物理的な実体（サーバーや機器）から、論理的なサービス宛先を切り離すこと」** です。

つまり、IPアドレスを「特定の機器の所在」ではなく、**「どこにでも移動できる1つの窓口（サービスそのもの）」** として独立させることです。これにより、裏側のサーバーを入れ替えたり、増やしたり、故障時に引き継いだりしても、クライアントが向かう先（VIP）は変わらずに済みます。
