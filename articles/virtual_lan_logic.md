[VLAN](https://yoshishinnze.hatenablog.com/entry/2026/01/27/000000)とは組織の内部のネットワークを部門ごとに分割したいというようなシチュエーションで使われるネットワークを仮想に分割する手法です。
VLANの登場によって物理ケーブルを見に行ってネットワークのリアル分割するみたいな作業が不要になりました。
また拠点が離れてるけど、同じ部門の人に対してNAS経由のファイル共有が出来るようになりました。

## 概要

**VLAN（Virtual LAN）**は、**物理的な配線やスイッチを変えずに、論理的にネットワークを分割する技術**です。

### 1. 本質的な役割

- 同じスイッチや同じ配線に接続していても、**「別のネットワークグループ」** として分離できます。
- 例えば、1台のスイッチにA課とB課のPCを混在して接続していても、VLAN設定で**A課用のネットワーク**と**B課用のネットワーク**に分けることができます。

### 2. なぜ必要か（主なメリット）

- **ブロードキャスト（同報通信）の範囲を小さくする**ネットワーク内の全員に届く不要な通知を減らし、**通信の混雑を防ぎます**。
- **セキュリティの向上**異なるVLAN同士は、原則直接通信できないため、**部門間や用途別にアクセスを分離**できます。
- **物理配線を変えずにネットワーク構成を変更できる**
  オフィスの引っ越しや部署変更があっても、**ケーブルを抜き差しするだけでネットワークの所属を変更**できます。

### 3. 基本的な仕組み

- イーサネットフレームに**「VLAN ID（タグ）」**という識別子を付与します（IEEE 802.1Q）。
- スイッチはこのタグを見て、**「このポートはVLAN 10」「このポートはVLAN 20」** のように振り分けます。
- 異なるVLAN間で通信したい場合は、**ルータやL3スイッチ**が必要になります。

### 4. 具体例

- **ポートベースVLAN**：スイッチの「ポート1〜8はVLAN10（営業部）」「ポート9〜16はVLAN20（開発部）」のように、物理ポート単位で分ける。
- **タグVLAN（トランク）**：スイッチ同士を繋ぐ回線では、複数のVLANのタグを乗せて運び、受信側スイッチがタグに応じて振り分ける。

## 実現手段

**VLANの実現方法**には、**「どの基準でフレームをVLANに分類するか」** によって、主に以下の方法があります。

### VLAN実現法の種類

| 方法                           | 分類基準                                                 | 特徴                                         | 用途                         |
| ------------------------------ | -------------------------------------------------------- | -------------------------------------------- | ---------------------------- |
| **ポートベースVLAN**     | スイッチの**物理ポート**                           | 最も基本的。ポートにVLAN IDを固定割り当て    | フロアごと、部門ごとの分離   |
| **タグVLAN（802.1Q）**   | フレームに付与された**VLANタグ**                   | トランクポートで複数VLANを混在転送           | スイッチ間接続、ルーター接続 |
| **MACベースVLAN**        | フレームの**送信元MACアドレス**                    | どのポートに繋いでも、端末のMACでVLAN決定    | 移動频繁な端末（会議室など） |
| **サブネットベースVLAN** | フレーム内の**IPサブネット**                       | IPアドレスのネットワーク部でVLAN決定         | L3スイッチでの運用           |
| **プロトコルベースVLAN** | 上位プロトコル（IPv4/IPv6/IPXなど）                      | プロトコル種別でVLAN分離                     | レガシー環境                 |
| **ポリシーベースVLAN**   | 複数条件の組み合わせ                                     | MAC＋IP＋ポートなど複合判定                  | 高度なアクセス制御           |
| **VXLAN**                | UDPパケット内の**VNI（VXLAN Network Identifier）** | L3ネットワーク上でL2セグメントをオーバーレイ | データセンター、クラウド     |

### 1. ポートベースVLAN（静的VLAN）

最も一般的な方法です。スイッチの各ポートに **「このポートはVLAN10」** と固定で割り当てます。

```
[PC-A]──[Port1 : VLAN10]
[PC-B]──[Port2 : VLAN10]
[PC-C]──[Port3 : VLAN20]

→ Port1・Port2に届いたフレームはVLAN10として扱う
→ Port3に届いたフレームはVLAN20として扱う
→ VLAN10とVLAN20はL2で分離。相互通信にはL3ルーターが必要
```

- 設定がシンプルで管理が容易
- 端末が別のポートに移動すると、そのポートのVLANに変わる

### 2. タグVLAN（IEEE 802.1Q）

**トランクポート**で使われる方法です。フレームに**4バイトのVLANタグ**を挿入して、複数VLANを1本のリンクで運びます。

```
【タグなしフレーム（アクセスポート）】
| 目的MAC | 送信元MAC | タイプ | ペイロード | FCS |

【タグ付きフレーム（トランクポート）】
| 目的MAC | 送信元MAC | 802.1Qタグ | タイプ | ペイロード | FCS |
                          ↑
                    VLAN ID（12ビット：1～4094）
                    優先度（3ビット：QoS）
```

- **スイッチ間のVLAN混在転送**を実現
- 以前ご説明した**Q-in-Q（802.1ad）**は、このタグを二重化した技術
- **Native VLAN**（タグなしフレーム）は、設定されたVLAN IDとして解釈される

### 3. MACベースVLAN（動的VLAN）

ポートではなく、**端末のMACアドレス**でVLANを決定します。

```
[PC-A: MAC=aa:bb:cc...] ──→ [Port1] → 「このMACはVLAN10」→ VLAN10に振り分け
[PC-A] 移動 ──→ [Port5] → 「このMACはVLAN10」→ やはりVLAN10に振り分け
```

- RADIUSサーバー（IEEE 802.1X認証）と連携して、**認証されたユーザーや端末のMACに応じてVLANを動的に割り当てる**ことも多い
- ポートを意識せずに移動できる

### 4. サブネットベースVLAN

L3スイッチが、フレーム内の**送信元IPアドレスのサブネット**を見てVLANを決定します。

```
[PC: 192.168.10.5/24] ──→ 「192.168.10.0/24はVLAN10」→ VLAN10に振り分け
[PC: 192.168.20.5/24] ──→ 「192.168.20.0/24はVLAN20」→ VLAN20に振り分け
```

- IPとVLANの対応を明確にできる
- L3スイッチでないと実現できない

### 5. VXLAN（Virtual Extensible LAN）

[VXLAN](https://yoshishinnze.hatenablog.com/entry/2026/01/29/000000)で実現する方法です。
本手法はデータセンター・クラウド環境でよく使われる**L2オーバーレイ技術**です。L3ネットワーク（IP）の上に、**UDPパケットでL2フレームをカプセル化**して運びます。

```
【VXLANのカプセル化】
[元のイーサネットフレーム] → [VXLANヘッダ(VNI)] → [UDP] → [IP] → [イーサネット]

VNI（VXLAN Network Identifier）：24ビット（最大約1600万個）
→ VLAN ID（12ビット・4094個）の限界を大きく超える
```

- **VMのライブマイグレーション**（vMotionなど）を跨データセンターで実現
- 以前の**広域イーサネット**や**VPC**の文脈でも、クラウド基盤の内部で使われている

## 総括

> **VLANの本質は、「イーサネットフレームに『所属グループの識別子』を付与し、スイッチがその識別子を見てフレームの転送範囲（ブロードキャストドメイン）を論理的に分離する」ことです。**

### 1. 本質的な構造：「識別子による分離」

VLANは物理的な配線やポートの配置に依存せず、**フレームそのものに「このフレームはどの仮想ネットワークに属するか」という識別子を持たせる**ことで実現します。

```
【物理的な世界】
ポート1〜8 = 1階、ポート9〜16 = 2階 → 物理的な場所で分離

【VLANの世界】
フレームに「VLAN10」のタグが付いていれば営業部、
「VLAN20」のタグが付いていれば開発部 → 論理的な所属で分離
```

この識別子の付与方法・判定方法が、**ポートベース、MACベース、タグ、VXLANなどの「実現手段」の違い**です。

### 2. 識別子の進化：スケールと柔軟性の拡張

VLAN技術の発展は、**「識別子の表現力と運用範囲の拡張」** として理解できます。

| 技術                      | 識別子                        | 識別のタイミング        | スケール            | 適用範囲           |
| ------------------------- | ----------------------------- | ----------------------- | ------------------- | ------------------ |
| **ポートベース**    | ポート番号（設定）            | フレーム受信時          | ポート数依存        | 単一スイッチ内     |
| **802.1Q**          | VLAN ID（12ビット）           | フレーム受信時          | **4,094**     | 同一L2ドメイン内   |
| **802.1ad(Q-in-Q)** | S-TAG + C-TAG（24ビット相当） | フレーム受信時          | 4,094×4,094        | 事業者のL2VPN      |
| **VXLAN**           | VNI（24ビット）               | UDPパケットデカプセル後 | **約1,600万** | L3ネットワーク跨ぎ |

> **進化の本質は、「識別子のビット長を増やし、識別の場所をスイッチポートからL3ネットワーク全体へと拡張した」ことです。**

### 3. 以前の文脈との接続

__トランクポート__

**802.1Qタグという「識別子」をフレームに挿入することで、1本の物理リンク上で複数のVLAN（識別子ごとのグループ）を混在させられる**ようになりました。これがトランクポートの本質です。

__広域イーサネット（Q-in-Q / PBB）__

事業者ネットワークでは、**顧客のVLAN ID（識別子）をそのまま保持しつつ、外側に事業者用の識別子（S-TAG / I-SID）を追加**することで、顧客の論理分離を事業者網内でも維持します。識別子の「入れ子（カプセル化）」が広域イーサネットの本質です。

__VPC・クラウド__

AWS VPCのサブネット分離も、ハイパーバイザー内部では**VLANやVXLAN的な識別子**によるL2分離が行われています。VXLANは「L3上でL2識別子（VNI）を運ぶ」ことで、データセンター跨ぎの論理分離を実現します。

### まとめ

> **VLANの本質は、「イーサネットフレームに『所属グループの識別子』を付与し、スイッチがその識別子を見て転送範囲（ブロードキャストドメイン）を論理的に分離する」技術です。ポートベース、MACベース、802.1Qタグ、VXLANなどは「いつ・どこで・どの識別子を使って分離するか」の違いであり、802.1Qの12ビットVLAN IDからVXLANの24ビットVNIへと識別子の表現力が拡張されることで、単一スイッチ内からL3跨ぎのデータセンター・クラウド基盤まで、論理的なネットワーク分離が実現されてきました。**
