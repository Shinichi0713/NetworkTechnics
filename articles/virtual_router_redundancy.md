組織のネットワークにおいて、LANからインターネットに出るデフォルトゲートウェイが障害が起きると、インターネット関係のすべての通信が不可能となります。

この致命的な状況を回避するために考案された方法が本日記事で説明するVRRPというプロトコルです。
VRRPについて説明していきます。

## VRRPとは

VRRP（Virtual Router Redundancy Protocol / 仮想ルータ冗長性プロトコル）は、**ネットワークのデフォルトゲートウェイ（ルータ）の冗長性を確保するためのプロトコル**です。

### 1. 基本概念

通常、PCやIoTデバイスは「デフォルトゲートウェイ」として1台のルータIPアドレスを設定します。もしそのルータが故障すると、ネットワーク全体が外に出られなくなります。

VRRPは、**複数台のルータを1つの「仮想ルータ」としてまとめ、どれか1台が故障しても自動的に別のルータが引き継ぐ**仕組みです。

### 2. 直感的なアナロジー：病院の受付

通常のネットワークは、**受付係が1人だけの病院**のようなものです。

- 受付係（ルータA）が病気で休むと、患者（パソコン）は誰にも対応してもらえない
- VRRPは、**受付係が2〜3人いて、どの窓口に行っても同じ受付として対応してくれる**体制です
- 受付係Aが休んでも、受付係Bが自動的に引き継ぐ。患者は「受付係が変わった」と気づかない

### 3. VRRPの仕組み

```
【VRRPの構成】

        PC/IoTデバイス
              │
              ▼
    ┌─────────────────────┐
    │   仮想IP: 192.168.1.1  │  ← PCが設定するゲートウェイ（実体はない）
    └─────────────────────┘
              │
      ┌───────┴───────┐
      ▼               ▼
  ┌─────────┐    ┌─────────┐
  │ ルータA │    │ ルータB │
  │ Master  │    │ Backup  │
  │(実IP .2)│    │(実IP .3)│
  └─────────┘    └─────────┘
      │               │
      └───────┬───────┘
              ▼
          インターネット
```

__役割__

| 役割 | 説明 |
|------|------|
| **Master（マスター）** | 仮想IPを実際に担当するルータ。通常時はこれが通信を中継 |
| **Backup（バックアップ）** | Masterを監視しており、故障時に引き継ぐルータ |
| **Virtual IP** | PCが設定するゲートウェイIP。実体のルータには割り当てない |

__動作の流れ__

1. **Masterルータ**が仮想IP（例：192.168.1.1）を使ってパケットを中継
2. **Backupルータ**は定期的にMasterからの「生存通知（アドバタイズメント）」を受信して監視
3. Masterが故障すると、生存通知が止まる
4. **Backupルータの中で優先度が高いものが新しいMasterに昇格**
5. PC側の設定を変更しなくても、ゲートウェイとして引き続き通信できる

### 4. VRRPの重要なパラメータ

| パラメータ | 説明 |
|-----------|------|
| **VRID**（Virtual Router ID） | 仮想ルータの識別番号（1〜255）。同じVRRPグループのルータは同じVRIDを持つ |
| **Priority**（優先度） | Master選出の優先順位（1〜254、大きいほど優先）。255は現在Masterを意味する |
| **Preempt Mode** | Master復旧時に、優先度の高い元Masterが自動的に役割を取り戻すかどうか |
| **Advertisement Interval** | 生存通知の送信間隔（通常1秒） |

### 5. VRRPと似たプロトコルとの比較

| プロトコル | 特徴 | 用途 |
|-----------|------|------|
| **VRRP** | IETF標準（RFC 3768）。ベンダー非依存。オープン | 多くの企業ネットワーク |
| **HSRP** | Cisco独自プロトコル。VRRPの先駆け | Cisco機器中心の環境 |
| **GLBP** | Cisco独自。負荷分散もできる | Cisco環境で負荷分散が必要な場合 |

### 6. IoT・センサネットワークとの関係

センシングやIoTの文脈では、VRRPは以下の場面で重要です。

- **エッジゲートウェイの冗長化**: 工場やスマートビルのセンサーデータ収集ゲートウェイが止まると、データが失われる
- **クラウド接続の可用性確保**: センサーデータをクラウドに送る出口ルータを冗長化
- **監視カメラ・センサーネットワーク**: 常時監視が必要な環境で通信途絶を防ぐ

## 開発背景

VRRPが開発された背景は、主に以下の2つの問題が重なったことです。

### 1. デフォルトゲートウェイの「単一障害点」問題

PCやサーバーは、外のネットワーク（インターネットなど）に出るために「デフォルトゲートウェイ」として1台のルータのIPアドレスを設定します。

しかし、**そのルータが故障すると、ネットワーク内の全端末が外部と通信できなくなります**。これはネットワーク設計における典型的な「単一障害点（Single Point of Failure）」でした。

### 2. Cisco HSRPの「ベンダー依存」問題

この問題に対して、Ciscoは1994年に**HSRP（Hot Standby Router Protocol）** を独自開発し、複数のCiscoルータで冗長化を実現しました。

しかしHSRPは**Cisco独自プロトコル**であり、他社（Nortel、3Com、Juniper等）の機器とは互換性がありませんでした。異なるベンダーの機器を混在させるネットワークでは利用できず、ベンダーロックインの懸念もありました。

### 3. IETFによるオープン標準の策定

そこでIETF（Internet Engineering Task Force）は、**ベンダーに依存しないオープンな「ファーストホップ冗長性プロトコル」** を標準化する動きを1997年に始めました。

- **1997年**: IETFのBOFセッションでVRRPの必要性が議論される [IETF Proceedings](https://www.ietf.org/proceedings/38/97apr-final/xrtftr56.htm)
- **1998年**: RFC 2338として初版が公開
- **2004年**: RFC 3768として改訂版が公開 [RFC 3768](https://www.rfc-editor.org/info/rfc3768/)

Ciscoは当初VRRPに対して特許を主張しましたが、後に撤回し、VRRPはIETF標準として確立されました。 [Cisco IPR History](https://datatracker.ietf.org/ipr/19/history/)

ということでルーティングやVPN製品で有名なCiscoが口火を切って開発した技術でした。

## VRRPの仕組み

VRRPの仕組みを、動作の流れから詳しく説明します。

### 1. VRRPの構成要素

__仮想ルータ（Virtual Router）__

複数の物理ルータが共同で担当する「見せかけのルータ」です。

| 要素 | 説明 |
|------|------|
| **Virtual IP Address** | PCがデフォルトゲートウェイとして設定するIPアドレス |
| **Virtual MAC Address** | 仮想ルータ用のMACアドレス（00-00-5E-00-01-XX形式） |
| **VRID** | 仮想ルータの識別番号（1〜255）。同じグループのルータは同じVRIDを共有 |

__ルータの役割__

| 役割 | 説明 |
|------|------|
| **Master** | 仮想IPを実際に担当し、パケットを中継するルータ |
| **Backup** | Masterを監視し、故障時に引き継ぐ待機ルータ（複数台可） |

### 2. メカニズム：VRRPはどうやって動くか

__Step 1: 初期選出（Masterの決定）__

```
ルータA（Priority: 100）  ルータB（Priority: 200）
        │                        │
        └────────┬───────────────┘
                 ▼
           優先度が高いBがMasterに
```

- VRRPを設定したルータ同士が起動時に優先度（Priority）を比較
- **優先度が最も高いルータがMasterに昇格**
- 優先度が同じ場合、**実IPアドレスが大きい方**がMasterになる

__Step 2: Masterの生存通知（Advertisement）__

Masterルータは、**定期的にVRRPアドバタイズメントパケット**をマルチキャストで送信します。

- **送信先**: 224.0.0.18（VRRPマルチキャストアドレス）
- **間隔**: 通常1秒（設定可能）
- **内容**: 「私はVRID=XのMasterです。生存しています」

```
Masterルータ
    │
    ▼
224.0.0.18  ← マルチキャスト
    │
    ├──→ BackupルータA（監視中）
    └──→ BackupルータB（監視中）
```

__Step 3: 故障検出とフェイルオーバー__

Masterからのアドバタイズメントが一定時間（通常3回分=約3秒）途絶えると、Backupルータは「Masterが故障した」と判断します。

```
【故障前】
Master(A)  ←── Advertisement ──  Backup(B)（監視中）

【故障後】
Master(A)  ×××  Advertisement途絶  ×××  Backup(B)

【フェイルオーバー後】
（故障）      Backup(B)がMasterに昇格
```

- Backupルータの中で**優先度が最も高いもの**が新しいMasterに
- 新Masterは**Gratuitous ARP**を送信し、ネットワーク内のスイッチやPCのARPテーブルを更新
- PC側は設定変更なしで、引き続き仮想IP宛の通信が届く

__Step 4: Master復旧時の動作（Preempt Mode）__

**Preempt Mode ON**の場合:
- 元のMasterが復旧し、優先度が現在のMasterより高ければ、**自動的にMasterに戻る**
- 常に最も優先度の高いルータがMasterになる状態を保つ

**Preempt Mode OFF**の場合:
- 元のMasterが復旧しても、現在のMasterが正常に動作していれば**Backupのまま**
- 不要な切り替えを防ぎ、安定性を重視

### 3. パケットの流れ（正常時と故障時）

__正常時__

```
PC（ゲートウェイ: 192.168.1.1）
    │
    ▼
┌─────────────────┐
│ 仮想IP: 192.168.1.1 │
│ Master: ルータA      │
└─────────────────┘
    │
    ▼
インターネット
```

__故障時（フェイルオーバー後）__

```
PC（ゲートウェイ: 192.168.1.1）← 設定変更なし
    │
    ▼
┌─────────────────┐
│ 仮想IP: 192.168.1.1 │
│ Master: ルータB      │  ← 自動的に引き継ぎ
└─────────────────┘
    │
    ▼
インターネット
```

PCは「192.168.1.1」にパケットを送り続けるだけで、裏でルータが変わっても気づきません。

### 4. VRRPのバージョン

| バージョン | 特徴 |
|-----------|------|
| **VRRPv2** | IPv4対応。認証機能あり（実際はあまり使われない）。RFC 3768で規定 |
| **VRRPv3** | IPv4/IPv6両対応。認証機能を廃止（セキュリティはIPsec等で別途対応）。RFC 5798 |

## 総括

VRRPは、**複数台の物理ルータを1つの「仮想ルータ」としてまとめ、Masterルータが故障したときにBackupルータが自動的にIPアドレスを引き継ぐことで、デフォルトゲートウェイの冗長性を確保するプロトコル**です。

### 要点

- **解決した問題**: デフォルトゲートウェイが1台だと、そのルータが故障するとネットワーク全体が外に出られなくなる「単一障害点」
- **開発の背景**: Ciscoの独自プロトコルHSRPが先行していたがベンダー依存だったため、IETFがベンダー非依存のオープン標準として策定 [RFC 3768](https://www.rfc-editor.org/info/rfc3768/)
- **仕組み**: Masterが定期的に生存通知（Advertisement）を送り、Backupがそれを監視。通知が途絶えると優先度の高いBackupがMasterに昇格
- **PC側の設定変更は不要**: PCは仮想IPをゲートウェイとして設定するだけで、裏でルータが変わっても気づかない
- **重要パラメータ**: VRID（グループ識別子）、Priority（優先度）、Preempt Mode（復旧時の自動切り戻し）、Advertisement Interval（生存通知間隔）

### 一言で

> **VRRPは、ルータの故障に備えて複数台を1つの仮想IPでまとめ、自動的に役割を引き継ぐIETF標準の冗長化プロトコルです。**
