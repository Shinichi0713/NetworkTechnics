コンピュータを扱うと必ずOSに基づいたシステム管理がされています。
逆に計算用のハードウェアがあって、OSが実装されてないとコンピュータとして振る舞いません。

コンピュータをコンピュータたらしめているOSとは何かについて説明していきます。

## OSとは
OS（オペレーティングシステム）は、**コンピュータのハードウェアを管理し、アプリケーションが動くための環境とサービスを提供する基本ソフトウェア**です。

### 直感的な例え：レストラン全体

これまでの「店長＝[カーネル](https://zenn.dev/yoshinn/articles/kernel_system_cp)」に加えて：

- **ハードウェア** = 厨房の設備（コンロ、冷蔵庫）
- **カーネル** = 店長（厨房の管理・資源分配）
- **OS全体** = **店長 ＋ メニュー表 ＋ レジ ＋ 接客マニュアル ＋ 従業員の制服**など、お店が回るために必要なすべて
- **アプリケーション** = 実際に作られる料理（ハンバーグ、サラダなど）
- **ユーザー** = お客様

店長（カーネル）だけではお店は回りません。メニュー表（ファイル操作の仕組み）やレジ（ユーザーインターフェース）も必要です。これらを合わせたものがOSです。


### OSがやっている主な仕事

| 役割 | 説明 |
|------|------|
| **ハードウェア管理** | CPU・メモリ・ディスク・プリンタなどを管理（カーネルの仕事） |
| **アプリケーションの実行環境** | プログラムを起動し、動作させる |
| **ファイル管理** | データをフォルダやファイルとして整理・保存する |
| **ユーザーインターフェース** | 画面やコマンドで人間とコンピュータをつなぐ |
| **セキュリティ** | ユーザー権限やアプリの権限を管理する |

### カーネルとの関係

OSにおいて[カーネル](https://zenn.dev/yoshinn/articles/kernel_system_cp)は非常に大きな役割を果たしています。
[カーネル](https://zenn.dev/yoshinn/articles/kernel_system_cp)とはOSの「心臓部」と言えます。

```
[ ユーザー ]
    ↓
[ アプリケーション（ブラウザ、ゲームなど）]
    ↓
[ OS（カーネル ＋ 周辺ツール・ライブラリ）]
    ↓
[ ハードウェア（CPU・メモリ・ディスク）]
```

OSはカーネルより大きな概念です。カーネルが「内部の管理担当」なら、OSは「ユーザーがコンピュータを使えるようにするための総合的な基盤」です。

### 具体的なOSの例

- **Windows**：PCで最も広く使われる。ゲームや業務ソフトが豊富
- **macOS**：AppleのPC向け。デザインや音楽制作で人気
- **Linux**：サーバーや組み込み機器、ロボットで主流。オープンソース
- **iOS / Android**：スマートフォン向けOS

### 混同しやすいポイント

- **OS ≠ アプリケーション**：WordやChromeは「OSの上で動くソフト」であり、OSそのものではない
- **OS ≠ ハードウェア**：OSはソフトウェア。ただしハードウェアを動かすための最も根本的なソフトウェア

## カーネル以外の機能

カーネルが行うプロセス管理・メモリ管理などの「中核機能」以外に、OSを構成する周辺ツールは大きく分けて以下のようなものがあります。


### 直感的な例え：レストランでいうと

カーネル（店長）は厨房の管理をしますが、それだけではお客様は来ません。

- **シェル（shell）** = 受付係。「何名様ですか？」「どのメニューにしますか？」とお客様からの要望を店長に伝える
- **ファイル操作コマンド** = 冷蔵庫の整理係。「この食材はどこに置く」「この料理のレシピをどこにファイルする」を管理
- **デバイスドライバ** = 専門技術者。新しいコンロや冷蔵庫が来たときに「この機械の使い方を店長に教える」人
- **ウィンドウシステム・GUI** = 店内の装飾とテーブル配置。お客様が座って注文しやすい環境を作る
- **システムライブラリ** = 料理の「下ごしらえ済みの食材」。料理人が毎回玉ねぎを切らなくても、最初からカット野菜を使えるようにする


### 周辺ツールの具体的な分類と例

| 分類 | 具体的なツール・例 | 役割 |
|------|-------------------|------|
| **シェル（命令解釈）** | bash、zsh、PowerShell、cmd.exe | ユーザーが打った文字命令を解読し、カーネルに伝える |
| **ファイル操作コマンド** | cp、mv、rm、ls（Linux）/ copy、del、dir（Windows） | ファイルの作成・移動・削除・検索を行う |
| **テキスト処理ツール** | grep、awk、sed、cat | ファイルの中身を検索・変換・表示する |
| **システム管理ツール** | ps、top、systemctl、taskmgr | 動いているプログラムの確認、サービスの起動停止 |
| **デバイスドライバ** | グラフィックドライバ（NVIDIA）、プリンタドライバ | ハードウェアとカーネルの「通訳」。機器固有の操作を抽象化 |
| **ファイルシステム実装** | ext4、NTFS、APFSの管理プログラム | カーネルの指示を受けて、実際にディスク上にデータを配置する仕組み |
| **ウィンドウシステム・GUI** | X11、Wayland、WindowsのExplorer | 画面の描画、ウィンドウの移動、マウスカーソルの表示 |
| **システムライブラリ** | glibc（Linux）、Win32 API（Windows） | アプリ開発者が「ファイルを開く」「メモリを確保する」などの共通処理を呼び出せる関数群 |
| **ネットワーク設定ツール** | ip、ifconfig、ファイアウォール設定 | IPアドレスの設定、通信の許可・拒否 |
| **ユーザー管理ツール** | passwd、useradd、設定画面 | 「誰がこのPCを使えるか」「管理者権限は誰か」を管理 |


### 重要なポイント：カーネルと周辺ツールの境界

カーネルと周辺ツールの境界はOSによって微妙に異なります。

- **Linux** の場合：カーネル本体は「Linuxカーネル」だけ。上記のシェルやコマンドはGNUプロジェクトのツールなので、厳密には「GNU/Linux」と呼ばれます。
- **Windows** の場合：カーネル（NTカーネル）に加え、Explorer（画面）、cmd.exe、デバイスドライバなどがセットでOSです。
- **macOS** の場合：XNUカーネル + Darwin層 + Aqua（GUI）などがセットです。

### まとめると

周辺ツールは「**カーネルが管理した資源を、人間やアプリケーションが実際に使える形に変換・提供するための支援ソフトウェア群**」です。

カーネルだけでは「CPUとメモリは管理できているが、ユーザーは何も操作できない」状態です。周辺ツールがあって初めて、ファイルをコピーしたり、画面をクリックしたり、プログラムをインストールしたりできるようになります。
