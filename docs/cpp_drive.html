目次

    Google ColabでC++のコードを動作させましたが、これがどんな原理で動作しているかについて説明していきます。

    概要

    Google Colab で C++（cpp）のコードが動作する原理は、「ブラウザ上で直接 C++ を実行しているのではなく、バックエンドの Linux 仮想マシン（VM）上で g++ コンパイラを使ってコンパイル・実行し、その結果をブラウザに表示している」 という仕組みです。

    1. Colab のアーキテクチャの全体像

    [ユーザーのブラウザ]
        ↓ HTTP/WebSocket
[Jupyter Notebook インターフェース（Colabフロントエンド）]
        ↓
[Google Colab バックエンド（Linux VM / コンテナ）]
        ├── g++ コンパイラ
        ├── Python ランタイム
        └── ファイルシステム

    Colab の裏側は Ubuntu ベースの Linux VM が動作しています。Python セル（! や %% マジック）を使うことで、この Linux シェルに直接アクセスできます。

    2. C++ を実行する具体的な仕組み

    Colab では、以下の流れで C++ コードを実行します。

    ステップ 1: ソースコードをファイルに書き出す

    Jupyter Notebook の %%writefile マジックコマンドを使い、VM 上のファイルシステムに .cpp ファイルを作成します。

    %%writefile hello.cpp
#include <iostream>
int main() {
    std::cout << "Hello from C++" << std::endl;
    return 0;
}

    これは Python ではなく、Jupyter のセルマジック で、バックエンドの Linux ファイルシステムに直接ファイルを書き込みます。

    ステップ 2: g++ でコンパイルする

    !（感嘆符）を使うことで、シェルコマンドをバックエンドの Linux VM 上で実行できます。

    !g++ hello.cpp -o hello

    これはバックエンドのシェルで g++ コマンドを直接実行し、実行ファイル hello を生成します。

    ステップ 3: 実行ファイルを実行する

    !./hello

    同様に、バックエンドの Linux VM 上でネイティブバイナリを実行し、その標準出力をブラウザに返します。

    3. なぜこの仕組みで動くのか

    バックエンドが Linux VM である

    Google Colab のセッションごとに割り当てられるバックエンドは、フル機能の Linux 環境です。以下が利用可能です。

    • g++ / gcc: GNU Compiler Collection（C++ コンパイラ）
    • make / cmake: ビルドツール
    • apt: パッケージマネージャ（!apt install ... で追加ライブラリもインストール可能）

    Jupyter の「!」と「%%」マジック

    Jupyter Notebook（Colab の基盤）には以下の機能があります。

    機能 役割
    !コマンド バックエンドのシェルでコマンドを実行
    %%writefile ファイル名 セルの内容をファイルとして書き出す
    %%shell セル全体をシェルスクリプトとして実行

    これらにより、Python ランタイムの「中」からシェル経由で任意の Linux コマンド（g++ コンパイルも含む）を実行できます。

    4. 補足：「C++ セルマジック」も存在する

    より簡潔に書くため、外部ライブラリを使う方法もあります。

    !pip install jupyter-cpp

    %load_ext jupyter_cpp

    %%cpp
#include <iostream>
int main() {
    std::cout << "Hello" << std::endl;
}

    これは裏側で「ファイル書き出し → g++ コンパイル → 実行 → 出力表示」を自動化したラッパーに過ぎず、原理は同じです。

    例題

    Google ColabでC++を実行するメリットを確認する例題を扱います。 N×N 行列の三重ループ乗算の計算をGoogle Colab上でPythonとC++の実行ファイルによる計算を行い、計算速度を比較してみます。

    Python

    Pythonで2次元の行列計算を行います。

    N = 300  # 行列のサイズ（N x N）

    以下が実際に行列計算を行っているPythonコードです。

    import time
import random

# 乱数シード固定で再現性を確保
random.seed(42)

# N x N 行列を生成（値は 0.0 〜 1.0）
def create_matrix(n):
    return [[random.random() for _ in range(n)] for _ in range(n)]

A = create_matrix(N)
B = create_matrix(N)

# 行列乗算（純粋 Python）
def matmul_python(A, B, n):
    C = [[0.0] * n for _ in range(n)]
    for i in range(n):
        for k in range(n):
            a_ik = A[i][k]
            for j in range(n):
                C[i][j] += a_ik * B[k][j]
    return C

print(f"Python: {N} x {N} 行列の乗算を開始します...")
start = time.time()
C_py = matmul_python(A, B, N)
elapsed_py = time.time() - start
print(f"Python 実行時間: {elapsed_py:.3f} 秒")
print(f"結果の一部: C[0][0] = {C_py[0][0]:.6f}")

    実行すると以下でした。

    計算に2.38secかかりました。

    Python: 300 x 300 行列の乗算を開始します...
Python 実行時間: 2.380 秒
結果の一部: C[0][0] = 71.517190

    C++

    続いて同じ計算をC++で計算します。

    # C++ ソースコードをファイルに書き出す
cpp_code = f'''
#include <iostream>
#include <vector>
#include <cstdlib>
#include <ctime>
#include <chrono>

using namespace std;
using namespace std::chrono;

int main() {{
    const int N = {N};
    srand(42);

    // N x N 行列の生成
    vector<vector<double>> A(N, vector<double>(N));
    vector<vector<double>> B(N, vector<double>(N));
    vector<vector<double>> C(N, vector<double>(N, 0.0));

    for (int i = 0; i < N; ++i) {{
        for (int j = 0; j < N; ++j) {{
            A[i][j] = (double)rand() / RAND_MAX;
            B[i][j] = (double)rand() / RAND_MAX;
        }}
    }}

    cout << "C++: " << N << " x " << N << " 行列の乗算を開始します..." << endl;
    auto start = high_resolution_clock::now();

    // 行列乗算
    for (int i = 0; i < N; ++i) {{
        for (int k = 0; k < N; ++k) {{
            double a_ik = A[i][k];
            for (int j = 0; j < N; ++j) {{
                C[i][j] += a_ik * B[k][j];
            }}
        }}
    }}

    auto end = high_resolution_clock::now();
    double elapsed = duration<double>(end - start).count();

    cout << fixed;
    cout.precision(3);
    cout << "C++ 実行時間: " << elapsed << " 秒" << endl;
    cout << "結果の一部: C[0][0] = " << C[0][0] << endl;

    return 0;
}}
'''

with open('matmul.cpp', 'w') as f:
    f.write(cpp_code)
print("C++ ソースを matmul.cpp に書き出しました。")

    その後、このC++コードをコンパイルします。

    # コンパイル（最適化オプション -O2 を付与）
!g++ -O2 -o matmul matmul.cpp
print("コンパイル完了")

    その後、実行ファイルを実行します。

    # 実行
!./matmul

    計算にかかった時間は0.01secでした。 1/230の計算速度だったことになります。

    C++: 300 x 300 行列の乗算を開始します...
C++ 実行時間: 0.010 秒
結果の一部: C[0][0] = 77.978

    なぜ差が出るのか（要点）

    以下のような点が速度差に結びついた理由です。

    • コンパイル vs インタプリタ：C++ は実行前に機械語に変換されるのに対し、Python は実行時に逐次解釈される
    • 動的型付けのコスト：Python の list には型情報のボックス化オーバーヘッドがある
    • メモリレイアウト：C++ の vector はメモリ上に連続配置されるが、Python のリストはポインタの配列
    • ループ処理の効率：C++ の for ループは CPU レジスタ最適化が効きやい

    ポイント：Python で numpy や numba を使えば C++ に近い速度が出ますが、言語自体の純粋な処理能力の差を知ることは、計算量の多い処理をどこで実装すべきか判断する上で重要です。

    総括

    以下のように整理できます。

    C++に処理を寄せるべき場面

    「純粋Pythonのforループが支配的で、かつ実行回数が膨大な処理」 です。

    具体的には

    • 行列・ベクトルの多重ループ演算（numpyで賄えない自作処理）
    • シミュレーション・モンテカルロ法（乱数生成乱数生成＋億回単位の反復）
    • ピクセル単位の画像・信号処理
    • 大規模グラフ探索・動的計画法

    逆に、Pythonで十分な場面

    場面 理由
    pandas/numpyでのデータ処理 内部がC/C++で実装済み
    PyTorch/TensorFlowの学習・推論 内部がCUDA/C++で最適化済み
    Webスクレイピング・API通信 ボトルネックはネットワークI/O
    ファイル入出力中心の処理 ディスクI/Oが支配的

    判断の基準

    C++化を検討すべき条件：
  □ 純粋Pythonのforループがボトルネック
  □ 処理時間が1秒以上かかる
  □ 同じ処理を大量に繰り返す
  □ リアルタイム性が求められる（例：30fps画像処理）

    実務での最適解：「Python＋C++」のハイブリッド

    全部をC++にするのではなく、重い部分だけをC++に寄せるのが現実的です。

    手法 使い方
    subprocess C++実行ファイルをPythonから呼び出す
    Cython Python風構文でC拡張を書く
    pybind11 C++コードをPythonモジュールとして呼び出す
    ctypes コンパイル済み共有ライブラリを呼び出す
