

ALPN（Application-Layer Protocol Negotiation）は、TLS/SSLの暗号化ハンドシェイクの中で、**クライアントとサーバーがどのアプリケーション層プロトコル（HTTP/1.1、HTTP/2、HTTP/3など）を使って通信するかをあらかじめネゴシエーション（事前交渉）するためのTLS拡張プロトコル**です（RFC 7301）。


### なぜ ALPN が必要なのか？

通常、Web通信で暗号化（HTTPS）を行う場合、まず TLS のハンドシェイクを実行して暗号化セッションを確立し、その後に HTTP 通信を開始します。

ここで HTTP/1.1 や HTTP/2 など複数のプロトコルに対応しているサーバーの場合、「TLSが繋がった後に、どのプロトコルでやり取りするか」を決定する必要があります。

もし TLS 確立後に交渉を始めると、その分やり取り（RTT: Round Trip Time）が増えてしまい通信遅延の原因になります。ALPN を使うことで、**TLS の暗号化ネゴシエーションを行うついでにアプリケーションプロトコルも一緒に決めてしまう**ことができ、無駄な往復を削減できます。


### ALPN の動作の仕組み

1. **Client Hello（クライアントからの提案）**
* クライアント（ブラウザなど）が TLS 接続を始める際、「自分が利用できるアプリケーションプロトコルのリスト（例: `h2`, `http/1.1`）」を ALPN 拡張フィールドに入れてサーバーに送信します。


2. **Server Hello（サーバーの選択）**
* サーバーはクライアントから受け取ったリストの中から、自身がサポートしているプロトコルを1つ選択し（例: `h2`）、TLS のレスポンス（Server Hello）に含めて返します。


3. **通信開始**
* TLS ハンドシェイク完了と同時に、決定したプロトコル（HTTP/2など）で即座にアプリケーション通信を開始します。


### 主な利用例と特徴

* **HTTP/2 や HTTP/3 の必須要件**
* Web ブラウザにおける HTTP/2 通信では、TLS 上での ALPN 利用が事実上の必須要件となっています。


* **NPN（Next Protocol Negotiation）の後継**
* もともと Google が SPDY 向けに開発した NPN という規格がありましたが、それを標準化・改良したものが ALPN です（NPN ではサーバーが候補を出し、クライアントが選ぶ方式でしたが、ALPN では標準的な TLS 拡張に合わせてクライアントが候補を出しサーバーが選ぶ方式に変更されました）。

## 用途

ALPN（Application-Layer Protocol Negotiation）は、「1つの通信ポート（主に443番ポート）で複数種類のアプリケーションプロトコルを効率よく使い分けたい場面」で広く活用されています。

主な使用場面は以下の通りです。

* **WebブラウザとWebサーバー間のHTTP/2・HTTP/3通信**
* 最も代表的な利用例です。暗号化通信（HTTPS/443番ポート）の確立と同時に、クライアントとサーバーが「HTTP/1.1」「HTTP/2（`h2`）」「HTTP/3（`h3`）」のどのバージョンで通信するかを即座に決定するために使われます。
* 主要なブラウザ（Chrome、Edge、Safari、Firefoxなど）は、ALPNを利用してHTTP/2以降の通信を有効化します。


* **gRPC（RPCフレームワーク）によるマイクロサービス間通信**
* Googleが開発した高速な通信規格「gRPC」は、トランスポート層の基盤としてHTTP/2を必須としています。
* TLS通信上でgRPCを実行する際、接続相手と正しくHTTP/2でネゴシエーションするためにALPN（プロトコル識別子: `h2`）が使用されます。


* **IoT機器とクラウド間のMQTT（TLS暗号化通信）**
* AWS IoT Coreなどのクラウドプラットフォームでは、Port 443（HTTPSと同じポート）経由でMQTT通信（軽量プロトコル）を受け付ける仕組みを提供しています。
* 企業内の厳しいファイアウォール（443番ポート以外を遮断する環境）を通過させるため、TLS接続時にALPNを用いて「これはMQTT通信である（`x-amzn-mqtt-ca`等）」と提示し、443番ポート上でMQTTプロトコルを識別・ルーティングさせています。


* **リバースプロキシやロードバランサーでのトラフィック振分け**
* Nginx、Envoy、HAProxy、AWS ALB（Application Load Balancer）などのプロキシ/ロードバランサー機器で利用されます。
* クライアントから到達したTLS接続のALPN識別子（`h2` なのか `http/1.1` なのか）を読み取り、後方のバックエンドサーバーへ適切なプロトコルで振り分ける際に活用されます。
