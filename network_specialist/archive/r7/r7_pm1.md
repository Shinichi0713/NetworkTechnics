**giaddr**（Gateway IP Address、または Relay Agent IP Address）とは、DHCP（Dynamic Host Configuration Protocol）のメッセージヘッダ内に存在する、DHCPリレーエージェントのIPアドレスを格納するためのフィールド（およびその中の値）のことです。


## 役割と仕組み

異なるサブネット（ネットワークSegment）間でのIPアドレス自動割り当てを可能にするために使用されます。

* **問題点**
* DHCPクライアントがIPアドレスを要求する際、最初は自身のIPアドレスを持たないため、ネットワーク全体にブロードキャスト（`255.255.255.255`）でリクエストを送信します。
* しかし、ルーターは基本的にブロードキャストパケットを通過させないため、DHCPサーバーが別サブネットにある場合はリクエストが届きません。


* **giaddr による解決**
* ルーターなどの機器（DHCPリレーエージェント）がブロードキャストを受け取ると、**自分のインターフェースのIPアドレス（DHCPリレーエージェントのIP）を `giaddr` フィールドに書き込み**、DHCPサーバーへユニキャストで転送します。
* DHCPサーバーは `giaddr` の値を参照することで、「どのサブネット（ネットワークプール）からIPアドレスを割り当てればよいか」を判断します。



---

## パケットの流れの例

1. **クライアント**：DHCP Discovery パケットをブロードキャスト送信（この時点での `giaddr` は `0.0.0.0`）。
2. **リレーエージェント（ルーター）**：パケットを受け取り、自分の受信側IPアドレス（例: `192.168.10.1`）を `giaddr` にセットして、別サブネットにあるDHCPサーバーにユニキャスト送信。
3. **DHCPサーバー**：`giaddr`（`192.168.10.1`）を見て、`192.168.10.0/24` のネットワークプールから空きIPアドレスを選び、レスポンスを返信。

リンクローカルユニキャストアドレスについて、以下にわかりやすく説明いたします。

---

### 1. リンクローカルユニキャストアドレスとは

リンクローカルアドレスとは、**同一の物理的・論理的なネットワークリンク（セグメント）内**でのみ有効なIPアドレスのことです。ルーターを越えて他のネットワークへ通信することはできません。

代表的な例として、IPv6では `fe80::/10` の範囲、IPv4では `169.254.0.0/16` の範囲がリンクローカルアドレスとして使われます。

特徴は以下の通りです。

- **手動設定なしで自動的に割り当てられる**：IPv6では、NIC（ネットワークインターフェースカード）があれば、DHCPサーバーがなくても自動的にリンクローカルアドレスが生成されます。
- **ルーターは転送しない**：リンクを越えた通信には使えません。
- **近隣探索（Neighbor Discovery）などに利用される**：同一リンク上の機器同士の通信や、アドレスの重複確認などに使われます。

---

### 2. 「ある範囲でネットワークインターフェースを一意に識別できる」とは

この「ある範囲」とは **「同一リンク（同一セグメント）」** のことです。

つまり、**「同じネットワークセグメント内では、リンクローカルアドレスはその中の各ネットワークインターフェースを一意に特定できる」** という意味です。

#### 具体的に言うと

- コンピュータAのNICが `fe80::1` というリンクローカルアドレスを持っているとします。
- 同じスイッチや同じWi-Fiネットワークに接続されているコンピュータBのNICが `fe80::2` を持っているとします。
- このとき、セグメント内では `fe80::1` と `fe80::2` は重複せず、それぞれのNICを一意に識別できます。

#### ただし、注意点があります

リンクローカルアドレスは **「リンクを越えると一意性は保証されない」** という点が重要です。

- コンピュータAの `fe80::1` と、別のセグメントにあるコンピュータCの `fe80::1` は、**同じアドレスでも構いません**。
- なぜなら、ルーターはリンクローカルアドレスを他のセグメントに転送しないため、異なるリンク間でアドレスが重複しても通信上の問題が起きないからです。

---

### 3. まとめ

| 項目 | 内容 |
|------|------|
| **スコープ（有効範囲）** | 同一リンク（同一ネットワークセグメント）内のみ |
| **一意性の保証範囲** | そのリンク内のみ。別リンクでは同じアドレスが存在してもよい |
| **主な用途** | 自動設定、同一リンク内通信、近隣探索など |
| **ルーティング** | 不可（ルーターは転送しない） |

したがって、「ある範囲で一意に識別できる」とは、**「そのアドレスが有効なリンク（セグメント）という範囲内では、同じアドレスを持つNICが2つ以上存在しない」** という意味になります。これにより、同じリンク上の機器同士がお互いを区別して通信できるようになります。

プレフィクス長とは、**IPアドレスのうち「ネットワーク部分」が何ビット分あるかを示す数値**のことです。

通常、スラッシュ記号（`/`）を使って表記します。例えば、`192.168.1.0/24` の「`/24`」の部分がプレフィクス長です。

---

### 1. IPアドレスの構造

IPアドレスは大きく分けて2つの部分で構成されています。

- **ネットワーク部分**：どのネットワークに属しているかを示す部分
- **ホスト部分**：そのネットワーク内のどの機器かを示す部分

プレフィクス長は、この「ネットワーク部分が何ビットか」を示します。

---

### 2. 具体的な例（IPv4の場合）

IPv4アドレスは全部で **32ビット** です。

#### 例：`/24` の場合

```
アドレス：  192.168.1.10
プレフィクス長： /24
```

- 先頭から **24ビット** がネットワーク部分
- 残りの **8ビット**（32 - 24 = 8）がホスト部分

つまり：
- **ネットワークアドレス**：`192.168.1.0`
- **ホストアドレスの範囲**：`192.168.1.1` ～ `192.168.1.254`

#### 例：`/16` の場合

```
アドレス：  172.16.5.3
プレフィクス長： /16
```

- 先頭から **16ビット** がネットワーク部分
- 残りの **16ビット** がホスト部分

---

### 3. サブネットマスクとの関係

プレフィクス長は、サブネットマスクと同じ意味を持ちます。表記方法が異なるだけです。

| プレフィクス長 | サブネットマスク | 説明 |
|---|---|---|
| `/8` | `255.0.0.0` | 大規模ネットワーク向け |
| `/16` | `255.255.0.0` | 中規模ネットワーク向け |
| `/24` | `255.255.255.0` | 小規模ネットワーク（家庭やオフィスなど）で一般的 |
| `/32` | `255.255.255.255` | 1台の機器のみ（ホストルートなど） |

---

### 4. IPv6の場合

IPv6アドレスは **128ビット** ですが、考え方は同じです。

#### 例：`/64` の場合

```
アドレス：  2001:0db8:0001:0002::/64
```

- 先頭から **64ビット** がネットワーク部分
- 残りの **64ビット** がホスト部分（インターフェースID）

IPv6では、通常 **(`/64`)** が1つのネットワーク（サブネット）の標準的な大きさとして広く使われています。

---

### 5. まとめ

| 項目 | 内容 |
|---|---|
| **プレフィクス長とは** | IPアドレスのネットワーク部分のビット数 |
| **表記方法** | `/24` のようにスラッシュに続けて数字で表記 |
| **役割** | ネットワークの大きさ（範囲）を決定する |
| **関連する概念** | サブネットマスク、CIDR（サイダー）表記 |

プレフィクス長が大きいほど（例：`/30`）、ネットワークに所属できる機器の数は少なくなります。逆に小さいほど（例：`/8`）、多くの機器を収容できる広いネットワークになります。
グローバルユニキャストアドレスとは、**インターネット全体で一意に識別され、世界中のどの場所からも到達可能なIPアドレス**のことです。

---

### 1. 基本的な特徴

- **グローバルに一意**：世界中で重複しないアドレスです。
- **ルーティング可能**：インターネット上のルーターによって転送され、他のネットワークとも通信できます。
- **リンクローカルアドレスとは対照的**：リンクローカルアドレスが「同一セグメント内のみ」有効なのに対し、グローバルユニキャストアドレスは「インターネット全体」で有効です。

---

### 2. IPv6におけるグローバルユニキャストアドレス

IPv6では、グローバルユニキャストアドレスは現在 **2000::/3** の範囲（先頭のビットが `001` から `111` まで、実質的には `2000::/3`）が割り当てられています。

#### 構造の例（一般的な `/64` ネットワークの場合）

```
|  グローバル・ルーティング・プレフィクス  |  サブネットID  |  インターフェースID  |
|              48ビット（例：/48）         |    16ビット    |       64ビット       |
```

- **グローバル・ルーティング・プレフィクス**：ISPなどから割り当てられるネットワーク番号
- **サブネットID**：組織内で細かくネットワークを分けるための識別子
- **インターフェースID**：各機器（ネットワークインターフェース）を識別する部分

#### 具体例

```
2001:0db8:1234:5678:9abc:def0:1234:5678/64
```

このようなアドレスは、インターネット上で一意であり、他のホストから通信を受けることができます。

---

### 3. IPv4における対応する概念

IPv4には「グローバルユニキャストアドレス」という正式な用語はありませんが、**グローバルIPアドレス（公衆IPアドレス）**がこれに相当します。

- 例：`203.0.113.10` など
- プライベートIPアドレス（`192.168.x.x` など）やループバックアドレスとは異なり、インターネット上で直接通信できます。

---

### 4. リンクローカル・ユニキャストアドレスとの比較

| 項目 | グローバルユニキャストアドレス | リンクローカルユニキャストアドレス |
|---|---|---|
| **有効範囲** | インターネット全体 | 同一リンク（セグメント）のみ |
| **一意性** | 世界中で一意 | リンク内でのみ一意 |
| **ルーティング** | 可能（ルーターが転送する） | 不可（ルーターが転送しない） |
| **IPv6の例** | `2001:db8::1` | `fe80::1` |
| **割り当て** | ISPや管理者が割り当てる | 自動生成される |

---

### 5. まとめ

グローバルユニキャストアドレスは、**インターネット上で世界中のどの機器とも通信するために使われる、一意なIPアドレス**です。IPv6では `2000::/3` の範囲に属し、組織や家庭のネットワーク機器がインターネットに接続する際に欠かせないアドレスです。

RFC 4862 において、ルータからの情報（RAメッセージなど）をもとに、DHCPサーバーを使わずにホスト自身が自動でIPアドレスを生成・設定する仕組みである SLAAC（Stateless Address Autoconfiguration / ステートレスアドレス自動設定） が規定されています。
