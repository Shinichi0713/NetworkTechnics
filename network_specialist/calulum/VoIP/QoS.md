**QoS（Quality of Service）** とは、一言でいうと **「ネットワーク上の通信に優先順位をつけ、特定のデータが途切れたり遅れたりしないように品質を保証する技術」** のことです。

ネットワークの帯域（道路の幅）は有限です。すべてのデータを平等に扱うと、重要な通信（音声やビデオ会議）が、急ぎではない通信（メールやファイルのダウンロード）に邪魔されて品質が低下してしまいます。
QoSは、いわば **「データの優先順位を決める交通整理」** の役割を果たします。


### 1. なぜQoSが必要なのか？（4つの敵）

特にリアルタイム性が求められるVoIP（IP電話）やWEB会議において、以下の現象を防ぐためにQoSは不可欠です。

* **遅延（Latency）:** パケットが届くのが遅れ、会話にタイムラグが生じる。
* **ゆらぎ（Jitter）:** パケットが届く間隔がバラバラになり、音声がガビガビになる。
* **パケットロス（Packet Loss）:** 混雑でパケットが捨てられ、音が飛ぶ。
* **帯域不足:** 道路が渋滞して、重要なパケットが動けなくなる。


### 2. QoSが交通整理をする「4つのステップ」

ルーターやスイッチの中で、QoSは以下の手順でデータを処理します。

1. **識別（Classification）:** 流れてきたデータが「音声」か「動画」か「メール」かを判別します。
2. **マーキング（Marking）:** 判別したデータに「優先度」というラベルを貼ります。
   * IPヘッダー内の**DSCP**という値や、レイヤ2の**CoS**という値が使われます。
3. **キューイング（Queuing）:** ラベルに従って、データを種類別の「待機列（キュー）」に並べます。
4. **スケジューリング:** 「優先ラベル」がついた列のデータから先に、ネットワークへ送り出します。


### 3. 主なQoSの制御手法

* 優先制御（Priority Queuing）:
  優先度の高いデータを「絶対最優先」で送ります。音声通信によく使われます。
* 帯域制御（Traffic Shaping / Policing）:
  特定の通信（例：YouTube視聴）が帯域を使いすぎないよう、上限を設けて「道路を占領させない」ようにします。


### 4. まとめ：QoSのイメージ

QoSを道路に例えると、以下のような構成になります。

| **ネットワークの要素** | **道路での例え**                     |
| ---------------------------- | ------------------------------------------ |
| **帯域（Bandwidth）**  | 道路の車線数                               |
| **パケット**           | 走行している車                             |
| **QoSなし**            | 一般道（すべての車が混ざって渋滞する）     |
| **QoSあり**            | **バス専用レーンや救急車の優先走行** |


### 結論

QoSは、単に「通信を速くする技術」ではなく、 **「限られたリソースの中で、絶対に止めてはいけない通信を確実に守る技術」** です。



1. 指標としてのQoS（ユーザーが体感する「品質」）
本来の意味でのQoSは、ご指摘の通り**「サービス品質（Quality of Service）」そのもの**を指す評価指標です。 ネットワークが期待通りの性能を出しているかを、以下の数値で測定します。

スループット: 単位時間あたりにどれだけデータを送れたか（実行速度）。

遅延（レイテンシ）: パケットが届くまでの時間。

ゆらぎ（ジッタ）: 到着時間のバラつき。

パケット損失率: 送ったパケットがどれだけ消えたか。

この場合のQoS: 「このネットワークは**QoS（通信品質）**が高い/低い」といった、結果としての評価を指します。

2. 技術としてのQoS（品質を制御する「仕組み」）
一方で、エンジニアやITの現場で「QoSを入れる」「QoSを設定する」と言うときは、**「品質を一定に保つための制御技術」**のことを指します。

もし、ネットワークが常に空いていれば、特別な技術は不要です。しかし、混雑時に特定の通信（音声など）の品質（指標としてのQoS）が落ちないように、**優先制御や帯域制限といった「技術」**を使って、人為的に品質をコントロールします。

## TOS

TOSフィールド（Type of Serviceフィールド）は、**IPパケットのヘッダ内にある8ビットのフィールド**で、そのパケットに対する**サービスの種類や優先度**を指定するために使われます。

### 1. 基本的な役割

- ルータやスイッチが、**どのパケットを優先的に扱うか**（QoS：Quality of Service）を判断するための**ヒント**として利用されます。
- 例：
  - 音声・ビデオ通話のパケット：遅延が少ない方がよい → 高優先度
  - バックアップやファイル転送：多少遅れてもよい → 低優先度

### 2. フィールドの構成（IPv4）

IPv4ヘッダのTOSフィールドは、歴史的にいくつかの解釈がありますが、現在は主に以下のように使われます。

- **DSCP（Differentiated Services CodePoint）**：上位6ビット  
  - パケットの「クラス」や「優先度」を表すコード。
  - 例：EF（Expedited Forwarding）、AF（Assured Forwarding）など。

- **ECN（Explicit Congestion Notification）**：下位2ビット  
  - ネットワークの輻輳（混雑）を通知するためのビット。


### 3. 実務での使われ方

- 音声・ビデオ通話（VoIP、Web会議）など、**リアルタイム性が重要なトラフィック**には、高優先度のDSCP値を設定します。
- ルータやL3スイッチは、このTOSフィールド（特にDSCP部分）を見て、**優先キューイングや帯域制御**を行います。
- 最近では、**DiffServ（Differentiated Services）アーキテクチャ**の一部として、TOSフィールドをDSCPとして利用するのが一般的です。


### 4. IPv6での対応

- IPv6では、TOSフィールドに相当するものとして**Traffic Classフィールド**があります。
- 役割はIPv4のTOSと同様で、**パケットの優先度やQoSクラス**を指定するために使われます。


### まとめ

TOSフィールドは、**IPパケットに「優先度」や「サービスクラス」を付与するためのフィールド**であり、ルータなどがQoS（品質保証）を行う際の判断材料として利用されます。  
現在は、その上位6ビットを**DSCP**として扱い、下位2ビットを**ECN**として扱うのが一般的です。
