## 1. 彼らが作っているアプリの種類

Xで発信している個人開発者が作っているものは、大きく以下のカテゴリに分かれます。

### ① 小さなWebツール・ユーティリティ
日常の「ちょっとした不便」を解消するブラウザ完結型のツールが非常に多いです。

| 例 | 説明 |
|---|---|
| **AIトークン可視化ツール** | ChatGPT系AIが文章をどう区切って読んでいるかを色分けで表示 |
| **Markdown→HTML変換** | リアルタイム変換＋プレビュー並べて確認 |
| **マインドマップメモ** | 考えを枝分かれさせてサッと整理 |
| **X投稿タイムヒートマップ** | 自分のベスト投稿時間を可視化 |
| **住所正規化ツール** | 日本の住所の表記ゆれを一括整備 |
| **AI週報ライター** | 作業メモを貼るだけで週報が自動生成 |

これらは「大手SaaSを入れるほどではない、でも手作業だと地味につらい」という**隙間ニーズ**を狙ったものです。<source-chip title="urara.dev" url="https://urara.dev/" /><source-chip title="Sukima Labs" url="https://zenn.dev/sukima_labs/articles/59319396bbe74c" />

### ② Micro SaaS（小規模なサブスクサービス）
月額数百〜数千円で販売する、ニッチな業務効率化ツールです。

- Threads投稿分析アプリ
- 価格比較・JANコード検索プラグイン
- AI翻訳（i18n JSONの多言語化）
- 業務自動化ツール（GAS/Claude API連携）
- 採用管理SaaSの受託から派生した自社プロダクト

<source-chip title="EneoWorks" url="https://eneoworks.com/" /><source-chip title="Leia.dev" url="https://portfolio-site-sooty-zeta.vercel.app/" />

### ③ モバイルアプリ（iOS/Android）
個人でもリリースできる規模の実用アプリです。

- **価格比較アプリ**（容量・数量の異なる商品の単価比較＋ポイント計算）
- **音声案内付きインターバルタイマー**（トレーニング用）
- **イベント幹事支援アプリ**（日程・参加者・会費管理）
- **スコア管理アプリ**（野球・ソフトボールの試合記録）

<source-chip title="GTANSU LAB" url="https://gtansu.com/" /><source-chip title="週末のアプリ作成" url="https://www.tfsappsone.com/entry/2025/01/23/212249" />

### ④ ゲーム
ブラウザゲームやモバイルゲームの個人開発も活発です。

- 物理演算パズルゲーム
- TPSガンシューティング
- 麻雀牌を使ったパズルゲーム
- 短歌創作支援ゲーム

<source-chip title="Nicoyou Games" url="https://nicoyou.jp/" /><source-chip title="HONGSOFT" url="https://www.hongsoft.jp/" />

### ⑤ Chrome拡張機能・業務自動化ツール

## 2. 委託されたものと見分ける方法

### 結論：Xで発信しているものの多くは「委託ではなく自社開発」

個人開発と受託開発は本質的に異なります。

| 項目 | 個人開発（自社プロダクト） | 受託開発 |
|------|------------------------|---------|
| **企画者** | 自分 | クライアント |
| **要件定義** | 自分で決める | クライアントから指定される |
| **所有権** | 自分 | クライアント |
| **収益モデル** | 広告・サブスク・買い切りなど | 開発費として受取 |
| **Xでの発信** | 「Build in Public」で開発過程を公開 | 守秘義務のため公開できないことが多い |

<source-chip title="フリコン" url="https://freelance-concierge.jp/articles/detail/341/" />

### 委託かどうかの見分け方

Xの発信から判断するポイントは以下の通りです：

| 個人プロダクトの特徴 | 委託案件の特徴 |
|---|---|
| 「自分が困ったので作りました」と語っている | 「○○社の○○案件で〜」と具体的な依頼主がいる |
| 開発過程を**Build in Public**で公開している | 守秘義務やNDAのため詳細が語れない |
| 収益やDL数を公開している | クライアントの成果指標を公開することは少ない |
| 自分で価格設定・マーケティングしている | 納品後の運用はクライアント任せ |
| 複数の小さなプロダクトを並行して持っている | 単発・期間限定の案件が多い |

### ただし「副業＝委託ではない」わけでもない

個人開発者の中には、以下のような**ハイブリッド型**もいます：

1. **本業は受託開発・フリーランス**、副業で自社プロダクトを育てる
2. **受託から派生した自社プロダクト**（クライアントの課題を見て、汎用化したツールを自分でも販売）
3. **委託しながら自分のプロダクトも並行**で開発

例えば、THINK DESIGNという個人開発者は「自社開発」と「受託・委託」の両方を明記しています。<source-chip title="THINK DESIGN" url="https://thinkdsgn.com/" />

## 3. なぜXで「個人開発＝副業」が多く見えるのか

X（旧Twitter）では**「Build in Public」**という文化が定着しており、個人開発者が意図的に開発過程を公開することで：
- ユーザー獲得（マーケティング）
- フィードバック収集
- 技術的な信頼性の構築
- 同じ志を持つ開発者との交流

を行っています。つまり、**Xで見えているのは「見せたい側面」**であり、委託案件はそもそも公開できないため、目に入る個人プロダクトの割合が高くなります。<source-chip title="Qiita" url="https://qiita.com/DevMasatoman/items/f5e297f5153995219e79" />
