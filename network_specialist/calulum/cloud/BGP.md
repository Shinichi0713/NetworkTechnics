BGP（Border Gateway Protocol）は、一言で言えば **「インターネット上のルート（道筋）を決めるための仕組み」** です。

インターネットは、一つの巨大なネットワークではなく、大学、企業、プロバイダー（ISP）などが管理する無数の小さなネットワークの集合体です。この個々のネットワークを **AS（Autonomous System：自律システム）** と呼びます。

BGPは、このAS同士が「自分のところを通れば、この目的地へ行けるよ」という情報を交換し合うためのプロトコルです。


### BGPの主な役割と特徴

BGPを理解する上で重要なポイントは以下の3つです。

#### 1. AS間の経路制御（外側との通信）

家庭内や会社内のネットワークで使われるプロトコル（OSPFなど）が「ビル内の案内図」だとすれば、BGPは「世界中の都市をつなぐ高速道路の地図」のようなものです。

#### 2. パスベクタ方式

BGPは、目的地までの「距離」ではなく、**「どのASを経由するか」というリスト（パス）**を見てルートを判断します。これにより、ループ（同じところをぐるぐる回ること）を防ぎ、最適な道を選びます。

#### 3. 柔軟なポリシー設定

BGPの最大の特徴は、単に「最短距離」を選ぶだけでなく、**「大人の事情（運用ポリシー）」**でルートを決められることです。

* 「A社を通ると通信料が高いから、B社を優先しよう」
* 「セキュリティ上の理由で、特定の国を経由させない」
といった細かなコントロールが可能です。


### なぜBGPが重要なのか？

もしBGPが止まってしまうと、自分のネットワークから外の世界（GoogleやSNSなど）へどうやって行けばいいのかが分からなくなり、**インターネット全体が不通**になってしまいます。

過去に大規模なSNSやサービスが世界中で閲覧不能になった原因の多くは、このBGPの設定ミスによる「経路情報の消失」によるものです。

### BGPの2つの種類

| 種類 | 名称 | 役割 |
| --- | --- | --- |
| **eBGP** | External BGP | **異なるAS間**で経路情報をやり取りする（例：ソフトバンクとKDDIの間） |
| **iBGP** | Internal BGP | **同じAS内**のルーター同士で、外から得た経路情報を共有する |



**BGP（Border Gateway Protocol）** とは、**インターネット上の「自律システム（AS: Autonomous System）」同士を繋ぎ、「どのIPアドレスブロックがどの組織（AS）を経由して到達可能か」を交換・決定する外部ゲートウェイプロトコル（EGP）**です。

インターネットは**「ASの集合体」**であり、BGPはその**「外交プロトコル」**です。

## 1. 本質：「組織間の経路交換プロトコル」

まず、BGPが動く世界を理解することが重要です。

```
【インターネットの構造：ASの集合】
     ┌──────────┐
     │ AS 64500 │  ← 企業Aのネットワーク
     │ 192.0.2.0/24 │
     └────┬─────┘
          │  eBGPピアリング
     ┌────┴─────┐
     │ AS 64496 │  ← ISP-A
     │ 198.51.100.0/24 │
     └────┬─────┘
          │  eBGPピアリング
     ┌────┴─────┐
     │ AS 64501 │  ← ISP-B（トランジット）
     │ 203.0.113.0/24 │
     └────┬─────┘
          │  eBGPピアリング
     ┌────┴─────┐
     │ AS 64502 │  ← 企業Bのネットワーク
     └──────────┘

BGPが交換するのは「192.0.2.0/24はAS64500→AS64496→AS64501を経由して到達可能」という情報
```

- **自律システム（AS）**：1つの組織（ISP、企業、大学など）が管理するネットワークの集合。AS番号（ASN）で識別（例：AS 64496）
- **BGPの役割**：「自分の持っているIPプレフィックス（経路）を隣のASに教え」「隣のASから経路を学ぶ」ことで、インターネット全体の経路図を構築する

> **本質は、「組織の境界（Border）で、組織間の経路情報を外交的に交換するプロトコル」です。**

---

## 2. なぜOSPFやRIPではなくBGPが必要か

以前ご説明したOSPFは**IGP（内部ゲートウェイプロトコル）**です。ASの内部で使われます。インターネット規模ではIGPでは到底対応できません。

| 項目 | IGP（OSPFなど） | EGP（BGP） |
|------|----------------|-----------|
| **設計対象** | AS内部（数百〜数千ルーター） | AS間（全世界のAS：10万超の接続） |
| **経路数** | 数千〜数万 prefix | 90万 prefix超（2024年時点） |
| **最適化の基準** | 「最短（メトリック/コスト）」 | 「ポリシー・契約・経由AS数」 |
| **信頼前提** | 同一組織内のルーター同士（信頼） | 異なる組織同士（非信頼・外交的関係） |
| **セキュリティ** | 比較的単純な認証 | MD5/TTL-Security・RPKI・ROVなど複雑 |
| **ルーティング変更の速度** | 速い（秒単位） | 遅い（分単位。意図的にゆっくり） |

### なぜ「最短」ではなく「ポリシー」なのか

インターネットでは、**「最短経路＝最適経路」ではありません。**

```
【例：企業がISPを選ぶ場合】
企業Aのサーバー → ISP-A → ISP-B（契約なし） → ISP-C → ユーザー
              → ISP-A → ISP-D（長期契約・安価） → ISP-C → ユーザー

「最短」なら前者だが、「契約関係・料金・信頼性」から後者を選ぶ
```

BGPは**「どの経路を広報するか」「どの経路を受け入れるか」を、組織のポリシーで細かく制御**できるのが最大の特徴です。

## 3. BGPの仕組み：ピアリングと経路広報

### BGPピア（隣接ルーター）の確立

BGPは**TCPポート179**で接続を確立します（OSPFやEIGRPが独自のL3プロトコル（IP直接載せ）なのとは異なります）。

```
[ルーターA] ──TCP 179──→ [ルーターB]
   ↑                         ↑
「BGPオープンメッセージ」でASN・オプションを交換
「キープアライブ」で維持
```

### eBGPとiBGP

| 種別 | 接続先 | 用途 |
|------|--------|------|
| **eBGP**（external BGP） | **別のAS**のルーター | AS間の経路交換 |
| **iBGP**（internal BGP） | **同じAS内**のルーター | AS内でeBGPで学習した経路を共有 |

```
【eBGPとiBGPの関係】
              ┌─────────────┐
              │   AS 64496   │
              │  [R1]──[R2] │  ← iBGPでR1がeBGPで学習した経路をR2に共有
              │   │     │   │
              └───┼─────┼───┘
                  │ eBGP  │ eBGP
              ┌───┘       └───┐
           [ISP-A]         [ISP-B]
           AS 64500         AS 64501
```

> **eBGPで「外の世界から経路を学び」、iBGPで「AS内の全ルーターにその経路を教える」**のが基本構造です。

---

## 4. BGPの経路選択：「最適経路」の決め方

BGPは1つの宛先（プレフィックス）に対し、複数の経路候補を受け取ることがあります。以下の順序で「最適経路」を選びます（Ciscoの例、簡略化）。

| 順序 | 属性 | 意味 |
|------|------|------|
| 1 | **Weight**（Cisco独自） | ローカル優先度。大きいほど優先 |
| 2 | **Local Preference** | AS内での出口優先度。大きいほど優先 |
| 3 | **経由AS数（AS Path長）** | 短いほど優先（ただしポリシーで変更可） |
| 4 | **Origin** | 経路の発生元（IGP＜EGP＜Incomplete） |
| 5 | **MED（Multi-Exit Discriminator）** | 同じ隣接ASから複数入口がある場合のヒント |
| 6 | **eBGP > iBGP** | eBGP経由の経路をiBGPより優先 |
| 7 | **IGPコスト** | 次のホップまでの内部コスト |
| 8 | など | ルーターIDなど |

> **重要：BGPは「最短」だけでなく、組織の意図（Weight, Local Preference）を最大限に反映できる。**

---

## 5. BGPの経路属性（Path Attributes）

BGPが交換するのは「IPプレフィックス」だけでなく、**豊富な属性情報**です。

| 属性 | 役割 |
|------|------|
| **AS_Path** | この経路がどのASを経由してきたかの履歴。ループ防止にも使用 |
| **Next_Hop** | 次のホップのIPアドレス |
| **Origin** | 経路の発生元タイプ（IGP, EGP, Incomplete） |
| **Local_Pref** | AS内での優先度（iBGPで共有） |
| **Community** | 経路に「タグ」を付けてポリシー制御（例：「この経路は海外に広報しない」） |
| **MED** | 隣接ASに対する「この入口を使ってほしい」というヒント |

**Communityの例：**

```
ISPが企業に対して：
「この経路には Community 64496:100 を付けると国内のみ広報、
  64496:200 を付けると海外にも広報」
```

## 6. 以前の文脈との接続

### OSPFとの関係

以前「OSPFがインターネットに接続する際に必要なこと」として**BGP**を挙げました。

```
【企業ネットワーク】
内部：OSPFで「社内の地図」を作る
境界：BGPで「インターネットとの外交」を行う

[内部ルーター]──OSPF──[エッジルーター]──BGP──[ISP]
   ↑                       ↑
「10.0.0.0/24は          「203.0.113.0/24は
  この方向」               AS64496に所属」
```

### VPC・クラウドとの関係

AWSやAzureでは、**Direct Connect / ExpressRoute**を使ってオンプレミスとVPCを接続する際に、**BGPピアリング**が標準的に使われます。

- 企業側のエッジルーターと、クラウドプロバイダーのルーターが**eBGPでピアリング**
- VPC内のIPプレフィックスをBGPで企業側に広報
- 企業側のオンプレミスプレフィックスをBGPでクラウド側に広報

### 広域イーサネット・IP-VPNとの関係

MPLS L3 VPNでは、**PE（Provider Edge）ルーターとCE（Customer Edge）ルーター間でBGPピアリング**を行うことが一般的です。事業者のVPNv4/VPNv6経路と、顧客のIPv4/IPv6経路をBGPで交換します。

---

## まとめ

> **BGP（Border Gateway Protocol）は、インターネットを構成する自律システム（AS）間で「どのIPアドレスブロックがどのASを経由して到達可能か」を交換する外部ゲートウェイプロトコル（EGP）です。TCPポート179で動作し、eBGP（AS間）とiBGP（AS内）の2つのモードを持ちます。OSPFなどのIGPが「内部の最短経路」を求めるのに対し、BGPは「組織間のポリシー・契約関係・経由AS数」などを考慮して経路を選択するため、インターネットのスケールと多様な組織関係に対応できます。経路属性（AS_Path, Local_Pref, Communityなど）による豊富なポリシー制御が最大の特徴であり、クラウド接続（Direct Connect）やMPLS VPNでも広く使われています。**
