**VRRP（Virtual Router Redundancy Protocol）は、基本的に L3（ネットワーク層）の冗長化プロトコルです。**

ただし、L2（データリンク層）の仕組みとも密接に連携しています。以下に詳しく説明いたします。

---

## 結論：L3 が正解

VRRP は **「デフォルトゲートウェイの IP アドレスを冗長化する」** ために設計されたプロトコルです。

- 複数台のルーターで **1つの仮想 IP アドレス**（例：`192.168.1.1`）を共有する
- マスタールーターがダウンすると、バックアップルーターが同じ IP アドレスを引き継ぐ
- エンドユーザーの PC から見ると、ゲートウェイ IP は常に同じ

このように、**IP アドレスという L3 の論理アドレスの冗長化** を行うため、VRRP は L3 のプロトコルに分類されます。

---

## では L2 の側面は？

VRRP は L3 の IP アドレスを冗長化する際に、**L2 の MAC アドレスも仮想化** します。

| 項目 | 内容 |
|------|------|
| **仮想 MAC アドレス** | `00-00-5E-00-01-{VRID}`（IPv4 の場合） |
| **ARP** | マスターが仮想 IP に対する ARP 応答を行い、仮想 MAC を通知する |
| **VRRP パケット** | IP プロトコル番号 `112`、マルチキャスト `224.0.0.18` を使用 |

つまり、**IP（L3）の冗長化を実現するために、MAC（L2）も合わせて偽装・共有する** のが VRRP の動作です。

> **イメージ**：「この IP の担当者はこの MAC だよ」と ARP で告げて、実際にパケットが届く MAC もマスターが引き受ける。マスターが変わっても「仮想 MAC は同じ」なので、エンドユーザーの PC は気づかない。

---

## L2 スイッチの冗長化とは別物

混同しやすいのですが、**L2 の冗長化**（スイッチの冗長化）は別の仕組みです。

| 冗長化の種類 | プロトコル・技術 | 層 |
|-----------|---------------|-----|
| **ゲートウェイ（IP）の冗長化** | **VRRP**、HSRP、CARP | **L3** |
| **スイッチ・リンクの冗長化** | STP（Spanning Tree）、LACP | **L2** |

- VRRP：ルーター/レイヤー3スイッチの **IP インターフェース** を冗長化
- STP/LACP：スイッチ間の **物理的なリンクやループ** を冗長化

---

## まとめ

| 質問 | 答え |
|------|------|
| VRRP は L2？ | **基本的には No**。IP アドレスの冗長化は L3 の仕事 |
| VRRP は L3？ | **Yes**。デフォルトゲートウェイの IP を冗長化する L3 プロトコル |
| L2 と関係ない？ | **関係ある**。仮想 MAC アドレスや ARP を使って L2 とも連携する |

**「L3 の IP 冗長化を目的としつつ、L2 の MAC 仮想化を手段として使うプロトコル」** というのが、VRRP の正確な位置づけです。
