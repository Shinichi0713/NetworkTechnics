
ASと呼ばれるルータのグループで構成されたネットワークの内部をトポロジーを構築して自律的にネットワーク情報を交換するプロトコルがあります。
その中でも安定感抜群なものがOSPFです。

## 概要

**OSPF（Open Shortest Path First）** とは、**1つの組織（自律システム：AS）の内部で、「ネットワークの地図（トポロジー）」を全ルーターで共有し、それぞれがDijkstra最短経路アルゴリズムを使って最適な経路を自律的に計算するリンクステート型の内部ゲートウェイプロトコル（IGP）** です。

### 1. 本質：「地図を配って、各自が最短経路を計算する」

OSPFの最大の特徴は、**「距離ベクトル型（RIPなど）ではなく、リンクステート型である」** 点にあります。

__距離ベクトル型（RIPなど）との違い__

| 項目 | 距離ベクトル型（RIP） | リンクステート型（OSPF） |
|------|---------------------|------------------------|
| **交換する情報** | 「私はこのネットワークまで○ホップで行けます」 | 「私はこういうインターフェースを持ち、こういう隣接ルーターと繋がっています」 |
| **持っている情報** | 隣接ルーターから聞いた「2番目の情報」 | 自分で集めた「1番目の生のトポロジー（地図）」 |
| **経路計算** | 隣から聞いた情報を足し算していく | 地図全体から最短経路を計算（Dijkstra法） |
| **収束速度** | 遅い（ホップ数の伝搬に時間がかかる） | 速い（トポロジー変更を即座にflood） |
| **ループのリスク** | ある（カウントトゥインフィニティ問題） | ほぼない（地図ベースなので一貫性がある） |

```
【RIPの考え方】
[ルーターA] 「10.0.0.0/24は私の左に1ホップです」
    ↓
[ルーターB] 「10.0.0.0/24は私の左に2ホップです」
    ↓
[ルーターC] 「10.0.0.0/24は私の左に3ホップです」
    ↑ 情報が「伝言ゲーム」的に伝わる

【OSPFの考え方】
[全ルーターが持つリンクステートデータベース（LSDB）]
「ルーターAはeth0で10.0.1.0/30に接続、コスト1」
「ルーターBはeth0で10.0.1.0/30に接続、eth1で10.0.2.0/30に接続」
「ルーターCはeth0で10.0.2.0/30に接続」
    ↑
全ルーターが「同じ地図」を持つ。
各自がDijkstra法で「自分から見た最短経路」を計算する
```

> **本質は、「全ルーターがネットワーク全体の地図（トポロジーデータベース）を同一に保ち、各自が最短経路を計算する」ことです。**

### 2. OSPFの動作：5つのステップ

__① Helloパケットによる隣接発見__

OSPFルーターは、OSPFが有効なインターフェースから**10秒間隔（デフォルト、ブロードキャスト環境）** でHelloパケットをマルチキャスト（224.0.0.5）します。

| Helloで確認すること | 内容 |
|-------------------|------|
| **隣接ルーターの存在** | 同じネットワーク上にOSPF有効なルーターがいるか |
| **パラメータの一致** | エリアID、認証、Hello/Dead間隔、サブネットマスクなど |
| **DR/BDRの選出** | ブロードキャスト・NBMA環境での代表ルーター選出 |

__② 隣接関係（Adjacency）の確立__

Helloで一致が確認できたら、**DBD（Database Description）** パケットで「自分が持っている地図の目録」を交換し、**LSR/LSU（Link-State Request/Update）** で不足している地図情報をやり取りします。

```
[ルーターA] ←──DBD: 「私はこういうLSAを持っています」──→ [ルーターB]
[ルーターA] ←──LSR: 「そのLSAの詳細をください」────────→ [ルーターB]
[ルーターA] ←──LSU: 「詳細なLSAデータです」────────────→ [ルーターB]
[ルーターA] ←──LSAck: 「受信確認です」────────────────→ [ルーターB]
```

__③ リンクステートデータベース（LSDB）の同期__

全ルーターが**同一のLSDB**を持つようになります。LSDBは**LSA（Link-State Advertisement）** というレコードの集合です。

| LSAタイプ | 内容 |
|----------|------|
| **Type 1: Router LSA** | 各ルーターが自らのリンク状態を広報（全ルーターが生成） |
| **Type 2: Network LSA** | DRがブロードキャストセグメントの状態を広報 |
| **Type 3: Summary LSA (IP network)** | ABRが他エリアのネットワーク経路を広報 |
| **Type 4: Summary LSA (ASBR)** | ABRがASBRの位置情報を広報 |
| **Type 5: External LSA** | ASBRが外部（BGP側など）の経路を広報 |
| **Type 7: NSSA External LSA** | NSSAのASBRが外部経路を広報（ABRがType5に変換） |

__④ SPF計算（Dijkstraアルゴリズム）__

各ルーターが、LSDBを元に **「自分を根とする最短経路木」** を計算します。

```
【LSDBから計算するイメージ】
LSDB: A─(cost1)─B─(cost2)─C─(cost1)─D
       └(cost3)─E────────────(cost5)─┘

ルーターAから見た最短経路木:
A → B (cost1)
A → B → C (cost3)
A → B → C → D (cost4)
A → E (cost3)  ← A→B→C→D→E(cost1+2+1+5=9)より短い
```

__⑤ ルーティングテーブルへの反映__

SPF計算結果を、OSPFの経路として**ルーティングテーブルに登録**します。管理距離（Administrative Distance）は**110**です。

### 3. エリア（Area）：大規模ネットワークへの対応

OSPFは**階層的なエリア設計**を持ち、大規模ネットワークを分割管理できます。

```
【OSPFのエリア構造】
              ┌─────────────┐
              │  Area 0     │  ← バックボーン（必須）
              │ (Backbone)  │
              │  [ABR]──[ABR] │
              └──┬─────┬────┘
                 │     │
            ┌────┘     └────┐
         [ABR]             [ABR]
            │                │
        Area 10          Area 20
      (営業部門)        (開発部門)
```

| 用語 | 役割 |
|------|------|
| **Area** | LSAのフラood範囲を限定する論理的な分割単位 |
| **Backbone Area (Area 0)** | 全エリアが接続する中核エリア |
| **ABR (Area Border Router)** | エリアとバックボーンを繋ぐ境界ルーター。Type3 LSAでエリア間経路を要約・広報 |
| **Internal Router** | 1つのエリア内にのみ所属するルーター |
| **ASBR (AS Boundary Router)** | OSPFドメインと外部（BGPなど）を繋ぐ境界ルーター |

**エリア分割のメリット：**
- **LSDBサイズの削減**：エリア内ルーターは自エリアのLSAだけを保持すればよい
- **SPF計算の軽減**：他エリアの変化がType3 LSAとして要約されるため、全網でSPF再計算が走らない
- **トラフィックの局所化**：エリア内のフラoodが他エリアに漏れにくい

>__Backbone Area__
>**バックボーンエリア（Backbone Area / Area 0）** は、OSPFにおいて **「全てのエリアが必ず接続する中核となるエリア」** です。
>__なぜ必要か__
>OSPFはエリアに分割することで、各エリア内のルーターが持つ**リンクステートデータベース（LSDB）のサイズ**と**SPF計算の負荷**を抑えます。しかし、エリア同士が直接経路を交換すると、**エリア間のループ**が発生する危険があります。
>そこで、**エリア間の経路交換は必ずArea 0を経由させる**というルールを設けました。
>```
>【構造】
>   Area 10 ──→ [ABR] ──→ Area 0 ←── [ABR] ←── Area 20
>(営業)       (境界)    (中核)    (境界)       (開発)
>→ エリア間通信は「Area 10 → Area 0 → Area 20」と必ず中継
>→ エリア間のループが構造的に起きにくい
>```
>__役割の本質__
>| 役割 | 内容 |
>|------|------|
>| **ハブ** | 全エリア間経路交換の集約点 |
>| **隠蔽** | 各エリアの詳細なトポロジー（Type1/2 LSA）はArea 0には届かない。ABRが**Type3 LSA（サマリー経路）** に変換して広報 |
>| **ループ防止** | エリア間ルーティングを「星型（Hub-and-Spoke）」に限定し、一貫性を保つ |
>
> **つまり、バックボーンエリアは「エリア分割による負荷軽減」と「エリア間経路交換の一貫性・ループ防止」を両立させるための、OSPF階層設計の中核です。**

### 4. OSPFのコスト計算

OSPFの経路選択は **「コスト」** というメトリックで行います。

```
コスト = リファレンス帯域 / インターフェース帯域

デフォルトのリファレンス帯域 = 100Mbps

例：
・GigabitEthernet (1Gbps) → 100/1000 = 0.1 → 1（小数は切り上げ）
・FastEthernet (100Mbps) → 100/100 = 1
・Ethernet (10Mbps) → 100/10 = 10
```

現代では10Gbps/100Gbpsが一般的なため、**リファレンス帯域を10,000Mbps（10Gbps）や更高に変更**する必要があります（設定ミスで高速リンクが正しく評価されないケースが多い）。

### 5. ネットワークタイプ：環境に応じた動作

OSPFは接続環境に応じて**異なる動作モード**を持ちます。

| ネットワークタイプ | 環境 | DR/BDR選出 | Hello間隔 |
|-------------------|------|-----------|----------|
| **Broadcast** | イーサネットLAN | あり | 10秒 |
| **Non-Broadcast (NBMA)** | フレームリレー、ATM | あり | 30秒 |
| **Point-to-Point** | PPP、HDLC、専用線 | なし | 10秒 |
| **Point-to-Multipoint** | 部分メッシュNBMA | なし | 30秒 |

**DR（Designated Router）/ BDR（Backup DR）** は、ブロードキャスト環境で **「全ルーターが互いにフル隣接関係を持つ」** のを防ぐための代表者です。DRを経由してLSAを交換することで、隣接関係数を `O(n)` から `O(1)` に削減します。

## OSPFによる冗長化

**OSPFによる冗長化**とは、**「同じ宛先に対して複数の経路（コストが等しいまたは不等しい）を学習しておき、リンクやルーターの故障時に自動的に代替経路に切り替える」** ことです。

### 1. 基本の仕組み：「地図を持つ」から迂回できる

OSPFは全ルーターが**同一のリンクステートデータベース（LSDB）＝地図**を持ちます。

```
【冗長経路の例】
        [R1]═══10Gbps═══[R2]
       /  ╲              /  ╲
    1Gbps  10Gbps    1Gbps  1Gbps
     /      ╲        /      \
   [PC]    [R3]════[R4]    [サーバ]
            ↑________________↑
         このリンクが切れたら？

OSPFの対応：
1. R3がリンクダウンを検知
2. 新しいLSAをフラood
3. 全ルーターがSPFを再計算
4. 「R3→R1→R2→R4」という迂回経路を自動的に採用
```

**VRRPが「同じサブネット内のゲートウェイの冗長化」**なのに対し、**OSPFは「ルーター間の経路そのものの冗長化」**です。

### 2. 等コスト冗長：ECMP（Equal-Cost Multi-Path）

同じ宛先に対して**同じコストの複数経路**がある場合、OSPFは**両方をルーティングテーブルに登録**し、負荷分散（パケット単位またはフロー単位）を行います。

```
【ECMPの例：コストが同じ場合】
[PC]──[R1]═══cost10═══[R2]──[サーバ]
          ╲___cost10___/

→ R1のルーティングテーブル：
  10.0.2.0/24 → [R2直接: cost10], [R3経由: cost10]
  両方をアクティブにして負荷分散
```

**故障時は、残った1本に自動的に集約**されます。設定変更は一切不要です。

### 3. 不等コスト冗長：故障時の自動迂回

等しくなくても、OSPFは**代替経路を常に把握**しています。

| 状況 | OSPFの動作 |
|------|-----------|
| **リンク切断** | 該当LSAが無効化され、SPF再計算。代替経路へ即座に切り替え |
| **ルーター故障** | Deadタイマー（通常40秒）満了で隣接関係解除。LSA更新とSPF再計算 |
| **コスト変更** | 新しいLSAでコストが更新され、最適経路が再選定 |

### 4. VRRP・スタッキングとの違い

| 技術 | 冗長化の対象 | レイヤー | 切り替えのトリガー |
|------|-------------|---------|-----------------|
| **VRRP** | デフォルトゲートウェイ（L3SWの1台） | L2/L3境界 | L3SWのダウン検知 |
| **スタッキング** | スイッチ本体の故障 | L2/L3 | メンバ故障時のマスター引き継ぎ |
| **OSPF** | ルーター間の経路・リンク | L3 | リンクダウン・LSA更新・SPF再計算 |

> **OSPFの冗長化は「経路そのもの」を動的に再計算するため、VRRPのように「仮想IP・仮想MAC」を使う必要がありません。単に「生きている経路に自動的に流れる」だけです。**

## ループ発生の可能性

OSPFのLSA（リンクステート広告）のフラッディング（情報交換）時に、原則としてループは発生しません。 以下の仕組みで防止されています。

### 1. フラッディングの仕組みとループ防止

OSPFでは、新しいLSAを受信したルーターは **「受信したポート以外の全ポート」** にそのLSAを転送（フラッディング）します。これは一見ループしそうですが、以下の仕組みで防がれます。

__① Sequence Number（LS Sequence Number）__

各LSAには**32ビットのシーケンス番号**が付いています。

- ルーターが自分のLSAを更新するたびに、シーケンス番号を**インクリメント**
- 他のルーターが**同じまたは古いシーケンス番号のLSA**を受信した場合、**破棄**します
- より新しいシーケンス番号のLSAだけを受け入れてフラッディングします

```
【ループ防止のイメージ】
[R1] ──LSA(seq=0x80000001)──→ [R2] ──LSA(seq=0x80000001)──→ [R3]
  ↑___________________________________________________________↓
  R3がR1に同じLSAを送り返そうとするが、
  R1は「seq=0x80000001は自分が出したものと同じ」→ 破棄
```

__② MaxAge（Max Age）とLSAの寿命__

各LSAには**Age（経過時間）** フィールドがあり、**最大3600秒（1時間）** で無効化されます。

- LSAは発生元から**1秒ごとにAgeがインクリメント**されていく
- Ageが**MaxAge（3600）に達すると、そのLSAは削除**される
- これにより、「どこかで回り続ける古いLSA」が永遠に残ることはありません

__③ LSAck（Link-State Ack）による確認__

フラッディングされたLSAには、隣接ルーターから**LSAck（Link-State Ack）** が返されます。確認応答がない場合は再送しますが、**重複したLSAはackだけ返して破棄**されます。

### 2. エリアを跨ぐ場合は「構造的に」ループしない

OSPFのエリア設計自体が、**LSAの循環を構造的に防いでいます**。

| LSAの種類 | フラッディング範囲 | 理由 |
|----------|-------------------|------|
| **Type 1, 2**（Router/Network） | **同一エリア内のみ** | エリア境界（ABR）で止まる |
| **Type 3**（Summary） | ABRが**エリア0を経由して**他エリアに広報 | エリア間は「星型（Area 0がハブ）」のため循環しない |
| **Type 5**（External） | 全エリア（NSSA除く）に広がるが、ABRが変換・制御 | Area 0を必ず経由する構造 |

```
【エリア間でループしない構造】
Area 10 ──[ABR]──→ Area 0 ←──[ABR]── Area 20
              ↑_________________↓
         Type3 LSAはABRが生成。エリア間の循環は構造的に起きにくい
```

エリア0（バックボーン）が**全エリア間経路交換の唯一の中継点**であるため、エリア間でのLSA循環は起きません。

### 3. では、まったくループしないのか

原則として**LSAのフラッディング自体がループすることはありません**が、以下のような**設定ミスや特殊な状況**では問題が生じる可能性があります。

| 状況 | 内容 |
|------|------|
| **エリアの非対称配置** | Area 0が分断された状態（ partitioned backbone ）で、仮想的なリンク（virtual link）を使う場合に、設計が複雑化して予期せぬ経路が発生する可能性がある |
| **双方向再配布（Redistribution）の誤設定** | OSPFと他プロトコル（BGPなど）間で**相互に経路を再配布**すると、メトリックの操作によって**経路ループ**が発生することがある（LSAのフラッディングループではなく、**パケット転送のループ**） |
| **MaxAgeのLSAが残存** | 極めて稀だが、ソフトウェアバグなどでMaxAgeに達したLSAが削除されず残ると、データベースが不整合になる可能性がある |

## 総括

OSPFの内容を総括していきます。

### 1. 一言で言うと

> **OSPFは「1つの組織内で、全ルーターがネットワーク全体の地図（トポロジー）を共有し、各自が最短経路を計算するリンクステート型IGP」です。**

### 2. なぜOSPFなのか（RIPとの違い）

| 観点 | RIP（距離ベクトル） | OSPF（リンクステート） |
|------|-------------------|----------------------|
| 持つ情報 | 隣から聞いた「2手の情報」 | 自分で集めた「生の地図（LSDB）」 |
| 経路計算 | ホップ数を足し算（伝言ゲーム） | Dijkstra法で地図から最短経路を計算 |
| 収束速度 | 遅い（カウントトゥインフィニティ） | 速い（トポロジー変更を即座にフラood） |
| ループリスク | ある | ほぼない（地図ベースで一貫性がある） |
| 大規模対応 | 不向き | **エリア分割で対応可能** |

### 3. 動作の核心：5ステップ

1. **Hello**（10秒間隔）：隣接ルーターを発見・パラメータ確認
2. **DBD/LSR/LSU/LSAck**：地図の目録交換→詳細要求→詳細配布→確認応答
3. **LSDB同期**：全ルーターが**同一の地図**を完成させる
4. **SPF計算**：各自がDijkstra法で「自分を根とする最短経路木」を計算
5. **ルーティングテーブル反映**：管理距離110で経路を登録

### 4. エリア設計の核心

```
Area 10 ──[ABR]──→ Area 0 ←──[ABR]── Area 20
(営業)              (中核)             (開発)
```

| 要素 | 役割 |
|------|------|
| **エリア** | LSAのフラood範囲を限定し、LSDBサイズとSPF負荷を削減 |
| **Area 0（バックボーン）** | 全エリア間経路交換の唯一の中継点。エリア間ループを構造的に防ぐ |
| **ABR** | エリア境界でType1/2 LSAを**Type3サマリー**に変換して広報 |
| **ASBR** | 外部（BGPなど）の経路をType5 LSAとしてOSPFドメインに注入 |

> **エリア分割は「負荷軽減」と「一貫性・ループ防止」を両立させる設計。**

### 5. 冗長化の核心

| 方式 | 内容 |
|------|------|
| **ECMP**（等コスト） | 同じコストの複数経路を同時にアクティブにして**負荷分散** |
| **自動迂回**（不等コスト） | リンク・ルーター故障時、LSA更新→SPF再計算で**代替経路へ自動切り替え** |
| **切り替えトリガー** | リンクダウン、Deadタイマー満了、コスト変更 |

> **VRRPが「ゲートウェイの冗長化」なら、OSPFは「経路そのものの動的冗長化」。**

### 6. ループ防止の核心

| 仕組み | 内容 |
|--------|------|
| **シーケンス番号** | 古い/同じLSAは破棄。新しいものだけをフラッディング |
| **MaxAge（3600秒）** | LSAに寿命あり。永遠に回り続けることはない |
| **LSAck** | 確認応答で重複排除 |
| **エリア階層** | Type1/2はエリア内のみ。エリア間はArea 0経由の星型構造で循環防止 |

> **LSAのフラッディング自体がループすることはない。ただし、OSPFと他プロトコル間の「相互再配布（redistribution）」の誤設定では、パケット転送のループが起きる可能性がある。**
