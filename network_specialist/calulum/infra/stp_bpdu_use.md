

**STP（Spanning Tree Protocol）** は、**「スイッチ間の冗長リンクを物理的には生かしつつ、論理的には一部を遮断してループを潰す」**ことでループを回避します。

その設定（動作）の核心は、**スイッチ同士がBPDU（Bridge Protocol Data Unit）という制御フレームを交換し、相互チェックを行って各ポートの役割（フォワーディングかブロッキングか）を自動的に決定する**ことです。

### 1. なぜループが怖いのか

まず前提として、イーサネットは **「フレームを受け取ったら、学習したポート以外の全ポートに転送する（フラッディング）」** 仕様です。これがループ構造で発火すると、**ブロードキャストストーム**が発生します。

```
【ループ構造】
[PC]──[SW-A]════════[SW-B]
          ╲          /
           ╲════════/
            [SW-C]

PCがブロードキャストを送信 → SW-AがSW-BとSW-Cに転送
→ SW-BがSW-CとSW-Aに転送 → SW-CがSW-AとSW-Bに転送
→ フレームが永遠に循環し、全リンクを埋め尽くす
```

### 2. STPの基本戦略：「1本だけ通す。残りは塞ぐ」

STPは、スイッチ間の全リンクを **「ループがない木構造（スパニングツリー）」** に変換します。

```
【物理的な冗長構造】        【STPが論理的に作る構造】
[SW-A]══════[SW-B]         [SW-A]══════[SW-B]
   ╲          /                 ╲
    ═════════                   (Blocking)
   [SW-C]                      [SW-C]

全3本のリンクがアクティブ      SW-B→SW-Cのリンクは論理的に塞がれる
                               ループは解消される
                               SW-BとSW-C間のリンクが切れたら
                               STPが再計算して復旧
```

> **本質：物理的な冗長性は維持しつつ、論理的には「木（ツリー）」にしてループを消す。**

### 3. STPの「選挙」プロセス：4つのステップ

STPはBPDUを交換して、以下の選挙を行います。

__ステップ1：ルートブリッジ（Root Bridge）の選出__

全スイッチの中から、**「代表（ルート）」を1台選びます。**

| 選出基準 | 内容 |
|----------|------|
| **Bridge ID** | ブリッジプライオリティ（2バイト、デフォルト32768）＋ MACアドレス（6バイト） |
| **勝利条件** | Bridge IDが最も小さいスイッチがルートブリッジ |

```
【例】
SW-A: 優先度 32768 + MAC 00:11:22:33:44:AA → 32768.0011...
SW-B: 優先度 4096  + MAC 00:11:22:33:44:BB → 4096.0011...  ← 優先度が小さい！
SW-C: 優先度 32768 + MAC 00:11:22:33:44:CC → 32768.0011...

→ SW-Bがルートブリッジに選ばれる
```

**管理者は「優先度を小さく設定」することで、意図したスイッチをルートにできます。**

__ステップ2：各スイッチの「ルートポート（Root Port）」選出__

**ルートブリッジ以外の全スイッチ**は、自分からルートブリッジへ**最も「コストが低い」ポート**を「ルートポート」に選びます。

| 項目 | 内容 |
|------|------|
| **Root Path Cost** | 各ポートからルートブリッジまでの累積コスト |
| **ポートコスト** | リンク速度によって決まる（10Mbps=100、1Gbps=4、10Gbps=2など） |
| **ルートポート** | 「ルートブリッジへの最短路になっているポート」 |

```
【ルートポートの例】
        [SW-B: ルートブリッジ]
       /                    \
  1Gbps                    1Gbps
     /                        \
[SW-A]════════1Gbps════════[SW-C]
   ↑                         ↑
 SW-Aのルートポートは        SW-Cのルートポートは
 「SW-B方向のポート」        「SW-B方向のポート」（直接つながっている方）

もし SW-A→SW-C→SW-B の方がコストが低ければ、
SW-Aは「SW-C方向のポート」をルートポートに選ぶ
```

__ステップ3：各セグメントの「指定ポート（Designated Port）」選出__

各リンク（セグメント）ごとに、**「そのセグメントを代表してフレームを転送するポート」** を1つ選びます。

| 選出基準 | 内容 |
|----------|------|
| **そのセグメントに繋がるスイッチの中で、ルートブリッジまでのコストが最も低いポート** | 同点ならBridge IDが小さい方 |

```
【指定ポートの例】
[SW-B: ルート]══════[SW-A]
   ↑                  ↑
 ルートなので全ポート  このリンクではSW-B側が指定ポート
 が指定ポート

[SW-A]══════════════[SW-C]
   ↑                   ↑
 このリンクでどちらが指定ポートか？
 → SW-AとSW-Cのルートまでのコストを比較
 → コストが低い方のポートが指定ポート
```

__ステップ4：残りのポートを「ブロッキング（Blocking）」にする__

以下のいずれにも該当しないポートは、**ブロッキング状態**になります。

- ルートポートでもない
- 指定ポートでもない

```
【最終的なポート状態】
        [SW-B: ルート]
       /    ↑指定      \
  指定/      ポート       \指定
     /                      \
[SW-A]══════[SW-C]
   ↑           ↑
 ルートポート  ルートポート
 指定ポート    (Blocking)  ← ここだけ塞がれる！
```

### 4. BPDU（Bridge Protocol Data Unit）の中身

スイッチは**2秒間隔（デフォルト）** でBPDUを交換し、トポロジー情報を共有します。

BPDUに含まれる主な情報：

| フィールド | 内容 |
|-----------|------|
| **Root ID** | 現在認識しているルートブリッジのBridge ID |
| **Root Path Cost** | 送信側スイッチがルートまでにかかっている累積コスト |
| **Bridge ID** | 送信側スイッチ自身のBridge ID |
| **Port ID** | 送信側ポートのID（ポートプライオリティ＋ポート番号） |
| **Message Age** | BPDUがルートから何秒経過したか（Max Ageでタイムアウト） |

各スイッチはBPDUを受信するたびに、「もっと良い（コストが低い）ルート情報が来たか」を確認し、必要に応じてポートの役割を更新します。

### 5. トポロジー変更時の動作

リンクの切断や新しいスイッチの追加が発生すると、STPは**再計算**を行います。

```
【SW-BとSW-C間のリンクが切断】
[SW-B]══════[SW-A]
   ╲          /
    ═════════  ← ここが切れた！
   [SW-C]

1. SW-CがBPDUの受信停止を検知（Max Age: 20秒待機）
2. STPが再計算開始
3. SW-CのブロッキングしていたポートをListening→Learning→Forwardingへ移行
4. 新しいツリー構造が確立
```

従来STPでは、この再計算に**30～50秒**かかりました（Max Age 20秒 + Forward Delay 15秒×2）。

### 6. 以前の文脈との接続

__フォワーディング/ブロッキング状態との関係__

以前ご説明した**フォワーディング状態とブロッキング状態**は、まさにこのSTPの選挙結果を反映したものです。

- **ルートポート** → Forwarding
- **指定ポート** → Forwarding
- **非指定かつ非ルートポート** → Blocking（Discarding）

__トランクポートとの関係__

トランクポートも**STPの対象**です。ただし、**PVST（Per-VLAN Spanning Tree）**や**MSTP（Multiple Spanning Tree Protocol）**では、**VLANごとに独立したスパニングツリー**を構築できます。

```
【VLANごとに異なるブロッキングポート】
VLAN10: [SW-A]════[SW-B]  (SW-A→SW-CがBlocking)
VLAN20: [SW-A]════[SW-C]  (SW-A→SW-BがBlocking)

→ 負荷分散が可能（1本の物理リンクをVLANで分担）
```

__スタッキングとの関係__

スタックされたスイッチは**論理的に1台**なので、**スタックリンク内部ではSTPは不要**です。スタック内のメンバ間リンクはSTPの対象外となります。

__VRRPとの関係__

STPのブロッキングによって**L2SW間の経路が分断**されると、VRRP広告（L2マルチキャスト）が届かず、**デュアルマスター**が発生する可能性があります。L3SW冗長化の設計では、**STPのトポロジーとVRRPの配置を整合させる**ことが重要です。
