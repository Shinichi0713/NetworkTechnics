
## IPsec実現法

IPsec（IP Security）は、**IP層（ネットワーク層）で通信を暗号化・認証するためのプロトコル群**です。以下、その実現方式を構成要素から順に説明します。


### 1. IPsecの主な構成プロトコル

IPsecは複数のプロトコルを組み合わせて実現されます。

| プロトコル | 役割 |
|-----------|------|
| **AH（Authentication Header）** | データの完全性と送信元認証を保証（暗号化はしない） |
| **ESP（Encapsulating Security Payload）** | **暗号化** + 完全性 + 送信元認証を保証（最も一般的に使われる） |
| **IKE（Internet Key Exchange）** | 通信相手との**共通鍵（セキュリティ連想: SA）**を自動的に交換・管理 |

現在は**ESPが主流**で、AHはNAT環境で問題が生じやすいため、あまり使われません。

### 2. 動作モード（2種類）

IPsecには、パケットのカプセル化方法が2つあります。

__トランスポートモード__
- **元のIPヘッダーはそのまま**に、ペイロード（TCP/UDPデータ）のみをESPで保護
- 通信の**終端ノード同士**（PCとサーバーなど）が直接IPsecを終端する場合に使用
- オーバーヘッドが小さい

```
[元のIPヘッダー] [ESPヘッダー] [暗号化されたTCP/UDPデータ] [ESPトレーラー]
```

__トンネルモード（VPNで一般的）__
- **元のIPパケット全体**を暗号化し、さらに**新しいIPヘッダー**を付加
- サイト間VPNやリモートアクセスVPNで使われる。通信者はIPsecの存在を意識しない
- オーバーヘッドが大きいが、プライベートネットワーク全体を保護できる

```
[新しいIPヘッダー] [ESPヘッダー] [暗号化された元のIPパケット全体] [ESPトレーラー]
```

### 3. 鍵交換の仕組み（IKE）

IPsecの核心は「**安全に共通鍵を共有する**」ことです。これを自動化するのが**IKE（Internet Key Exchange）** です。

__IKEv1/v2の2段階（IKEv2で簡素化）__

**フェーズ1（IKE SAの確立）**
- 通信相手（ピア）を認証（事前共有鍵、デジタル証明書、または公開鍵暗号）
- Diffie-Hellman（DH）鍵交換で**共通の秘密鍵材料**を生成
- 以降のIKEメッセージを暗号化・保護するための「IKE SA（Security Association）」を確立

**フェーズ2（IPsec SAの確立）**
- フェーズ1で作った安全なチャネルを使い、**実際の通信データを暗号化するためのIPsec SA**を複数確立
- 送信用・受信用で別々のSAを持つ（双方向通信のため）

### 4. セキュリティ連想（SA: Security Association）

IPsecでは、**SA**という「通信のルールセット」を管理します。

1つのSAには以下が定義されています。

- **SPI（Security Parameter Index）**: SAを識別する32ビットのID
- **暗号化アルゴリズム**: AES-CBC、AES-GCMなど
- **認証（HMAC）アルゴリズム**: HMAC-SHA256など
- **共通鍵**: セッション鍵
- **モード**: トランスポート or トンネル
- **生存期間**: 鍵を使い続ける時間・バイト数の上限

送受信で別々のSAが必要なため、双方向通信には**最低2つのSA**が存在します。


### 5. 実際のパケット処理フロー（送信側）

1. **ポリシーチェック（Security Policy Database: SPD）**
   - 「この宛先へのパケットはIPsec保護が必要か？」を確認
   - 保護が必要なら、対応するSAをSAD（Security Association Database）から検索

2. **暗号化・認証（ESP処理）**
   - ペイロード（トランスポート）または元パケット全体（トンネル）を暗号化
   - **MAC（メッセージ認証コード）**を計算し、改ざん検知用に付加
   - ESPヘッダー（SPI、シーケンス番号など）を付与

3. **送信**
   - 新しいIPヘッダー（トンネルモードの場合）を付けてネットワークへ送出

### 6. 実際のパケット処理フロー（受信側）

1. **ESPヘッダーの確認**
   - SPIを見て、どのSAに属するパケットかを特定
   - シーケンス番号で**リプレイ攻撃**をチェック

2. **MAC検証**
   - 受信データ + SAの共通鍵でMAC値を再計算
   - 受信したMAC値と一致すれば「改ざんなし・正当な送信者」と判断

3. **復号化**
   - SAで定義された共通鍵とアルゴリズムでデータを復号
   - トンネルモードなら、内部の元IPパケットを取り出して通常のルーティングへ


## 使われている場面

IPsecは、**IP層で通信を暗号化・認証する**技術として、主に以下の場面で使われています。

### 1. 企業のサイト間VPN（Site-to-Site VPN）

最も典型的な用途です。地理的に離れた拠点同士を、**インターネットを介して暗号化された専用回線のように**接続します。

- **本社と支社**のLAN同士を安全に接続
- **企業とデータセンター**、**企業とクラウド基盤**（AWS、Azureなど）の接続
- 各拠点の**ルーターやFW（VPNゲートウェイ）同士**がIPsecトンネルを張り、拠点間の全通信を暗号化

利用者（社員）は特別な操作をせず、通常の社内通信として使えます。

### 2. リモートアクセスVPN（テレワーク・出張）

外出先の社員が、**インターネット経由で社内ネットワークに安全に接続**する場面で使われます。

- 社員のPCに**IPsec VPNクライアント**を導入し、社内のVPNゲートウェイと暗号化通信を確立
- 近年では**SSL-VPN**や**WireGuard**も多く使われますが、高いセキュリティ基準を求める企業や政府機関では、IPsecを採用するケースも多いです

### 3. モバイル通信網（LTE/5G）のバックホール保護

携帯電話基地局（eNodeB/gNodeB）からコアネットワーク（EPC/5GC）への通信（**バックホール**）を暗号化するためにIPsecが使われることがあります。

- 特に**非信頼の回線**（他社回線を借りている場合等）を通す際に、ユーザーデータや制御信号を保護
- モバイル通信の標準仕様（3GPP）でも、セキュリティ要件に応じてIPsecの使用が定められています


### 4. 政府・金融・医療などの機密通信

高いセキュリティが求められる分野では、IPsecが標準的に使われます。

- **金融機関**: 銀行間通信、決済ネットワーク、ATM回線の保護
- **政府機関・防衛**: 機密性の高い行政通信
- **医療機関**: 患者データ（PHI）を含む通信の暗号化（HIPAA等の規制対応）

これらの分野では、**暗号化アルゴリズムや鍵管理の厳格な基準**を満たす必要があり、IPsecの標準化された仕様が信頼されています。


### 5. クラウド・マルチテナント環境の仮想ネットワーク

クラウドインフラにおいて、**仮想ネットワーク間の通信**を暗号化するためにも使われます。

- **AWS Site-to-Site VPN**、**Azure VPN Gateway**などは、企業のオンプレミス環境とクラウドVPCをIPsecで接続
- クラウド上の異なるテナントやリージョン間の通信を暗号化

### 6. IoT・産業用システム（OT）の通信保護

工場の制御システムや監視カメラ、スマートグリッドなど、**IoT機器間の通信**を保護する場面でも使われます。

- 機器の性能が限られる環境では軽量な暗号が求められますが、**既存の産業用ネットワーク機器**ではIPsec対応が標準的
- 産業用プロトコル（Modbus等）をIPsecトンネルで運用し、サイバー攻撃から保護
