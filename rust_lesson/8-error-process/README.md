
Rustのエラー処理は他の言語と異なります。
どんな点が異なるか、使い方について説明していきます。

## 背景

Rustが「例外」を捨てて「Result型」を選んだ背景には、システムプログラミング言語としての **「究極の安全性」** と **「予測可能なパフォーマンス」** を両立させたいという強い意志があります。

大きく分けて3つの理由があります。

### 1. 「どこで何が起きるか」を透明にするため（可読性）

例外（Exception）がある言語では、関数を呼び出す際に「この関数はエラーを投げるかもしれないし、投げないかもしれない」という情報が、関数のシグネチャ（名前や引数）から見えません。

* **例外の問題**: 呼び出し先の深いところで発生したエラーが、どこを通ってどこでキャッチされるのかを追うのが非常に困難です。
* **Rustの解**: 戻り値が `Result` であれば、「この関数は失敗する可能性がある」ことが型として明記されます。コードを読むだけで、エラーの発生箇所と伝播ルートが**100%可視化**されます。


### 2. 「隠れたコスト」をゼロにする（パフォーマンス）

例外処理は、実はコンピュータにとって非常に重い処理です。

* **例外のコスト**: 例外が発生すると、OSや実行環境は「スタック展開（Stack Unwinding）」という複雑な処理を行い、メモリの状態を巻き戻し、キャッチできる場所を探します。これには大きなオーバーヘッドがかかります。
* **Rustの解**: `Result` は単なる `enum`（列挙型）です。成功か失敗かのフラグを1ビット確認するだけなので、通常の条件分岐と全く同じ速度で動きます。これは、ガベージコレクションを持たず、 **「ゼロコスト抽象化」** を掲げるRustにとって譲れないポイントでした。


### 3. 「不完全な状態」での動作を阻止する（安全性）

例外処理の最大の罠は、 **「例外が投げられた瞬間に、メモリの書き換えが途中で止まってしまう」** ことです。これにより、データが壊れたり（不整合）、ロックが解放されなかったりするバグが発生しやすくなります。

* **Rustの解**: エラーを「値」として扱うことで、プログラマは「エラーが発生したときに、今いじっているデータをどう片付けるか」をその場で書かざるを得なくなります。
* **網羅性の強制**: `match` で全てのケースを処理させることで、「エラーをうっかり無視して、壊れたデータのまま計算を続けてしまう」という事故を物理的に防いでいます。


## Rustのエラー処理
Rustのエラー処理が他の言語（Java, Python, C++など）と決定的に異なる点は、 **「例外（Exception）を投げない」** という設計思想にあります。

多くの言語が「問題が起きたら実行を中断してどこかでキャッチする」というスタイルなのに対し、Rustは **「エラーは単なる値として扱い、型システムで処理を強制する」** というスタイルを徹底しています。

具体的に異なる4つのポイントを解説します。


### 1. 例外ではなく「戻り値」で扱う

他の言語では `try-catch` を使いますが、Rustにはこれがありません。代わりに、エラーが起こる可能性のある関数は **`Result<T, E>`** という型を返します。

* **他の言語:** エラーが発生すると、呼び出しスタックを遡って例外が飛んでいく。どこで誰がキャッチするかは実行時まで不明確。
* **Rust:** エラーは関数の戻り値の一部。呼び出し側は、成功した時の値 `T` か、失敗した時のエラー `E` かを必ず受け取ります。

### 2. コンパイル時の「未処理エラー」防止

これが最も強力な点です。Rustでは `Result` を受け取った際、**そのエラーをどう扱うか（無視するのか、処理するのか）を決めないと、中身の値を取り出すことができません。**

* **他の言語:** 例外処理を書き忘れてもコンパイルは通るが、実行時にクラッシュ（Runtime Error）する。
* **Rust:** `match` や `if let` でエラーケースを処理しない限り、成功時のデータにアクセスできないため、「エラーを放置したまま進む」ことが物理的に不可能です。

### 3. 回復不能なエラーと明確に区別

Rustはエラーを2種類に厳格に分けています。

1. **回復可能 (`Result`)**: ファイルが見つからない、ネットワークが一時的に切れたなど。「想定内」のトラブル。
2. **回復不能 (`panic!`)**: 配列の範囲外アクセスなど、プログラムをこれ以上安全に続けられない「致命的なバグ」。

多くの言語ではこれらが「例外」として混ざり合いがちですが、Rustは **「プログラムが修正されるべきバグ（panic）」** と **「ユーザーが対処すべきエラー（Result）」** を明確に分けることで、設計の透明性を高めています。

### 4. `?` 演算子によるスマートな伝播

「エラーを値として扱うと、コードが `if` 分岐だらけで読みづらくなるのでは？」という懸念を解消するのが **`?` 演算子** です。

```rust
// 他の言語の try-catch のようにスマートに書ける
fn read_username() -> Result<String, io::Error> {
    let mut s = String::new();
    // 失敗したら即座に関数を抜けてエラーを返す、成功したら値を取り出す
    fs::File::open("hello.txt")?.read_to_string(&mut s)?;
    Ok(s)
}

```

この `?` は、エラーが発生した瞬間に現在の関数を終了し、呼び出し元にエラーを「丸投げ」する仕組みです。これにより、正常系のロジックをスッキリと記述できます。

## 文法

Rustのエラー処理の文法は、 **「型で包んで返す」** ことと、 **「それをどう開くか」** という2つのステップで構成されています。

主要な3つの構文を中心に解説します。


### 1. 戻り値の型：`Result<T, E>`

エラーが発生する可能性のある関数は、必ず `Result` 型を返します。

```rust
// 成功なら String (T), 失敗なら u32 のエラーコード (E) を返す
fn get_user_name(id: u32) -> Result<String, u32> {
    if id == 1 {
        Ok("Alice".to_string()) // 成功時は Ok で包む
    } else {
        Err(404)                // 失敗時は Err で包む
    }
}

```


### 2. エラーを「開く」3つの方法

#### ① `match` 式（最も基本で安全）

すべてのケースを網羅的に処理します。

```rust
let result = get_user_name(1);

match result {
    Ok(name) => println!("こんにちは、{}さん", name),
    Err(code) => println!("エラーが発生しました。コード: {}", code),
}

```

#### ② `?` 演算子（エラーの委譲・伝播）

「エラーだったらこの関数自体を終了して、エラーを呼び出し元に投げる」という、実務で最も使われる構文です。

```rust
fn greet_user(id: u32) -> Result<(), u32> {
    // 成功すれば name に中身が入り、失敗すればここでこの関数が終わる
    let name = get_user_name(id)?; 
    
    println!("Hello, {}", name);
    Ok(())
}

```

#### ③ `unwrap` と `expect`（強制取り出し）

「絶対に成功するはずだ」という時に使いますが、もし **`Err` だった場合はプログラムが強制終了（パニック）**します。

```rust
let name = get_user_name(1).unwrap(); // 失敗したらクラッシュ
let name = get_user_name(1).expect("名前の取得に失敗しました"); // エラーメッセージ付きでクラッシュ

```


### 3. 便利メソッドによる変換

`match` を書くのが面倒な場合、便利なメソッドが用意されています。

| メソッド | 動作 |
| --- | --- |
| **`.unwrap_or(default)`** | `Err` ならデフォルト値を返す |
| **`.map( | val |
| **`.and_then( | val |

```rust
// エラーだったら "Guest" にする
let name = get_user_name(99).unwrap_or("Guest".to_string());

```

### 4. 回復不能なエラー：`panic!`

バグ（配列の範囲外アクセスなど）により、プログラムを続行できない場合は `panic!` マクロを使います。

```rust
if false == true {
    panic!("宇宙の法則が乱れました"); // 即座に終了
}

```

## 最後に

Rustのエラー処理は、「不注意な人間」を「厳格なコンパイラ」が強力にバックアップする仕組みです。

最初は記述量が増えて面倒に感じるかもしれませんが、その「面倒さ」こそが、本番環境での深夜の呼び出し（障害対応）を減らすための最も安上がりな投資である、というのがRustの根本の考え方です。
