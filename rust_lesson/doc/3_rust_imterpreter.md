厳密な定義で言えば、Rustは「コンパイル言語」であるため、**コードを直接解釈して実行するインタプリタ（Pythonのような方式）は標準では存在しません。**

しかし、開発の現場において**「あたかもコンパイルしていないかのように、素早く実行する」**ための手段はいくつか存在します。

---

### 1. `cargo run` を使う（最も一般的）

最も「コンパイルを意識させない」方法です。内部ではコンパイルが行われていますが、ユーザーは1つのコマンドを打つだけで「ビルド → 実行」を自動で行えます。

**Bash**

```
cargo run
```

以前の実行時からコードに変更がない場合は、コンパイルをスキップして即座に実行されるため、非常にスムーズです。

---

### 2. `rust-script` を使う

「1つの `.rs` ファイルをスクリプトのように実行したい」場合に非常に便利です。

* **特徴** : `cargo` プロジェクト（`Cargo.toml`）を作ることなく、ファイル単体で実行できます。
* **仕組み** : 実行時に裏側で一時的なビルドを行い、キャッシュを利用して2回目以降を高速化します。

**Bash**

```
# インストール
cargo install rust-script

# 実行
rust-script my_script.rs
```

---

### 3. `evcxr` (Rust REPL) を使う

Pythonの `ipython` や Jupyter Notebook のように、**1行ずつコードを書いてその場で結果を確認する**ことが可能です。

* **evcxr_repl** : ターミナル上で対話的にRustを書けます。
* **Jupyter Kernel** : Jupyter Notebook 上でRustを動かせます。

---

### 4. なぜ「コンパイルなし」の完全なインタプリタがないのか？

Rustがインタプリタ方式を採用しないのには、明確な理由があります。

* **所有権のチェック** : Rustの最大の特徴である「メモリ安全性のチェック（ボローチェッカー）」は、コード全体の整合性を確認する必要があるため、コンパイル時にまとめて行うのが最も効率的です。
* **ゼロコスト抽象化** : 実行速度を極限まで高めるために、コンパイル時に高度な最適化（マシン語への変換）を行う設計になっています。

---

### まとめ

* **「スクリプト的に使いたい」**なら → **`rust-script`**
* **「1行ずつ試したい」**なら → **`evcxr`**
* **「普通の開発」**なら → **`cargo run`**

実質的には「コンパイルを待つ」時間は発生しますが、ツールを使いこなせば Python などのスクリプト言語に近い感覚で開発を進めることができます。

次は、**「コンパイル時間を劇的に短縮するための設定」 **や、** 「爆速でコードチェックだけ行う `cargo check`」**の使い方について詳しく紹介しましょうか？
