目次

    通信は、通常ネットワークを通過することが出来ないように設定されることが多いです。 そんな通信上の制約の中でも、サーバと会話したいというケースがあります。 そんなときに使われる手法が 「カプセル化」 です。

    通信におけるカプセル化は、一言でいうと 「本来のルールや物理的な制約を飛び越えて、データを目的地まで届けるため」 に使われます。

    カプセル化が使われる場面

    具体的には、以下のような「困った状況」を解決したいときに登場します。

    1. 本来通れない場所を通したいとき（トンネリング）

    これが最も一般的なケースです。

    • 例：プライベートIPをインターネットで運びたい 社内LANで使う「192.168.x.x」というアドレスは、インターネット上では通信できません。そこで、このパケットをグローバルIPアドレスという「封筒」でカプセル化して包むことで、インターネットという公共の道を通れるようにします。
    • 例：IPv6パケットをIPv4ネットワークで運びたい まだIPv6に対応していない古い経路を通る際、IPv6パケットをIPv4パケットの中に隠して（カプセル化して）運びます。

    2. データを暗号化して守りたいとき（セキュリティ）

    データの中身が丸見えだと困る場合、カプセル化の過程で中身を「暗号化」します。

    • VPN（IPsecなど）: 元のパケットを暗号化し、その上から新しいヘッダーを被せます。これにより、たとえ途中でパケットを盗み見られても、中身が何であるか、最終的な宛先が社内のどのPCなのかが分からなくなります。

    3. 離れた場所を「同じLAN」に見せたいとき（L2延伸）

    物理的には東京と大阪で離れていても、同じ部署のPC同士として（同じネットワークアドレスで）通信させたい場合です。

    • VXLANや広域イーサネット: 本来はルーターを越えると消えてしまう「MACアドレス情報（L2）」を、IPパケット（L3）の中に丸ごとカプセル化して詰め込みます。こうすることで、物理的な距離を無視して 「巨大な1つのスイッチにつながっている状態」 を作り出せます。

    4. ネットワークを論理的に分割したいとき（仮想化）

    1本の物理的な回線の中に、A社用、B社用、C社用と、互いに見えない独立したネットワークを作りたい場合です。

    • MPLS（ラベルスイッチング）: パケットの先頭に「ラベル」という短い目印をカプセル化して貼り付けます。ルーターはこのラベルを見て「これはA銀行のデータだから、この専用ルートへ」と高速に仕分けを行います。

    カプセル化の手段

    カプセル化の手段は一つではありません。 複数存在する手法の得意、不得意があります。

    1. セキュリティ（暗号化）が必要な場合

    → 主役：IPsec (ESP)

    暗号化が必要なインターネット経由で機密データを送る際は、GREではなくIPsecという方式でカプセル化します。

    • 特徴: パケットを丸ごと暗号化し、新しいIPヘッダーを被せます。
    • 使い分け: 「中身を保護したい」ならIPsec。前述の通り、GREと組み合わせて「GRE over IPsec」として使うことも多いです。

    2. データセンターや仮想ネットワークを作る場合

    → 主役：VXLAN

    クラウド環境や巨大なデータセンター内では、VXLANが主流です。

    • 特徴: L2（イーサネットフレーム）をUDPパケットで包みます。
    • なぜGREじゃないのか: GREは「1対1」のトンネルを作るのが得意ですが、VXLANは「数千〜数万の仮想ネットワーク」を効率よく管理し、多対多の通信を捌くのに特化しているからです。

    3. 通信キャリアの網内で高速転送する場合

    → 主役：MPLS

    先ほどの「IP-VPN」などの内部では、IPヘッダーを被せるのではなく、　「ラベル」　という短い目印をパケットに貼り付けるカプセル化が行われます。

    • 特徴: IPヘッダーよりも処理が軽く、ルーターが高速にパケットを転送できます。

    MPLSは、**「IPルーティング（住所を見て判断）」の柔軟性と、「レイヤ2スイッチング（目印を見て転送）」**の高速性をいいとこ取りした技術です。

    • 高速: ラベルだけ見て飛ばすので速い。
    • 隔離: ラベルでグループ分けできるので安全（VPN）。
    • 制御: 通る道を自由に決められる。

    4. 一般的なネット接続（PPPoE）

    → 主役：PPP / PPPoE

    自宅の光回線でネットに繋ぐ際、IDとパスワードで認証しますよね。あの時もカプセル化が起きています。

    • 特徴: イーサネットの中に「PPP（認証用プロトコル）」をカプセル化して流しています。

    まとめ：なぜGRE「だけ」じゃないのか？

    カプセル化にはそれぞれ「得意科目」があります。

    用途 代表的なカプセル化方式 GREとの違い
    汎用・ルーティング GRE 何でも運べるが、暗号化できない。
    セキュリティ IPsec (ESP) 暗号化に特化。ただしマルチキャストが苦手。
    仮想化・クラウド VXLAN 膨大な数の論理ネットワークを作れる。
    高速転送 MPLS ラベルを使って処理を簡略化する。

    つまり、GREは「何でも入る便利な箱」ですが、 「中身を守りたい（IPsec）」 とか 「もっと大量の箱を整理したい（VXLAN）」 といった専門的なニーズがあるときは、他のカプセル化技術が選ばれます。

    技術進展

    通信のカプセル化は、今まさに 「物理的なネットワークを、ソフトウェアで自由自在に操る」 ための核となる技術として急速に発展しています。

    単に「包んで運ぶ」だけでなく、 「より細かく、より安全に、より自動的に」 という方向へ進化しており、特に以下の4つの分野が注目されています。

    1. SRv6 (Segment Routing IPv6)

    現在、カプセル化の技術で最も熱いのがSRv6です。これは先ほどお話しした「MPLS」の次世代版とも言える技術です。

    • 進化のポイント: MPLSは専用の「ラベル」を使っていましたが、SRv6はIPv6のアドレスそのものを命令（セグメント）として使います。
    • 何がすごくなるか: 「Aルーターを通って、Bでセキュリティ検査をしてから、Cへ届け」という複雑な経路指定を、カプセル化するIPv6ヘッダーに書き込むだけで実現できます。ネットワークの構造がシンプルになり、プログラミングするように通信を制御できるようになります。

    2. ネットワーク・スライシング

    5G通信の普及に伴って発展している技術です。

    • 進化のポイント: 1つの物理的なネットワークの中に、用途に合わせた 「仮想的な専用レーン（スライス）」 をカプセル化技術で作ります。
    • 何がすごくなるか: 自動運転用には「超低遅延」なスライス
    • 動画配信用には「超大容量」なスライス
    • IoTセンサー用には「大量接続」のスライス これらをカプセル化によって論理的に完全に分離し、互いに影響を与えないように提供できます。

    3. SASE (Secure Access Service Edge) と ZTNA

    これまでお話しした「VPN」というカプセル化の考え方が、クラウド時代に合わせて変化しています。

    • 進化のポイント: これまでは「拠点と拠点」を繋ぐためにカプセル化していましたが、今は 「ユーザーとクラウド上のアプリケーション」 を直接、安全に繋ぐためにカプセル化を使います。
    • 何がすごくなるか: どこにいても「暗号化された安全なカプセル」で保護され、かつ「誰がどのアプリを使うか」をクラウド側で一括管理する ゼロトラスト（ZTNA） の基盤として活用されています。

    4. 高度なテレメトリ（情報の可視化）

    カプセル化を使って、ネットワークの状態をリアルタイムで把握する技術です。

    • 進化のポイント: パケットをカプセル化する際、その中に「どのルーターを何ミリ秒で通過したか」という履歴データをこっそり書き込みます（INT: In-band Network Telemetry）。
    • 何がすごくなるか: ネットワークのどこで詰まっているかが一瞬でわかるようになります。これまでは「どこかが遅い」と調べるのが大変でしたが、カプセルが自分で「ここで遅延したよ」と教えてくれるようになります。

    最後に

    これまでは「東京と大阪を1本の線で繋ぐ」という物理的な発想が中心でした。 しかし現在は、 「インターネット」「専用線」「クラウド」という複数の道を、カプセル化とソフトウェア（SD-WANやSRv6）で束ね、状況に応じて最適に使い分ける時代 になっています。

    カプセル化は、単なる「パケットの包み紙」から、ネットワークをプログラミング可能にする「インテリジェントなタグ」へと役割を変えているのです。
